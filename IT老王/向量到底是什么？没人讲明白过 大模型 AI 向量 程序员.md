我们知道大模型的养料就是向量，但向量到底是什么呢？是一个字，是一个词，还是一句话，一段文章呢？稍微懂点技术的朋友一定知道，大模型本质上就是一个对矩阵进行疯狂数字计算的大号计算器，它的输入和输出全都是一堆数字组成的向量。你也大概率看过一些科普视频跟你解释文字怎么映射成向量的，最经典的例子就是国王减男人等于皇后减女人这一类的，只要把词变成向量，词和词之间就能做加减法了。但这种科普其实都只是讲了个皮毛，解决不了核心的问题。如果你稍微深入过大模型，一定听说过 RAG 检索增强生成技术，而做 RAG 就离不开一个东西，Embedding Model。比如这个案例，我们就可以用阿里提供的 DashScope Embedding Model 把任意的一个词或者一句话转成向量，这样就可以去原始资料里做检索，找出最相关的信息了。

那这里问题就来了，你给大模型发一段话，话里面有苹果这个词，那大模型要先把这个词转换成一个词向量才能够去理解，而你同样把苹果这个词发给 Embedding Model，它也能把这个词转换成一个向量，这些向量都是代表苹果这个词的。到这里你是不是有点晕了？这么多向量到底哪个是苹果呢？这向量到底是怎么回事呢？这次我就带你来深入了解一下这个没人说清楚过的向量。我是楼兰，关注我，IT 路上一起进步。讲清楚这个问题之前，首先要对那个你天天在用的大模型有个基础的认知。在千问、DeepSeek 这些大语言模型的最底层都自带了一个叫做 Embedding Layer 嵌入层的基础零件，当你输入一句话，大模型就会把它切成一个一个的 token，然后扔进这个嵌入层，把每个 token 都转换成一串固定长度的数学向量。

如果你懂一点代码，比如用个 PyTorch，你甚至可以很轻松的去开源模型的权重文件里把这个嵌入层给抽出来单独用。那这里就来了第一个问题，比如苹果这个词，你把它扔给千问大模型自带的 Embedding 层，它会吐出一个向量 a，你再把苹果这个词扔给阿里提供的 DashScope Embedding Model，它又会吐出另一个向量 b，这两个向量呢都代表苹果这个词，那它们是一样的吗？结果可能和你想象的不一样，这两个向量从形状到数字全都完全不同。千问大模型的向量 a 是一个包含四千零九十六个数字的超长数组，而 DashScope 的向量 b 是一个一千五百三十六位的短数组。为什么会这样？因为虽然都是向量，但是它们根本就不是同一个物种。

更深层次的原因在于千问和 DashScope Embedding Model 这是两个完全独立的深度学习大模型，它们虽然都用了 Transformer 架构来理解语义，但从根本上它们的结构和目的就完全不同。这就引出了很多人的一个巨大的知识盲区，Embedding 模型它本身就是一个独立完整的深度学习大模型，只不过它是专门为了解决语义距离而独立训练出来的。千问内部的那个 Embedding 层只是个半成品字典，它看到苹果就死板的抽出一个数字，不管你是说吃苹果还是苹果手机，苹果这个词它对应的数字永远是死的。而独立的 Embedding 模型呢，它的目标不是像千问那样去接话茬，而是算距离，它要计算的是苹果和苹果手机这两句话在语义上差距有多远。它用的是另外一种完全不同的训练手法，叫做对比学习。

LLM 大语言模型的训练数据就是给一些文本，它自己去练怎么接话茬，那训练 Embedding Model 的时候呢，程序员就不是给它喂文本了，而是要喂精心构造的三元组，比如基准语句是苹果公司最新财报，那正样本呢是 iPhone 制造商的营收数据，负样本是怎么在果园里种植苹果树，把这三句话同时扔进未经训练的模型里，如果模型傻乎乎的因为都有苹果两个字，就把基准句和负样本算的很近，那系统就会狠狠的抽它一鞭子，强迫它修改内部的权重，把它俩在空间里面推远，同时逼着它把字面完全不像但意思一样的正样本拉近。经过几亿次这样的毒打，这个独立的 Embedding 模型就终于开窍了，它不再被字面意思所迷惑，而是能够真正去理解文字背后的语义坐标。

如果说千问里的向量 a 是刚摘下来的生苹果，那 Embedding 吐出的向量 b 就是经过提纯的苹果浓缩汁了，哪怕为的是同一个词苹果，但出来的已经是完全不同的两个东西了。理解了 Embedding 是个独立大模型，咱们再来看看现实中我们怎么去用呢？其实和 LLM 大语言模型一样，Embedding Model 也分为开源和闭源两大阵容，比如像 DashScope 里的这个 text-embedding-v3、v4 这些模型是阿里闭源的商业机密，你只能花钱调 API，你不可能把它下载到本地。当然也有很多。开源的 embedding 模型，比如去阿里的魔塔社区 ModelScope 看一眼，这个句子相似度分类下就躺着一大批免费开源的 embedding 模型，这些模型你都可以下载到本地舒舒服服的白嫖。

比如排在前面的这个，哎等等，你有没有发现一个问题啊？咱们前面不是刚刚算明白吗？千问它是搞文字接龙的聊天模型，embedding 是专门算语义距离的独立模型，它俩是完全不同工种的两个物种啊，那为什么这个 embedding 模型的名字里居然嵌着一个千问的名字呢？而且类似这样的 embedding 模型还不少，这什么意思？如果你发现了这个问题，你就会发现大模型领域一个非常前沿的做法，就是用大语言模型来辅助训练 embedding 模型。以前大家都是从零开始训练 embedding 模型，但这种模型通常不会太大，也就有了一个致命的弱点，它处理不了太长的语料，稍微长一点的文章塞进去它就傻了，那怎么办呢？

科学就来了一招非常漂亮的移花接木，虽然这些大语言模型是用来聊天的，但它在出厂前可是把全人类的百科全书全都读了一遍的呀，而且它天生就支持超长文本，于是工程师们就直接抓了一个小千问，把它按在手术台上，第一步直接切除它最后生成的下一个可选词列表的预测模块，把它变成一个满腹经纶但无法开口的哑巴。第二步，在它的末端强行接上一个叫做池化层的新零件，把大模型脑子里对长篇大论的复杂理解强行压缩成一个固定长度的数学坐标。第三步，用咱们刚才说的对比学习对它疯狂进行洗脑，让它彻底忘记怎么聊天，专门练习怎么算空间距离。当训练量足够了，奇迹就发生了，这个被爆改后的聊天模型不仅完全继承了极其庞大的世界知识，还彻底解决了长语料的限制，直接碾压了以前所有的传统 embedding 模型。

它曾经是个能言善辩的文科状元，现在被强行改造成了最顶级的测量工程师，这就是把 transformer 当做乐高积木玩的最高境界。如果你理解了这一层，那其实你就离一个算法工程师的岗位不太远了，因为剩下的大部分的工作就是准备环境、清理数据、调调 API 的事了。其实从你看到那种国王减去男人等于皇后减去女人的半吊子常识开始，再一路拆解到大模型爆改 embedding 的最前沿现场，有了 AI 的辅助一点都不难，但真正困难的是你要有足够的好奇心驱使你去跟 AI 提出这个问题，这一步很简单，但却难住了大部分的人，这也才造就出了无数的所谓天之骄子、行业专家。AI 能帮你解决眼前的工程问题是不假，但是它永远解决不了你的好奇心啊。
