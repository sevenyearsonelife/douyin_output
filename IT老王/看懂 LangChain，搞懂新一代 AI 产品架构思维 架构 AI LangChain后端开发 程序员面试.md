Agent这个词啊，你是不是耳朵都听出茧了？那到底什么是Agent呢？现在的Agent到底发展到了什么程度呢？离各种科幻小说中的Agent到底还差多远呢？其实啊，Agent的本质就是把人类解决问题的过程逐渐移交给大模型，不过在现在这个阶段，大模型主要还只是做了自主抽象业务流程，也就是Edge，至于构建State和Node目前依然是人类的工作。要真正理解这些问题啊，最好的方式就是自己动手试一试。你别看现在外面各种Agent产品五花八门让人眼花缭乱，其实它们背后的设计思想都是差不多的。这次我就拿目前最权威的Agent框架LangChain作为教材，带你从底层设计入手，看看顶级的工程师是怎么用架构思维来驾驭大模型的。

就算你不是程序员，理解了这套思维，下次再去吃AI淘汰程序员的瓜的时候，你也能够比程序员们撑得更久一点，别一不小心把瓜吃到自己身上了。记得点赞关注收藏，我是楼兰，关注我IT路上一起进步。动手之前我们先建立一个全局的印象，现在的LangChain呢早就不是一个单纯的代码库了，它是一个包含三大模块的庞大的Agent生态。第一个LangChain，它是框架的基石，专门处理确定性线性的问题。第二个LangGraph，这是新一代的核心引擎，专门用来构建复杂的具备思考能力的Agent。第三个DeepAgent，面向未来的进阶模块，主攻多智能体协作等深度的场景。都是构建Agent，怎么就搞这么多花样呢？这就是因为Agent的形态各异，构建的思路自然也不同了。

LangChain框架给程序员们提供了各种API，但这些构建Agent的思路其实比API重要的多。接下来我们就来看看LangChain到底是怎么设计的。先来看第一个模块，叫做LangChain模块，它的核心思想就是一个词Chain链条，你可以把它想象成工厂的流水线，第一步干完交给第二步，第二步干完交给第三步，环环相扣。在代码层面呢，LangChain搞了一个非常优雅的设计，就叫做LCEL LangChain的表达式。写代码就像接水管一样的，用一个简单的管道符就能够把任务连起来，比如像这个案例当中的这一行，它的底层逻辑里非常的明显，上一个组件的输出严丝合缝的变成下一个组件的输入，数据就像流水线上的产品，单向推进。举个现在最火的例子，RAG检索增强生成，用Chain来做，那就是标准的四个步骤。

第一步接受用户的问题，第二步拿用户的提问去向量数据库检索跟问题最相关的参考文档，第三步把参考文档和问题拼装成一个完整的Prompt提示词，第四步把这个完整的Prompt丢给大模型生成答案。你看用LCEL这四个步骤一串，那么一个RAG系统基本上就跑起来了。这个Chain设计的优势就是极其的稳定可控，但缺点也很明显，它没有回头路啊，如果第二步检索出来的文档是错的，那大语言模型根本没有机会去纠正，只能硬着头皮胡说八道。这就注定了Chain只能够做流水线工人，做不了有独立思考能力的Agent。

为了让Agent具备思考和纠错的能力，LangGraph就诞生了，它的核心思想是Graph图，你可以把这个Graph简单粗暴的理解为我们常见的流程图，在LangGraph的代码实现当中呢，为了这张流程图提供了三个核心的概念，第一个State状态，它是Agent的全局记忆，保存着对话历史和所有的中间结果。第二个Node节点，它是真正干活的排审函数，比如调用大模型或者执行搜索或者做一个具体的操作都可以，形式上它就只是一个函数而已，这个函数接收State，干完活后结果它也只是更新到State里面。第三个Edge边，它是一个路由的逻辑，一个Node干完了活，接下来该去哪儿呢？这就由Edge来指定，形式上可以直接指定两个相邻的Node，也可以设计为一个以State为参数的函数，函数处理的结果就指向下一个Node。

有了Graph图这个工具之后，我们就能给刚才的RAG加上反思能力了。比如在第四步生成答案后，增加一个新节点，把用户的问题以及大模型生成的答案一起丢给大模型，再问大模型这个答案靠谱吗？如果大模型判断这个答案是牛头不对马嘴，那就通过Edge把流程重新指回第二步，重新检索，重新生成，这就是经典的React思考行动的模式。有了Graph，Agent才真正拥有了反思、重试和自我纠错的能力，就彻底的活了过来。但这还没完，我们理想的现代Agent还有一个终极要求，那就是流程自主规划。什么意思？就是用户随便丢一句模糊的需求，比如帮我调研一下竞品并写份报告，Agent就需要自己去拆解任务，第一步该干嘛，第二步该干嘛，最后再把结果汇总给你。

换成技术语言就是要让大模型在运行的时候，根据用户的问题自己动态去构建一条Chain或者是一个Graph，而不是靠程序员提前把代码写死。这么天马行空的要求。如果是你会怎么构建呢？你会选择用 chain 还是用 graph 呢？不妨在评论区先说说你的想法。其实好的结果也不用猜，LangChain 官方给出了答案，就是彻底的抛弃 chain，全面拥抱 graph。如果你对 LangChain 稍微有一点深入的了解，你会发现 LangChain 中的 DeepAgent 模块，底层全是用的 LangGraph 来构建的。现在哪怕你调用的只是最上层的一个简单的 agent 接口，它的底层也是在用 LangGraph 给你画图。

所谓自主规划，其实本质上就是程序员提前准备好 state 和 node，然后让大模型根据任务来动态构建 edge，相当于你去问大模型，我要完成一个这样的目标，帮我补充其中的 edge 代码。其实你仔细看一下现在市面上的所有 agent 的产品，本质上都是这样的一种模式。平台集中维护 state，形式上通常叫做记忆，还有各种 node 技能箱，比如操作本地文件的、查看网页的呀、检索内容的呀，还有对内容进行汇总的呀等等等等，甚至还有各种开源市场的 skill。至于中间的任务拆解、结果汇总等等过程，全都是通过极其严谨的提示词询问大模型来完成的。这也是为什么 agent 越严谨，消耗的 token 就越多的原因，因为背后的提示词就会越来越复杂。

你如果还想对这种模式有更加深入的了解，就可以来了解一下 LangChain 的 DeepAgent 模块。最后可以看到，目前阶段的所有 agent 的产品其实本质上都是 LangChain 这种思想的具象化。我们可以通过构建一个 chain 来构建一个单向通道，这种模式适合处理流程确定的任务，也可以来构建一个 graph，这种状态驱动的循环图，来做那一些不确定的需要反思和自主规划的复杂 agent。现代 agent 的发展思路其实就是把人类的工作一步步移交给大模型。不过在目前阶段，大模型还只是做了自主抽象业务流程，也就是 edge，至于构建 state 和 node，目前依然是人类的工作，至少是人类和 AI 协作的工作。如果再把它们也交给大模型自动处理，那就离各种科幻小说不远了。这一层架构思维你看懂了吗？
