在你的印象里，Redis 到底是个什么样的产品？缓存吗？分布式锁吗？还是排行榜计数器啊？现在 Redis 有了新的定位，就是 AI 时代最核心的底层基建。很多人一做 AI 应用，就会跟着网上的概念去盲目的折腾 Milvus、FAISS 这些以前听都没听过的新型向量数据库，依赖装了一大堆 API 查得晕头转向，结果连最基础的语义检索和 RAG 都没搞懂。但其实现在你回头看看，Redis 这个稳定支撑了整个互联网几十年业务的 KV 数据库，早就已经完成了面向 AI 基建的华丽转身。现在它已经是一个功能强大、性能稳定而且稳定可靠的 AI 基建设施了。只要你真的梳理清楚了你的要求，Redis 绝对能够给你足够的惊喜。这次我们就从实战出发，带你把 Redis 八点零的向量集合、混合检索和 MCP 服务一次性跑通。

建议你也打开终端，跟我一起来试试吧。我是楼兰，关注我，IT 路上一起进步。我们先来看核心的第一站，就是 Redis 八点零引入的全新原生数据类型 Vector Set 向量集合。大模型的基础是数据，而大模型理解世界的数据形式那就是向量了，把文本或者图片压缩成多维空间里的坐标，两句话意思越接近，坐标距离就越靠近。不管是做 RAG 还是做模型微调，一个能够稳定存储向量的数据库都是必不可少的。Redis 的 Vector Set 就是向量最坚实的底座，使用 Vector Set 你可以很轻松的把一整串的复杂向量作为核心数据存进 Redis 里。当你给定它一个新的问题时候，又可以从 Redis 里快速找出和用户的问题语义最相关的向量片段，这就是现在天天在说的 RAG 的基础。

而且基于 Redis 以往强大的数据检索功能，你还可以很轻松的在语义检索的基础上增加条件匹配检索，一条指令就可以同时支持传统的按条件过滤的数据检索以及新型的按语义相似度的向量检索。光说不练假把式，这次我们就直接上手来试试，我们在终端你可以写入一批测试数据，这里就可以添加原始的数据以及它们对应的向量。接下来第二步除此之外，我们还可以给这些原始数据添加其他的补充数据。接下来就可以快速按照你想的条件进行过滤了。像这个案例，我们可以找到和目标向量相似度最高的两部电影，同时又强制要求必须是在二零一五年之后上映的科幻片。你看，虽然星际穿越和黑客帝国在题材上它也是硬核科幻，但因为年份早于二零一五年，所以在底层就直接被剔除了，最终系统非常精准的返回了流浪地球和头号玩家以及他们的匹配得分。

一条命令就解决空间计算和业务过滤，这就是为 AI 原生设计的数据结构。刚才的 Vector Set 适合快速轻量的集合对比，但在实际的企业级开发中呢，情况往往更复杂，你的知识库里可能存着上百万条数据，你既要搜电影标题的关键字，又要对分类去做标签匹配，这就需要升级到 Redis 内置的向量搜索引擎了。在这个引擎底层呢，Redis 提供了三种经典的索引算法，第一种是 Flat 暴力遍历，虽然慢但准确率百分之百。第二种 HNSW 主流的多层导航网，像地图一样分层跳跃找路，速度非常快。第三种 Vamana，Redis 八里的终极杀器，打破多层网络的限制，用极小的内存开销跑出非常高的检索速度。这些算法的底层细节呢，我之前的视频已经拆碎讲透了，还没看过的朋友可以去翻翻我之前的视频。

今天我们来看实战中怎么把这些维度捏合到一起。首先我们就创作一个索引，同时包含全文检索、标签分类、数据范围和向量维度，像这样的可以添加几个测试数据，这些哈希结构的数据就会进入到之前的索引当中。接下来就可以进行复合的混合检索了，例如这个案例就是查在科幻标签下二零一五年之后评分大于等于八点五的电影里和查询向量最相似的前两个电影了。把业务过滤放在前面，把向量检索放在后面，一次查询直达结果，这就是企业级 RAG 知识库最标准最高效的玩法。正常来说能存数据也能查数据，那么一个向量数据库的职责就已经完成了，但 Redis 的想法显然远不止于此。Redis 还设计了标准的 MCP 服务，可以直接和大模型交互，让你通过大模型用自然语言来访问 Redis 的数据，把 Redis 真正升级成大模型背后的核心基建。
