首先什么是 AQS？它是 JUC 并发编程包里提供的一个小框架，别被框架这个词给吓住了，你就把它想象成一个负责修路和装红绿灯的基建公司就行了。AQS 给我们提供了两样最基础的设施，第一样是红绿灯，在代码里它就是一个叫 state 的数字，第二样是一条大马路，在代码里它就是一条双向链表组成的队列。AQS 的厉害之处在于它把最难的活全干了，比如红灯亮了车子怎么停，后面的车怎么排队，绿灯亮了怎么叫醒第一辆车，这些涉及到底层线程阻塞、唤醒、排队的脏活累活，AQS 全包圆了。那留给我们程序员做的是什么呢？AQS 说路我修好了，灯我也装好了，但是这个红绿灯到底亮几秒，左转弯能不能走，什么时候变绿，这些具体的交通规则你们业务方自己定。

所以 AQS 专门留了几个搞事情的方法给你来填空，这几个方法特别关键，大家一定要记住，一个呢是 tryAcquire，你要在这里写清楚满足什么条件才能成功抢到锁。第二个是 tryRelease，你要在这里写清楚怎么才算释放了锁。那如果是共享模式对应的方法就是 tryAcquireShared 和 tryReleaseShared。AQS 的工作原理就是有车来了，AQS 先调用你写的 tryAcquire 方法问你，老板能过吗？如果你返回了 true 表示能过，AQS 就放行，如果你返回了 false 表示不允许过，AQS 就说好嘞，那你去队列你排队睡觉吧。tryRelease 也是类似的逻辑，你打个滴滴到站了，AQS 就会调用你写的 tryRelease 问你，老板到站了要不要下车？

如果你返回了 true 表示能下车，AQS 就释放锁，允许下一个人来抢锁。如果你返回了 false 表示你不想下车，AQS 就不释放锁，后面的人就要乖乖等着。理解了 AQS 的底层逻辑，你再去看 JUC 的源码其实都是轻而易举的事情。看懂了的朋友别忘了双击屏幕点个赞，咱们接着往下看，用 AQS 又是怎么造出各种锁的呢？这里就引出了第一对概念，乐观锁和悲观锁。悲观锁是我们最熟悉的一种锁，只要有一个线程抢到了一个关键资源，别的线程就只能在后面等着，像 Java 当中最熟悉的 synchronized 和 ReentrantLock 都是属于悲观锁。

乐观锁其实就是不上锁，它想要将一个变量从零变成一，并不去锁定这个变量，只是去检查一下这个值现在是不是零，如果是零那就继续操作，将它设置成一，如果不是零，那说明有其他线程正在用这个变量，那我这次修改操作直接失败就是了。从 AQS 的角度来理解这两个锁呢，其实就是看你怎么去改那个红绿灯的状态。不过这里必须先提到一个核心技术 CAS，简单理解就是一次先比较再交换的操作，比如我要把一个变量从零变成一，就得先检查一下当前这个值是不是零，是就修改成一，如果不是零，表示这个值别人已经修改了，那就不要改了，过一会儿再来重新尝试。CAS 与众不同的一点在于它是一条操作系统内核级别的指令，它在硬件层面保证了比较和交换这两个操作的原子性。

你可以理解为修改红绿灯的那一瞬间，CPU 保证了绝对不会有第二个人插进来打断你，要么成功要么失败，没有中间状态。乐观锁的态度就是我觉得没人跟我抢，那就先用 CAS 试试，如果 CAS 成功了，直接通过，效率的非常高，像 JDK 里的 AtomicInteger 这一系列啊，就是典型的纯乐观锁实现。那悲观锁的态度就是肯定会有人跟我抢啊，那我不试了，直接排队。但在 AQS 的框架下通常是两者的结合，先用乐观锁 CAS 尝试去抢一下红绿灯，如果抢失败了，说明有人刚好插在你前面改了灯，这时候再来切换成悲观锁模式，乖乖的去 AQS。队列里排队挂起。所以 AQS 的本质就是 CAS 冲锋在前，队列兜底在后。搞懂了 CAS，那接下来内容就轻松多了。我们再来看看怎么用 AQS 造出各种花样的锁。

其实说白了就是在玩那个 state 数值的游戏。先说排他锁，概念很简单，就是这把锁同一时间只能被一个线程独占，其他人谁也别想进。怎么造呢？你在写规则的时候逻辑很简单，我看一眼 state，如果是零，我就用 CAS 把它变成一，啊这把锁就是我的了。如果我不释放，state 永远是一，别人的车来了，AQS 问你能过吗？你说 state 是一就不允许通过，AQS 把别人扔进队列了。JDK 里大名鼎鼎的 ReentrantLock 就是这么干的。那共享锁呢？概念就是这把锁可以同时被多个线程持有，大家一起进。怎么造呢？

比如我们要造一个 CountdownLatch 或者是 Semaphore 信号量，还有 ReadWriteLock 里的读锁，这时候 state 初始值可能是五，那你的规则就变成了，车来了，我看 state 是不是还大于零，如果是，我就把 state 减一放你进去，只要 state 还没减到零，后面的兄弟都能进，不用排队。直到 state 变成了零，大门才关上，后面的车才需要去 AQS 队列里等着。看到没？不管是独占还是共享，在 AQS 眼里无非就是 state 限制成零和一的开关，还是 n 减到零的计数器而已。最后咱们来聊一个有意思的话题，就公平锁和非公平锁，这其实就是关于能不能插队的问题。

大家想一下，你刚到路口发现前面已经排了一长串车，表示队列里有很多线程，这时候你是老老实实排到队尾，还是趁红绿灯变绿的一瞬间一脚油门冲过去呢？如果你是个老实人，你在规则里加一行代码，去查查有没有前辈在排队，如果有，我就不抢了，去排队去，这就是公平锁。那如果你是个老司机，你不管队列里有没有人，上来就用 CAS 猛抢一把 state，抢到了算我运气好，抢不到我再灰溜溜的去排队，这就是非公平锁。这里问大家一个问题，你们最熟悉的 ReentrantLock 默认是公平的还是非公平的呢？为什么会这样呢？不妨在评论区说说你的想法。好了，讲到这儿，咱们把 AQS 的底裤都看穿了。
