现在 Agent 太多了，学不过来怎么办？这次我给你一个三加六的万能公式，一次全部搞定。不知道你有没有这样一种感觉，现在 AI 越是越来越强了，但也越来越让人头晕了。Cursor、Trae 这些编程 Agent 还没玩明白呢，转眼又冒出了像 Codes、Defi 这些工作流产品，紧接着 CodeX、Worker Buddy、小龙虾、DeepSeek-Hunies 各种本地 Agent 马上开始轮番轰炸。现在呢，你打开微信、飞书，甚至是手机操作系统，都在往外弹各种 Agent，全都在告诉你我也变智能了。好用是好用，但每次面对一堆新工具、新名词，那种被技术牵着鼻子走的压迫感，也真的让人挺焦虑的。

但这次我帮你把这些花里胡哨的外衣全部扒掉，把市面上所有主流的 Agent 的能力做了一次深度的梳理，总结出了一套极其简单的三加六公式。只要你脑子里装下这个公式，以后不管什么样的 Agent 的产品，你一眼就能看穿他们在玩什么把戏，再也不会被各种技术牵着鼻子走了。接下来点个赞，马上开始上干货。我是楼兰，关注我，IT 路上一起进步。在讲公式之前，先分清楚一个基础概念，到底什么是大模型，什么是 Agent？我们经常听到 DeepSeek-V 四又跑了多少分呐，Kimi-K 三能力有多强啊，这些打得不可开交的，就是大模型。但这些大模型能力再强，本质上也就是一个非常干巴、冷酷，甚至是有点死脑筋的文本处理机器。他们认识世界的途径永远只有三个非常死板的信息通道，这就是公式里的三。

第一个呢，System Prompt 系统提示词，通常是用来跟大模型交代你们聊天的背景，比如你是谁，你要遵守什么规范。第二个呢，User Prompt 用户提示词，也就是你发给它的具体问题。第三个 Tools 工具，这是误解最大的，对大模型来说，工具只是相当于一个信息列表，大模型只看列表上有哪些工具可以用，以及用了之后会返回什么结果，至于这个工具它是怎么执行的，是读了你本地电脑还是调用了外部接口，大模型完全不知道，它也完全不关心。所以大模型本身通常是非常死板的，但 Worker Buddy、CodeX 这样的产品，你只要提需求，它们就能听懂话，还能主动干活，这些就是 Agent。

Agent 的本质就是架在大模型之上的一套应用程序，它们接收你提的问题，进行优化处理后，最终整理成大模型能懂的三种信息交给大模型处理，然后再把大模型的结果拆解后返回给你。在这个过程中，大模型只提供基础能力，而 Agent 就要绞尽脑汁把大模型的基础能力包装成你身边的全能管家。至于怎么包装呢？那这个中间就是八仙过海各显神通的领域了，我把这些花样繁多的招数给你整理成了接下来的六大能力，目前这些 Agent 花样再多也逃不过这几条主线。你给 Agent 发问题，往往只关注自己的需求，而 Agent 它除了接受你的问题，还要给大模型组织额外的系统提示词，让大模型能够更听话。能力一，动态提示词优化。

最基础的玩法呢是给大模型套个人设，你想问技术，那就告诉大模型让它扮演架构师，你想问游戏，那就让大模型去扮演无敌玩家，这就是基础的动态提示词优化。像豆包早期可以自己定制各种 Agent，玩的就是这个套路。后来问题越来越复杂，往往需要很长很复杂的提示词才能把需求和过程讲明白。比如说你想让 AI 去掉文章里的 AI 味儿，那这里面的弯弯绕太多了，你不可能每次提问都把几十上百条规则给补充进去吧，那怎么办？Agent 会把这些复杂的提示词固定下来，记录到一个文本里面，如果你触发了这个需求，它就直接从文本里面把它读出来，补充到系统提示词里。这种模板化的提示词技巧就是强大又神秘的 Skill。有了这些技巧，大模型就能快速清晰的了解你的需求，给你最精准的答案。能力二，记忆优化。

很多 Agent 的产品会让你感觉到越来越懂你，你跟它聊的越多，它就越了解你的需求。但大模型本身它就只是一个程序而已，你给它发一个问题，它就给你个答案，它可不知道你们以前聊了些什么。那 Agent 是怎么让大模型更懂你的呢？简单点的就是短期记忆，把你在这个窗口的聊天记录全部记下来，每次提问都补充进系统提示词。但如果是跨窗口呢？比如你让 Worker Buddy 记住你是楼兰，在下一个新任务里，你不用再说，它也能用无敌的 IT 知识来回答你，这就是长期记忆。这里面隐藏着一个非常硬核的技术挑战，就是上下文压缩。你要跟 Agent 聊一年，那记录太多，大模型迟早撑不住啊，这时候就必须对记录进行压缩了。好的压缩策略可以让大模型越聊越明白，而不好的压缩策略聊着聊着大模型它就降智了，这就非常考验 Agent 厂商的功底了。

通过这些玩法，Agent 就能在你和大模型聊天的过程当中保驾护航。能力三，外挂知识库。大模型虽然懂得多，但它肯定不懂你们公司内部规定，也不懂你电脑里的私密文件。一问公司最新的报销标准是什么，它肯定抓瞎。这时候Agent会先去你本地或公司的知识库里搜一圈，把相关文档找出来，悄悄塞进系统提示词里，这是背景资料，参考这个来回答。这种把外部知识喂给大模型的戏法就是RAG检索增强生成，有了它，大模型就从一个通用的学霸变成了你身边的百事通。除了系统提示词，还有用户提示词。大模型是可以接收你提的问题的，但现实中我们提需求往往非常的随意。比如老板经常甩一句，帮我搞定昨天的数据，大模型听到这种话肯定直接懵了呀。所以好的Agent绝对不能把这种模糊的问题直接扔给大模型，它要对你的提示词进行修改和完善。

那最基础的能力就是能力四，任务推演循环。首先是要对问题进行改写，昨天是哪天？数据是哪些数据？这些都要Agent想办法帮你去补充完整。然后呢是任务拆解，把大目标拆成几个具体的小目标，引导大模型一步步的完成任务。比如第一步要去找Excel，第二步要清理数据，第三步要画图表。这里面最核心的就是要设定任务循环，也就是Agent Loop。Agent需要协调先干什么后干什么，最厉害的是它要允许在这个过程当中犯错，比如清理数据的代码写错了，报了一堆error日志，那Agent就要把这些日志抓回来，补充到提示词里，让大模型反思并且自我纠错。这种补充问题、拆解任务、报错、再自我循环的内部推演，其实就是在不断重构用户的提示词，这也是最能体现Agent产品差距的地方。

不同产品的Agent Loop套路不同，对任务的适配度也就天差地别。所以你经常会感受到这一类任务用这个Agent更合适，那一类任务呢用另一个Agent效果更好，核心区别就在这里。接下来就轮到大模型的工具信息了。大模型只管接收信息，它不管中间的信息是怎么处理来的，这里面Agent玩的花样就多了。能力五，本地工具的用。以前Agent可以写一些通用的函数，比如调用搜索引擎、访问网页这些，但是都有一个问题就是离用户太远了。所以后来Agent进化了，把自己部署到用户电脑本地，提前写好操作本地资源的函数，比如读写本地文件，执行Python代码，甚至是控制鼠标键盘。正是有了这些本地工具的拓展，才诞生了CodeX、Local Buddy这些非常强大的本地Agent，他们把大模型从网上的工具变成了你身边的员工。

能力六，外部服务调用。本地工具再强也没法访问企业服务器里庞大的业务数据。为了调用远端接口，Trans又诞生了一个大杀器MCP模型上下文协议。比如调用GitHub的代码，使用Figma进行前端页面设计，调用高德地图进行路线规划等等，都有了非常成熟的MCP服务。很多人以为MCP只是个连接外部接口的工具，但MCP的架构远不止于此。它把与大模型交互的所有重要信息都进行了统一打包。比如企业数据往往有特殊的格式要求，那MCP就定义了Resource资源接口，把内部数据格式暴露出去，让用户可以更好的评估自己的需求。再比如企业级服务可能需要更精准的提示词，MCP也直接定义了Prompt提示词接口，企业可以通过MCP向客户暴露标准的提示词，让用户高效的使用服务。

所以MCP虽然走的是传统RPC的技术思路，但它的协议内容已经彻彻底底按照大模型的方式进行了优化。你看把这层窗户纸捅破，Agent的世界是不是也就非常清晰了？不管它叫什么名字，包装的多么高大上，底层全是大模型那干巴冷酷的三个信息通道，System Prompt、User Prompt、Tools，而Agent就是在这个基础上玩出了各种各样的花样。以后再看到什么颠覆性的AI新产品，你就直接拿这个三加六的公式去套，那你就再也不会被那些花里胡哨的技术名词牵着鼻子走了。其实回头来看，Agent走的也就是以前的老路子，以前是围绕数据库、缓存、搜索引擎这些数据处理能力去深挖产品的需求，现在只是换成了大模型的三大基础能力，深挖应用场景。所以夯实基础能力，深挖外部需求依然是AI时代的核心，也是你我努力的正确方向，你说呢？
