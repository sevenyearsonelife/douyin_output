这里有一串名字，它们各自对应一个编号，我们根据名字来找到编号，也就是一种映射。在数据结构中实现这样的方法称为散列表，或是哈希表，它的时间复杂度是大 O 一，也就是常数时间。那怎么做到的呢？最简单的方法就是准备一个固定大小的数组，然后将这些键值对散列在不同的单元格中。但是要想根据关键词找到对应的单元，如果从头开始比较，那么需要比较七次才能找到，最差的时间复杂度是大 O n，比较耗时。而散列表则先把关键词通过某种映射转换成数组的索引，然后根据索引，也就是距离起始地址的偏移地址，就可以瞬间找到。这个转换称为散列函数，那么这个散列函数有什么讲究吗？假如现在对所有的名字进行映射，如果都转换成索引六，那就意味着所有的数据项全部挤在一起了，找到六号单元格后还得都比较一遍，就很慢了。

相反，映射成不同的索引值，也就是散列均匀散布。那么最简单的散列函数就是取余数，比如我们可以把一个字符串，每个字符找到对应的 ASCII 码编码，ASCII 码是对包括英文字母等字符的编码方式，然后把它们相加，再取散列表大小为十的余数，得到索引值，毕竟索引值不能超出表的大小。那么用 C 语言来表示，这里的 key 是指针，通过对应地址的取值，用 while 循环遍历所有的字符，一直到杠零作为结束符。接着每次根据 key 得到字符编号，加到 hashval 上，当然 hashval 我们得先声明，并初始化为零，最后对 hashval 取余就可以了。但是如果表很大，比如是幺零零零七，然后假定一个关键词最多是八个字符，ASCII 码编号中最大的是一百二十七，总共最大就是幺零幺六，远远小于幺零零零七，一点也不分散。

事实上比如 a b c b a c c b a 都是一样的结果，所以更好的办法是将字符的位置信息编码进去，因为英文字符加空格一共是二十七，所以我们把每一位的编号乘为二十七的指数，再乘到字符编码上去，这样就实现了更好的分布。但是这里有很多乘法，对计算机来说乘法相比加法费时得多，所以将这个算式转换成这样的方式就好多了，这样的转换方式称为 Horner 法则或秦九韶法则。这样还不够，我们再把二十七改成三十二，毕竟也差不多嘛，而三十二就是二的五次方，我们对一个值乘以三十二，对于二进制而言只需向左移五位，也就避免乘法了，这就是二进制的好处了，刚才的代码就可以修改成这样了，其中两个小于号就是 C 语言中的一位符号。好了，假如我们有了一个合适的散列函数，但是还是无法避免出现两个不同的关键词被映射到同一个单元格中，那可怎么办？

我们主要介绍两种解决办法，分别是分离链接法和开放定址法。首先，若是分离链接法，原先的数组里每个单元格中都有一个区域存放指针，也就是内存地址，默认情况下初始为 null 空。这是对应的 C 语言代码实现 find 函数。那现在有一个数据项来存储，首先通过散列函数获得索引值，这里我们就对 key 一取十的余数，就像领到房间一号，拎着它的值准备入住。然后从单元格地址 arr 变量出发，通过 while 循环找到这里链表的末尾，接着是插入的代码。在查找之后，若是 null 空，则开始分配链表中新的节点，插入到末尾。这里我省略了存储的值和新节点的 next 指针的区域。其实除了链表，其他的也可以，只是散列函数就已经尽量避免冲突，简单的链表够了。然而这种方法的缺点是需要存储指针和动态分配，需要耗费更多的时间。

接下来我们介绍开放定址法，首先是一张容量为十的空表。现在有一个关键词为八十九的需要插入，这里对应的值省略了。经过散列函数，这里对它取十的余数就是九，找到插入搞定。接着是插入十八，获得索引值八，插入搞定。然后是四十九，对应的索引值九已经有人了，所以顺移一位，插入索引值零的位置。然后是插入五十八，索引值是八，有人了，顺移一位，九也有了，再移动一位不行，再移动一位总算可以了。以此类推，这里每次位移都是按照 f i 等于 i 的方式，这称为线性探测。我们看到它容易扎堆，称为聚集现象。而另一种平方探测法就是按照 f i 等于 i 的平方来顺移，那么表中的分布就变成了这样。其中五十八在第二次是，也就是 i 等于二十，顺移四次才到达空位置。虽然这样能够有效缓解聚集问题，但是因为跳着走容易产生浪费，需要的表也可能会更大。

好了，其他还有如双散列、再散列、可扩散列等，这里就不展开了。虽然它的查找时间仅仅只有大 O 一，非常棒，但是它和其他的数据结构，比如二叉查找树相比，因为没有顺序，所以不能遍历找到最大值、最小值等。所以不同的数据结构应当在各自合适的场景中使用。
