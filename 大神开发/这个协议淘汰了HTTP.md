就是一张写满了外星文字的纸头，没有 KFC 和 IETF 我们也能搭出互联网，所以我建议全面抛弃 HTTP 而使用新的协议，叫它 HP OK，全称 HTTP But All OK，正如字面意思，这个协议的所有响应状态码都只能是二百 OK，我们以 HTTP 一点零举例，因为有些神秘的运营商不喜欢 HTTP 二点零和三点零，加上二和三有一大堆隐私更新，个人隐私和集体安全是有不可调和的矛盾的，我有责任义务监控你是不是想要制造恐怖袭击，所以 HP OK 原生不支持加密，并且 must 大写的 M U S T 遵守 KFC 八一七四的 must 使用明文传输，这是 HP OK 的报文，我们有请求方法、路径和我们的 HP OK 协议标识符，当然也有响应的报文，注意到状态码固定为二百 OK，当然这些都只是纸上谈兵，所以我修改了 Python 的网络库，现在 Python 网络请求默认使用 HP OK 协议，我们可以搭建一个支持 HP OK 的服务器，提供用户查询服务，为了全链路支持新协议，我修改了 curl，让它默认使用 HP OK，并在试图访问 HTTP 服务的时候报错，同时我写了个 HTML 把它托管在这个服务器上，当我打开页面搜索时，它会向服务器发送查询用户请求并展示结果，顺带一起，这是修改后的一到浏览器，现在它认为 HTTP 协议不符合其设计时的隐私要求，转而强制使用 HP OK，我们输入 HP OK 冒号杠杠一二七点零点零一冒号八零，看到一切正常，搜索因此我发现这个用户不存在，查看控制台，状态码是二百，完全胜利，哦吼吼吼吼，呃哈哈哈。
