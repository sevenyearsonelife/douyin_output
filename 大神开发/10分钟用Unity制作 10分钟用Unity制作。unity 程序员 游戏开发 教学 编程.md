我们已经很久没有做过与游戏相关的视频了。之前呢，有一个特别火的游戏，和班尼特福迪一起攻克难关，又叫做绝地求生。很多小伙伴也都在这款游戏中找到了儿时的欢乐。这个游戏玩法简单，节奏轻松，可以说非常的修身养性。今天呢，我们用十分钟时间也在 Unity 中来重新制作这款游戏。我们不用任何第三方插件，全部使用 Unity 内置的功能模块，并以这个游戏给大家讲解一下 Unity 中游戏开发的思路、技巧和基本流程。如果你正在学习游戏开发，也希望能带给你一些帮助。这款游戏的玩法很简单，就是抡你手中的锤子，移动你的身体不停的往上爬，直到登上太空就算游戏通关。这个游戏的主要操作方式呢，也只是通过鼠标或者触摸屏来控制锤子的方向，并且这是一款二维游戏。Unity 对二维游戏的开发有一套专门的工作流程。

我这里使用的是 Unity 的最新版本，进入后创建工程，勾选二维选项，然后来到我们 Unity 的主界面。首先我们将事先绘制好的身体图片直接拖拽到场景中，然后将头部也拖拽进来作为身体的一个子节点。这样我们利用场景树节点的特性，头部就会自动跟随着身体而移动。这里顺便提一下，Unity 中左边这些列表中列出了场景中的所有物件，它被称作 Game Object。比如之前添加的玩家身体、头部以及场景中用于渲染的虚拟摄像头等等，它们都是 Game Object。每个对象呢又是由很多组件 Component 构成，比如这里的 Transform 可以用于修改游戏对象的坐标位置，或者它们的旋转角等等。我们再来看一看之前创建这个身体对象，它包含了 Sprite Renderer 这个组件。

Sprite 这个术语在游戏中代表二维的图片或者动画，Sprite Renderer 适用于渲染二维图片的组件。如果没有它，这张图片也不会显示在游戏中。随后我们可以在身体上添加一个 Rigidbody 2D 组件。Rigidbody 是物理引擎中的一个术语，翻译过来叫做刚体。如果你希望游戏中的元素受到物理引擎的影响，比如受到重力下降或者碰撞之后反弹等等，就可以直接添加这个组件。同时呢，为了让物理引擎帮我们实现物体间的碰撞，我们需要再添加另外一个组件 Collider 碰撞器。Collider 有许多不同的形状，对于身体的部分我们可以使用一个 Capsule Collider，它是一个胶囊形状的碰撞器。我们可以在右边的窗口里修改这个 Collider 的大小和偏移，调整使得这个绿色边界与我们的图片相吻合即可。

随后我们再添加一个地面，用同样的方式创建一个 Collider。这时我们运行游戏，这个身体对象就会受到重力下降，并且会和地面碰撞。接下来我们可以在场景中加入锤子这个对象。不过在实现控制逻辑之前，我们先来思考一下锤子的控制算法。为了控制锤子的方向，我们可以将屏幕中心点到鼠标的位置表示成一个向量，然后用玩家身体的坐标加上这个向量求出锤子在场景中的位置。同时我们可以设定一个向量的最大距离，如果锤子的移动超出了这个范围，则将它限制在这个最大距离上。这段逻辑我们可以通过创建一个脚本实现。我们可以在之前创建的 Body 对象上点右键，然后选择创建一个新脚本。我们将脚本命名为 Player Control，接下来我们会将玩家控制的基本逻辑都写在这个脚本里。

首先我们在脚本里定义两个 Public 变量，Body 和 Hammer Head，它们分别代表身体和锤子的头部。这里的 Max Range 代表锤子活动的最大范围。然后在 Start 函数中，我们可以使用 Ignore Collision 告诉 Unity 忽略身体和锤子之间的碰撞。随后的 Fixed Update 会以固定的间隔被 Unity 调起，我们会将主要的控制逻辑写在其中。这里使用 Fixed Update 也主要是为了保证我们的逻辑与 Unity 中的物理引擎计算同步，避免出现不一致的现象。然后呢。我们可以定义两个变量 center 和 mouse，分别代表屏幕中心的坐标和鼠标的当前坐标。接下来我们将它们从屏幕坐标系转换到世界坐标系中，也就是 Unity 中所有游戏对象都处在的全局坐标系下。

这里的代码呢会计算出一个向量 mouse vector，并将其限制在 max range 范围内。最后我们用 Rigidbody 2D 的 Move Position 来移动锤子，这样锤子在移动的过程中如果碰到其他的 Collider 会自动停下来。如果我们直接使用 transform 点 position 来修改坐标，Unity 是不会进行碰撞检测的。我们回到编辑器，锤子的头部我们可以先创建一个圆形代替，并命名为 hammer head，并加入之前提到的 Rigidbody 2D 和 Circle Collider 2D，用于进行物体间碰撞检测。之后我们将 body 和 hammer head 用鼠标拖拽到脚本的两个变量上，从而将脚本变量与场景对象关联起来。最后我们运行游戏，可以看到这样的效果。

这里有两个需要注意的地方。首先我们发现锤子在快速移动的时候会直接穿过地面，并不会与地面碰撞。这个我们可以通过设置 Collision Detection 为 Continuous 来避免。它会修改 Unity 中物理引擎碰撞检测的方式，用一定的性能开销来保证碰撞的精确计算。另外我们会发现碰撞发生时，锤子的头部会发生旋转，这个我们可以通过锁定刚体在 Z 轴方向上的旋转来避免。随后我们可以给锤子加入贴图，并调整贴图的大小，修改贴图的渲染顺序，将它移动到最前面。然后我们可以在脚本中根据之前计算的向量来调整锤子的旋转方向。那解决了锤子的基本方向控制，我们应当如何实现用锤子撑起身体的动作呢？你可能会想，只要一只手向上拉，另外一只手反向施力，锤子就会顺时针转动，因此玩家就可以保持图中的动作。

但学过初中物理都知道，这根本就不现实。你对锤子施加一个力，锤子也会反向对你施加同样大小的力，这两个力会相互抵消，你也不可能抓自己头发把自己拉起来，对吧？如果我们把玩家和锤子想象成一块连在一起的木板，并且木板的左边还要更重一些，木板的重心靠左，自然就会下落。那你可能会问，这种不切实际的操作在游戏中又怎么实现呢？那当然我们用物理引擎来模拟自然会失败，但谁说游戏一定要遵循物理规则呢？我们其实完全可以简化这里的控制逻辑，只要操作符合我们的直觉就够了。首先我们应当判断锤子是否与场景中的其他物体碰在一起，如果是的话，我们将根据锤子的方向来调整玩家身体的位置。什么意思呢？我们来举一个例子。

比如我们鼠标当前移动到这个位置，我们可以从玩家身体的中心到鼠标做一个向量，然后根据锤子头部的位置减去这个向量，就可以得到玩家身体应当移动到的位置。随后我们只需要让玩家的身体朝目标位置靠拢即可。但是移动身体有很多种办法，我们可以提供一个初速度，或者通过设置身体坐标等等。不过这里呢我们可以通过给身体施加一个力的方式来完成移动，这样看起来会更自然一些，并且这个力的大小和目标位置的远近是成正比的，距离越远力越大，距离越近力越小。在了解了算法的原理之后呢，我们可以在之前的脚本中添加下面这段代码。首先我们可以调用 hammer head 中 Rigidbody 2D 组件的 Overlap Collider，来得到与自己相碰撞的物体。

这里的 gravity scale 可以调节身体受到的重力大小，这个会直接影响身体下落的速度。这里的参数没有什么硬性规定，通常需要经过反复实验找到比较合适的来使用。接下来我们来看一下场景中的一些非功能性物体，比如玩家的手臂实际上是由若干张贴图构成的。我们可以先在场景中加入手臂对象，然后将手臂设置成身体对象的一个子节点，这样手臂呢才会跟随着身体而移动。接下来我们创建一个脚本 hand 来切换手臂的贴图。这里我们需要定义三个变量，其中第一个变量代表我们手臂握住手柄的坐标位置，这里我们叫做 hammer handle。同时在场景中我们可以在 hammer 下面创建一个空节点，并拖动它到差不多手柄的位置。这里的第二个变量代表我们要用到的所有手臂贴图，它是一个列表。随后呢我们可以在编辑器中将所有的手臂贴图拖拽进来。

第三个变量代表是左手还是右手，因为左手和右手实际上用的是完全相同的贴图，只不过是把图片翻转了一下。这里代码逻辑很简单，我就不细讲了。程序的部分呢大概是这个样子，我们可以从身体到锤子手柄做个向量，然后根据它的长短和方向来切换手臂的贴图。那关于玩家头部呢，我们也可以让它跟随着鼠标而旋转。我们可以根据鼠标与屏幕中心的夹角来计算头部的旋转角，并且可以将这个夹角限制在一定的范围内，不然这个动作看上去会很扭曲。当然如果鼠标是出现在屏幕的左半部分，我们还需要将头部贴图沿着 x 轴翻转过来。最后我们还可以每间隔若干秒切换一次贴图，来实现一个眨眼的效果。玩家的部分到这里我们就完成的差不多了，最后我们可以用脚本来实现摄像头跟随玩家的效果。

我们同样可以将摄像头的当前位置到玩家的位置表示成一个向量，不过我们每一帧只移动这个向量的某一部分，比如前百分之五十，这样摄像头会逐渐的向玩家的位置靠拢，直到和玩家重叠为止。使用这种方式来移动摄像头，画面会看起来平滑很多。最后的一步就是我们场景的搭建了，这里的场景素材呢我直接使用的是这个免费的资源包，2D Handcrafted Art。我们可以把这些图片按照喜好拖拽到场景中，另外千万不要忘记给每个 sprite 添加一个 collider，不然玩家的身体会直接穿过它们。这里我们还有意的把场景在三维空间中分成了几层，这样搭配透视摄像头可以起到一个视差滚动的效果，也就是说背景图片会比前景图片移动的要慢一些，这样可以给我们的二维场景创造一个深度的错觉。同时我们可以调节这里相机的参数，找到一个比较合适的视角。
