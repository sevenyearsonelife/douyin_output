内存中有很多个进程，它们独自维护着一个虚拟地址。那么如果进程互相之间需要传输数据怎么办？在上期的视频中我们讲到了共享变量，进程间互斥访问。那这期视频我们来讲讲更复杂的同步问题。在两个进程间首先需要一个共享的固定大小的缓冲区，进程一产生的数据放入缓冲区中称为生产者，另一个进程从缓冲区中取出数据称为消费者。假如这时的缓冲区已满，那么生产者就要阻塞，停止生产，而如果缓冲区已空，那消费者就要阻塞等待。那么如何让这两个进程保持同步呢？这称为生产者消费者问题，也称为有界缓冲区问题。这个问题看起来简单，但实际会出现复杂的竞争问题。首先我们需要一个变量 count，指代当前缓冲区中的数据项的个数，当前是空的，所以 count 就是零。

我们来看主要的 C 语言代码，首先是生产者，produce item 函数产生一项 item，然后判断当前的 count 是否是 n，代表缓冲区里的总项数，那这里 n 是七，现在 count 小于七，所以无需 sleep 睡眠，继续，然后就把产生的 item 放到缓冲区中，然后把 count 变量加一变成一，下一句，如果 count 是一的话，代表缓冲区开始有数据了，需要通过系统调用唤醒消费者，也就是进程二了。

现在我们来看消费者的代码，那么它首先会判断当前 count 是否是零，若是则睡眠，现在是一，所以直接进入下一行代码，从缓冲区中取出 item，接着把 count 减去一变成零，接下来检查 count 是否是 n 减一，是的话就唤醒生产者，当然 count 是零，直接跳过，最后对取来的数据进行处理，这看起来挺好的。

但是如果我们把 CPU 考虑进来，通常 CPU 的数量远小于进程数量，所以假定这里只有一个 CPU，交替运行两个进程，比如先运行消费者，它首先运行第一行，读取共享变量 count，恰好这时 CPU 切换到生产者进程去了，生产者先产生数据 item，然后 count 不是 n，接着插入 item，然后 count 从零变成一，最后 count 确实是一，所以尝试唤醒消费者，可是这时的消费者并没有在睡眠，是清醒的，自然就忽略了这个信号。

然后 CPU 切换到了消费者进程，既然已经读到了 count 值是零，所以接下来就开始睡眠，CPU 接着又切换到了生产者进程，生产者生产 item，判断 count，插入缓冲区，count 加一变成二，因为 count 从此会越来越大，永远不会是一，所以永远不会唤醒消费者，所以接下来不断循环，直到生产者把缓冲区全部填满，自己也睡眠，现在没有人去唤醒他们，这样两个进程就永远等下去了。那现在介绍一种解法名叫信号量，它是一个整型变量，相当于自然数，它对应有两个操作 down 和 up，是前面的 wake 和 sleep 的一般化，刚才的 wake 和 sleep 是一个进程对另一个进程的，会出现刚才的遗漏现象，而这里的 down 和 up 是进程对共享的信号量的操作。

具体来讲，比如有一个共享变量，进程间只能互斥访问，另外有一个对应的信号量，信号量初始时为一，也就是同。同一时间只允许一个进程读写。假如有一个进程一想要访问，就执行一个 down 操作，这个操作会对信号量减一，信号量也变成零。接着进程二若想访问，也就执行 down 操作，这时的信号量已经是零了，系统就会把该进程睡眠，down 操作也一同被暂停。然后进程三想要访问，执行 down 操作，同样也被睡眠。这时进程一结束读写，执行 up 操作，把信号量加一变成一，共享变量可以访问了。所以由系统随机选择一个睡眠的进程，比如进程三，将其唤醒。进程三的 down 操作继续把信号量减一变成零，可以读写了。

等到进程三结束，up 操作信号量变成一，再由系统唤醒进程二，进程二继续 down 操作，读写变量，结束时 up 操作，信号量恢复成一。现在我们再用信号量来解决生产者和消费者问题，我们一共需要三个信号量，分别是 empty，代表缓冲区中空的个数是七，full 代表满的个数是零，mutex 用来控制进程们的互斥访问是一。然后这是生产者的主要代码，这是消费者的主要代码，都非常简洁。

假如现在只有一个 C P U 轮流运行，先执行生产者进程，生产者先生产数据 item，然后需要插入 item，在插入之前先对 empty 使用 down 操作，使其空的个数减一，接着 mutex 使用 down 操作，代表要读写缓冲区了，在插入之后用 up 对 mutex 操作，结束访问缓冲区，再对 full 信号量 up 操作加一，而消费者的代码刚好把 full 和 empty 的位置换了顺序。刚才我们已经了解掉 mutex 可以保证进程间互斥访问缓冲区，那现在主要来看 full 和 empty 信号量的作用。

假如现在生产者产生很多个 item，把缓冲区填满了，那这时 full 就是七，empty 就是零，接下来当生产者再想要插入时，对 empty 的 down 操作就会让自己睡眠等待，而等消费者取出一个 item 后，就会对 empty 使用 up 操作。
