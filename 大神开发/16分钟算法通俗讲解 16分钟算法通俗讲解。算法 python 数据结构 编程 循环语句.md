对人来说，理解三加四是很容易的，这里三四是数据，加号是算法。但对计算机来说，要理解三加四，就得在 CPU 和内存里搞一大堆电路来实现。因为计算机只知道哪根电线有电，哪根电线没电。如果我们规定电线有电就是一，电线没电就是零，那么把多根电线排成一排，就是二进制最直观的物理表达，这就是计算机最底层的数据。下面再来看算法，算法的本质就是从一种状态转化到另一种状态，也就是说必须有输入和输出。比如这是一个两进一出的算法电路，我们可以先给它通上电，这儿接零伏，这儿接一点五伏，现在这个电路就能工作了。这个算法电路我们既可以把它设计成两根电线都有电时才输出有电，也可以把它设计成两根电线都没电时才输出没电，这就是计算机最底层的算法。对于没有鼓捣过计算机的人来说，习惯上认为数据就是数学里的数值，一二三四五，算法就是数学里的加减乘除。

而那些倒腾过计算机的人不是这么理解数据和算法的，他们理解的数据和算法是更广义的数据和算法，他们把事物的状态叫做数据，从一个状态到另一个状态的变化叫做算法。比如这张照片放在这儿，就是照片的一种状态，把它挪到这儿来，这是照片的另一种状态，那么挪动照片就是算法，而照片的前后两种状态就是两个数据。显然广义上的数据和算法不仅包含了数学中的数据和算法，也包含了像照片这种非数值内的数据和算法。这样一来，数据和算法就可以囊括所有事物以及它们的变化，比如给果树喷农药还是给母猪做产后护理，都可以用数据和算法来描述。上个小节我们说所有的事物以及它们的变化都可以用广义的数据和算法来描述。当我们试图把各种数据和算法搬进计算机时，很多事情都开始变得很奇妙。

我们可以认为数学中的数据和算法是最早被搬进计算机的，我们通过调用封装 CPU 和内存里的电路实现了数学中的数据和算法。计算机数学比人工的数学既高效又精准，它几乎成了计算机的标准配置，它也成了把其他非数值内的数据和算法搬进计算机的基础。也就是说当我们想把非数值内的数据和算法搬进计算机时，我们都不用再去捣鼓 CPU 和内存里的电路，而直接去捣鼓已经实现的数学中的数据和算法就好了。虽然现实世界里的很多事物都是非数值内的，但是要想把它们搬进计算机，都得把它们进行数值化。

比如还是刚才那张照片，它在计算机里是由三百万个像素组成，每个像素的颜色信息和位置信息都是用数值来表示，颜色信息是三个数值，RGB 红绿蓝数值，位置信息是两个数值，因为图片是平面的，X Y 坐标值就能表示位置，也就是非数值内的照片搬进计算机后实际上也是一堆数值。现在如果我们想移动照片，或者放大缩小照片，或者改变照片的颜色，我们一眼就能看出来应该去改变哪些数值，也就是我们要为哪些数值提供算法。很明显算法的设计是基于我们对照片数据的设计，比如当我们的照片是这样一个纯色的长方形时，那么我们的数据结构和算法就没有必要设计的像刚才那么复杂，就可以设计的更加简单。总之我们想要实现的最终功能是数据和算法通力配合的结果，单独强调数据的设计或者单独强调算法的设计都不利于我们想达到的最终功能。

我们学数据结构的时候，算法也是绕不开的重要内容。我们学计算机多数是从学数据结构开始的，同时还有线性代数，这个例子正好也可以帮助我们解释一下我们为什么要学线性代数。这张照片有三百万个像素，每个像素的位置信息是两个数值，如果我们现在想放大或者。缩小照片或者扭曲这张照片，就得集体操作这三百万个位置数值，看似很复杂、很花俏、很艺术的某种扭曲变化，其实背后只要一个简单的数学函数就能搞定。也就是说，我们只需要把每个位置数值带入这个数学函数，结果就是我们想要的效果。而这个简单的数学函数就是线性代数在研究数据、总结数据的过程中得出的共性。线性代数从造型上看，它是把各种物理意义都扔掉之后的纯数值，学习线性代数有点像演员对着空气演戏。

上个小节我们说非数值内的东西搬进计算机后也是一堆数值，比如这张照片，它在计算机里只是一堆数值，计算机用三个数值来表示它的一个像素，这三个数值对我们来说没有明确意义，但这三个数值到了显示器上就会变得有明确意义。显示器是由一个个像素组成的，每个像素又是由三个灯条组成，就是红绿蓝三个灯条。如果我们滴一小小滴水在显示器上，通过这滴水我们就能看到这些灯条，每个灯条不给电的时候不亮，把电给足就是最亮，在不亮与最亮之间可以有二百五十六种供电的级别，灯条就有了二百五十六个级别的亮度，也就是说红色灯条就有了二百五十六个级别的红色，绿色灯条就有了二百五十六个级别的绿色，这样计算机里的三个数值就可以对应到三个灯条的亮度级别，人眼的视觉混合效应，我们就看到了各种不同的颜色。

也就是说当我们看到屏幕上有粉色时，其实没有一个灯条是粉色的，是红绿蓝灯条细微到一定程度后，我们的视觉产生混合效应，让我们看到了粉色。很明显，当我们把照片搬进计算机后，它的主要功能还在，我们可以通过屏幕来欣赏照片，还有可能让更多的人看到。但是当我们把果树、动物搬进计算机后，它的主要功能可能就变了，变成农场游戏了，生产的苹果只能隔着屏幕看，不能吃了。当我们把工厂搬进计算机时，虽然不能生产商品，但它可以帮助我们管理工厂。当我们把南水北调工程搬进计算机时，虽然不能提供水源，但它可以模拟发生各种自然灾害时的状况，预测对生态环境的影响。

数据和算法本来是很普通的词，没那么大扯，但计算机兴起后跑进来一搅和，数据和算法就变得很宽泛，所有的事物都可以从数据和算法的角度来描述，它的概念显然比计算机更大，不是计算机包含了数据和算法，而是数据和算法反过来包含了计算机。当然也不是说所有的非数值内的数据和算法都需要搬进计算机，比如我们网上订餐、网上购物，如果把食物和衣服都搬进了计算机，那就真成游戏了。网上订餐我们只是把信息沟通部分搬进了计算机。这是一台计算机，它没开机的时候是一种状态，它启动完成后是另一种状态，那开机过程就是算法，因为开机前计算机里的所有元件，包括 CPU 和内存里的电路是一种状态，开机后 CPU 和内存里的电路就是另一种状态。按照这种广义的数据和算法，我们任何改变 CPU 和内存里电路状态的行为都是算法。

那么按照这种标准，程序的每一行代码都是一个算法，整个程序也是一个算法，整个程序就是把一行一行的算法整合到一起的算法。既然每行代码都是一个算法，那这一行一行的代码，我们应该先执行哪一行，再执行哪行，哪些行应该跳过，哪些行需要重复，这跟现实生活中的情况是一模一样的。如果今天下雨，我出门就得带伞，不下雨我就不带了。程序面对不同的状况也应该有不同的执行顺序，如果一个程序只能从头到尾一行一行顺序执行，那就完全失去价值了。人们在早期面对 CPU 和内存里的各种电路写代码时，可以说毫不顾忌程序的执行顺序，高兴怎么来就怎么来，想执行哪行就执行哪行。行，想让机器来判断执行哪行，就让机器来判断执行哪行。不想让机器来判断的话，也可以毫无条件的跳转到任何一行，goto语句满天飞。

比如第一行、第二行执行完后，直接goto到第十行，执行完第十行又goto到第五行。这种无条件跳转的基础，事实上是基于程序设计者自己心里明白，也就是说设计者没有把跳转的条件告诉计算机，而是直接告诉计算机应该怎么执行。这样搞的好处就是不给计算机添麻烦，不用让计算机去做条件判断，提升了执行效率。但这样搞的坏处也很明显，其他人想理解这个程序就很费劲，这显然是小作坊的思维，不利于程序的标准化、大型化。后来大家逐渐达成共识，过度滥用跳转，对程序的执行方向没有约束，是很糟糕的状况。后来有两个人从理论上证明了，只需要顺序、条件、循环三种结构，就能把算法需要的各种执行顺序都表达出来。也就是说这三种结构完全可以实现过去的胡乱跳转想要实现的所有功能。

于是那些乱七八糟的跳转，要么被铲除，要么被削弱阉割，结果不仅没有阻碍程序的发展，反而拉开了结构化编程的大幕。经过规范后的程序，人们发现越来越趋向于把一个实际问题分解成解决问题所需要的步骤。我们平常说把大象关进冰箱可以分三步，第一步把冰箱门打开，第二步把大象赶进去，第三步把冰箱门关上。这就是结构化思想，把要解决的实际问题按照人的视角划分成一个一个的步骤，以这些步骤为中心，围绕这些步骤展开操作。而非结构化思想是围绕外人根本看不懂的细节展开操作，比如直接操作一根绳子、一个台阶。在你没有把大象关进冰箱之前，外人根本不知道你想干什么。之前的对象视频说过，用对象的界定方式来理解编程思想，对于初学者来说是最简单、最通俗的方式。一个程序可以自上而下按顺序执行，这是最直观、最自然的执行方式，无论哪种语言都支持这种方式。

而不按顺序的跳转语句，经过大清理大洗牌之后，条件语句和循环语句幸存，几乎所有编程语言都支持这两种结构。这两种结构都是按条件跳转，在Python里条件语句就是if语句，循环语句有while循环和for循环。这一小节我们不谈它们的结构，它们的结构跟我们生活中遇到的同类情况没有区别。这个小节我们主要谈这两种结构跳转的条件。if条件语句跳转的核心是这个条件判断部分，比如现在这个一加三跟四做比较，中间两个等号表示比较，表示判断，不是等于的意思。如果这样我们写等于的话就会报错，因为等于的话这个表达式不会有判断结果。换句话说就是这个表达式必须要有一个判断结果出来，也就是说这个表达式只要能出判断结果，它怎么写都行。比如我们试试把后面的这个去了，条件就是一加三，看看怎么样。不会报错，结果是true，再加二。
