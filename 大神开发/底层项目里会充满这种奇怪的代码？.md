另一方面，如果要相加两个八位数，就无需专门的八位电路，处理器直接使用十六位加法器，将闲置输入位填零即可。处理器一次可处理的比特数就是我们所说的字。在计算领域，字是处理器的原生数据单位，指令集和硬件都针对这种固定大小的数据块作为单一单元进行优化。这就是为什么几乎没有计算机能用常规算术运算直接操作单个比特，因为根本没有专门设计用于单比特运算的电路。编写代码时，我们会频繁执行加减乘除和比较等运算来做出决策。为便于教学，我们称这些为常规运算。常规运算会一次性处理整个字 word，运算结果取决于整个字的数值，而非单个比特的值。若觉得难以理解，请看这个例子。当相加两个十六位数时，结果的第八位值不仅取决于输入数的第八位。零加零显然得零，但结果还受该比特右侧所有位的影响，低位的进位会向上传递。

而位运算虽然仍以字为单位，但每个比特都独立处理。假设有数字十四和四，均以八位字表示，我们对它们进行按位与运算。位运算 and 指令要求中央处理器对两个操作数中相同位置的每对比特执行逻辑 and 运算。正如先前所述，该运算仍然作用于整个字，中央处理器会一次性读取并处理整个八比特数据块。但关键区别在于，输出中每个比特的结果仅取决于输入字中对应位置的两个比特，仅此而已。不存在进位、借位，也不会受相邻比特影响。这正是位运算与常规算术运算的根本区别所在。尽管中央处理器会同时处理整个字，但结果中的每个比特都是独立计算的，仅取决于输入字中的对应比特，绝无其他因素干扰。主要有六种位运算，其名称都非常直观。虽然操作对象是整个字，但其逻辑是作用于单个比特层面而非整体。位与运算会对两个数值中每对对应比特执行逻辑与操作。

位或运算对每对对应比特执行逻辑或操作。位异或运算对每对对应比特执行逻辑异或操作。而位非运算则对单个数值的所有比特取反，实质上是翻转字内的每个比特。此外，还有位运算的子集，位移运算。与位非运算类似，位移运算也针对单个字进行操作，其作用是将字内所有比特向左或向右移动。位移时，一个比特会被移出，同时在另一侧需要补入新比特。新增位的值可以通过几种不同方式确定，可以补零，可以补一，也可以循环利用被挤出的位，这就是循环位移。信不信由你，这些操作的本质就是如此简单。所有编程语言都提供了专属语法来执行这些操作。现在的问题是，我们究竟为何需要这些操作？因为它们能开启各种精妙技巧的大门，在特定场景下极其有用。

假设你正在开发一款拥有数百万用户的应用，现需完成一个简单任务，实现这样一个充满切换开关的设置界面，但要尽可能采用最高效的方式。切换开关天然对应布尔值，每个开关代表启用或禁用状态，因此最直接的存储方式就是真与假。细想之下，在二进制中表示布尔值只需一比特，单个比特正好能存储两种状态，一或零。问题在于内存和存储硬件并不以比特为单位运作，最小的可寻址单位是一字节 byte，即八比特 bit 构成的组。中央处理器 CPU 存取数据时必须提供内存地址，而该地址始终指向完整的一个字节，不存在直接读取第三比特或写入第五比特的指令。内存操作总是以整个字节为单位进行。因此编程语言定义的基本数据类型最小单位为一字节。所以声明布尔变量时，通常会占用整个字节存储，尽管实际只用了一比特，剩余的七比特就被浪费了。

若需存储八个切换开关状态，通常要占用八字节，尽管实际只需要八比特。这看似无关紧要，本例中浪费的五十六比特七字节与千兆字节内存或太字节存储相比微不足道。但对于五千万用户而言，这些微小浪费会累积成超过三百五十兆字节的额外存储空间，这些空间实际上毫无用处。你或许觉得这仍然微不足道，但请记住，这只是单个界面。试想这款应用还可能有多少个带切换开关的配置菜单？若你仍未意识到其重要性，稍后我会在视频中列举另一个例子。现在，作为一名优秀工程师，你被委派解决这个问题。你决定不再用完整布尔值存储每个开关，而是用每位代表一个开关状态，将八个开关状态压缩到一个字节中。此时位运算便能大显身手。为便于理解，我们先定义四个高层操作：置位、清零、翻转和读取。

所有操作都接收一个字和一个数字 n，需要明确的是，字内的比特索引总是从零开始，这意味着最低有效位是第零位，最高有效位是第七位。因此当 n 等于三时，表示的是第四个比特位。选中第 n 位的比特，并将其值设置为一。选中第 n 位的比特，并将其值设置为零。选中第 n 位的比特，并将其值翻转，零变一或一变零。而读取操作会选中第 n 位的比特，并返回其数值作为零或一的整数。下面是设置字节中单个比特值的方法。如前所述，我们无法直接修改字中的单个比特。因此，若要将第三位的比特设为一举例说明，我们需要对整个字进行操作，保持其他比特不变，仅使目标比特变为一。具体该如何实现呢？查看逻辑或运算的真值表可知，只要任意输入为一，输出结果就是一。技巧如下：我们创建第二个字，除了第 n 位为一外，其余全为零。

然后对原始字和这个新值进行按位或运算。这个额外的值被称为掩码。无论第 n 位原本是什么值，结果该位置都会是一，因为掩码在此处为一，其他所有位都保持不变，零或零得零，一或零得一。这样一来，我们就成功设置了字中的单个比特，且不影响其他位。注意，每个比特位置都需要不同的掩码，手动输入会很繁琐。为了将这个流程通用化，我们可以这样做：我们从数字一二进制零零零零零零一开始，然后将其向左移动 n 次。举个例子，如果我们要获取位置 n 等于四的掩码，就向左移动四次，这就是我们要的掩码。通常来说，要设置一个比特位，我们将数字一向左移动 n 个位置，然后将这个掩码与原值进行或运算，这就是 set 函数的实现原理。Clear 函数也采用了类似的思路。

由于我们无法直接修改单个比特位，需要用一个掩码来强制将第 n 位变为零，同时保持其他位不变。逻辑与运算非常适合这个操作，因为只要有一个输入是零，输出结果就是零。所以，如果我们要清除第 n 等于一位，掩码对应位置需要是零，其余位置全为一。在我们对字和掩码进行按位与运算后，掩码中的零会使该位置的输出位强制归零。由于掩码中其余所有位都是一，剩下的位都不会改变。零与任何数相与都是零，而一与一相与则保持一。通用掩码的构建方法是始于数字一，左移至目标位位置，再执行按位取反运算，使所有比特翻转。这样我们就实现了清零函数。现在来看切换函数，将比特从零翻转为一，或从一翻转为零。此时异或运算是最佳选择。异或通常被解释为二者取其一，但不同时存在。

但就当前需求而言，我们可以这样理解：当第二个输入位为一时，输出结果就是第一个输入位的反转值；当第二个输入位为零时，输出与第一个输入位相同。因此我们需要的掩码仅在位置 n 处为一，这样该位置的比特位会被翻转，而其他所有比特位保持不变。所以我们从数字一开始，将其左移 n 位，得到掩码后，与原字进行异或运算。这就是我们如何在字中切换单个比特位的方法。最后是读取函数，这里我们的目标。表示提取单个比特位的值零或一，并返回可作为普通运算使用的整数值。在这个例子中，我们读取第七比特位，因此应返回一。若 n 为六，则返回零。若 n 为四，则返回一，以此类推。因此这个函数会返回零或一。为此我们需要将目标比特的值存入输出字的最低位中。所以第一步是将字右移 n 位。但移位后，数值左侧可能仍存在值为一的其他比特位，导致返回值非零非一。

需要通过位与运算使用数字一作为掩码，清除这些干扰位。由于位与运算在任意输入为零时，输出零除最低位外的所有比特都会被清零，而目标比特保持原值。读取比特的完整操作是将字右移 n 位后与掩码一进行位与运算，即可获得表示比特值的常规整数。这四个基础函数就足以实现字的内部单比特读写操作。这种将多个值压缩存储在一个字节中的技术称为比特打包。这样我们就解决了先前描述的问题。如我之前提到的，这可能看起来有点夸张。在大多数情况下，你只需使用编程语言提供的数据类型，仅在真正需要时才考虑位打包技术。这种方法主要在内存或存储空间极其有限时才会成为必要选择。例如在嵌入式系统领域，假设你正在使用一个传感器，它每秒报告四种可能的湿度等级，而你需要编程让微控制器连续记录这些读数整整一年。但可用的板载存储空间极小，仅有十兆字节。
