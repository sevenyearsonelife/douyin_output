npm 是 Node 包管理器，它改变了开发者共享和构建 JavaScript 应用的方式。它是随 Node.js 捆绑的默认包管理器，自 2010 年以来一直是 JavaScript 生态系统的支柱。如果你正在用 JavaScript 或 TypeScript 构建 Web 应用或 API，你很可能就在使用 npm。它拥有所有包管理器中最大的包注册中心，包含超过二百万个包。你几乎可以为任何事情找到一个库。命令非常简单：用 npm install 获取包，npm run 执行脚本，npm update 保持更新。它简单直接，文档完善，而且每个 JavaScript 的教程都假设你在使用它。现在问题来了，npm 的 node_modules 文件夹可能会变得异常庞大，因为它处理依赖的方式。

而且它不再是最快的选择了，但它成熟稳定。如果你刚开始学习 JavaScript，npm 是你应该开始的地方。Yarn。说到速度，Facebook 在 2016 年创建了 Yarn，正是为了解决这个问题。Yarn 的卖点是更快的安装、更好的安全性和更可靠的依赖解析。命令几乎相同，用 yarn add 代替 npm install，用 yarn run 来运行项目。切换起来很容易。Yarn 在 npm 之前引入了锁文件，确保你在不同机器上获得一致的安装结果。它有离线缓存，所以你以前安装过的包不需要再次下载。如果你克隆了一个带有 yarn.lock 文件的项目，请使用 yarn 而不是 npm，混合使用会导致奇怪的问题。不过如今 Yarn 和 npm 的性能非常接近，所以请使用你的项目已经使用的那个。

pnpm，p 代表高性能，而且它极其节省空间。npm 和 yarn 会为每个项目复制包，而 pnpm 在你的机器上只存储每个包版本的一个副本，并使用硬链接来共享它们。安装一次 React 到处使用，这使得 pnpm 速度极快且节省空间。像 Microsoft 和 TikTok 这样的公司都在使用它，尤其是在 monorepo 中。如果磁盘空间紧张或者你管理着大量项目，pnpm 确实值得考虑。Bun，现在来点不一样的。Bun 不仅仅是一个包管理器，它是一个完整的 JavaScript 运行时，旨在追求速度。我们说的是比 npm 快十到二十倍的安装速度。

命令是一样的，bun install，bun add，但 Bun 也替代 Node.js 作为运行时，内置了测试运行器，并且无需 Webpack 或 Vite 即可打包你的代码。Bun 于 2022 年推出，所以它不像 npm 或 Yarn 那样久经考验，但其速度确实令人印象深刻。如果你正在开始一个新项目，Bun 值得一看。pip，pip 是 Python 的标准包管理器。如果你在写 Python，你就在用它。它与 PyPI 协同工作，PyPI 拥有超过五十万个包。命令非常直观，pip install 用于添加包，pip install -r requirements.txt 用于从文件安装所有依赖。这是 Python 项目共享依赖的标准方式。需要知道的一点是，pip 默认是全局安装，这可能会导致冲突。

这就是为什么你会在虚拟环境 venv 中使用 pip。它能保持项目隔离，为你省去很多麻烦。现在，如果你从事数据科学，你可能听说过，它是一个包和环境管理器，在科学计算领域非常流行。Python，它可以安装 R、C 库和二进制依赖。这对需要 NumPy、Pandas、TensorFlow 和其他具有复杂依赖关系的重量级库。的数据科学家来说至关重要。当你进行机器学习或科学计算时，它是首选。它处理安装像 TensorFlow 这样的东西比 pip 好得多。对于简单的 Python 项目坚持使用 pip，对于数据科学，它是值得的。Cargo，Cargo 是 Rust 内置的包管理器。老实说，它是最好的之一。它处理一切，构建、测试、文档和依赖。如果你写 Rust，你就得用 Cargo，没得商量。

cargo build 编译，cargo test 运行测试，cargo run 构建并执行，一切统一且开箱即用。Rust 包注册中心，crates.io 拥有超过十万个名为 crates 的包。社区对质量要求严格，因此 crates 能很好的协同工作。如果你正在学习 Rust，你很快就会体会到 Cargo 有多好用。Go modules，Go 走了一条不同的路。多年来，Go 没有官方的包管理器，但从 Go 1.1 开始，Go modules 已成为内置在工具链中的标准。它的设计很简单，比如用 go get 下载依赖，go mod tidy 用于清理未使用的依赖。很酷的是它如何使用语义导入版本控制来处理版本，避免了其他语言所遭受的依赖地狱。Go modules 轻量、快速，而且老实说，以最好的方式显得相当无聊。

它能工作，不碍事，让你专注于编写代码。Maven 自 2004 年以来一直是标准的构建和依赖管理工具，在企业 Java 开发中无处不在。Maven 使用名为 pom.xml 的 XML 配置文件，你可以在其中声明依赖。像 mvn install 和 mvn package 这样的命令是你日常会用到的。Maven 通过强制执行标准的项目布局来带来结构，这在大型团队中非常有价值。但这里有个权衡，XML 配置很快会变得冗长，而且 Maven 在大型项目上可能很慢。但它成熟，文档完善，工具和生态系统非常庞大。Gradle，如果 Maven 的 XML 让你抓狂，Gradle 是更灵活的替代方案。它适用于 Java 和 JVM 语言，如 Kotlin，但使用 Groovy 或 Kotlin DSL 代替 XML。

得益于增量构建，Gradle 比 Maven 更快。它只重建更改的部分，节省了大量时间。配置更具可读性，并且它是 Android 开发的官方构建工具。如果你正在开始一个新项目并希望获得灵活性和性能，请使用 Gradle。如果你加入一个现有的 Maven 项目，除非有非常充分的理由，否则不要迁移。两者都工作的很好。面向 PHP 开发者的 Composer，Composer 是 PHP 的包管理器。它于 2012 年推出，彻底改变了 PHP 的依赖管理。你会用它来开发 Laravel、Symfony、WordPress 插件，基本上是任何现代 PHP 开发。命令也相当简单。composer install 用于设置依赖，composer require 用于添加新依赖。

Composer 的强大之处在于自动加载，它会生成一个自动加载器，这样你就不必手动包含文件。PHP 生态系统已经围绕 Composer 真正成熟起来。如果你正在学习 PHP，Composer 是必不可少的。Homebrew，最后让我们谈谈 Homebrew，这个不同，因为它不是针对特定编程语言的。它是适用于 macOS 和 Linux 的系统包管理器。如果你是 Mac 开发者，你肯定在用它。Homebrew 安装命令行工具、应用程序、语言、数据库，基本上是你开发所需的一切。需要安装 Python？brew install Python。想要 PostgreSQL？brew install PostgreSQL。它能处理一切，命令很简单，对于包是 brew install，对于。

多益应用程序是 brew install cats，brew upgrade 保持一切更新。它非常简单，而且就是能用。Homebrew 的核心价值在于它如何管理依赖并保持你的系统整洁。它将所有内容安装在自己的目录中，并在需要时创建符号链接，因此不会与系统文件冲突。
