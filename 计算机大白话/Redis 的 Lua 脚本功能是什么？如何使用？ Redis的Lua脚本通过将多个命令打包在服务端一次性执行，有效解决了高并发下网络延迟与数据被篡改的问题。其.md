Redis 的 Lua 脚本到底是什么？简单来说，它是一种让你把多个 Redis 命令打包在一起，直接送到 Redis 服务器内部去一次性执行的机制。平时我们操作 Redis 都是客户端发一条命令，服务器回一个结果，再来回好几次。但如果遇到需要连贯完成的复杂动作，这种一来一回不仅网络延迟高，还容易在中间被别人插队改乱数据。Lua 脚本就是为了解决这个问题而生的。那它具体是怎么做到执行时不被打断的？我们在代码里到底该怎么把指令传给它？又在什么情况下用它反而会拖垮整个系统？今天我们把这几个问题一次性讲透。要理解它为什么不被打断，得先知道 Redis 的一个核心脾气，它是单线程处理命令的。你可以把 Redis 想象成一个只有一个窗口的办事大厅。

如果你用普通命令，就像分三次去窗口办业务，每次办完你都得重新排队，这期间别人可能插队把数据改了。但 Lua 脚本就像是你把三份表格装进一个密封袋，一次性递给窗口，办事员只要拆开这个袋子，就会一口气把里面的事全办完，中间绝对不会停下来去接待别人。这就保证了操作的原子性，也就是要么全做完，要么全不做，数据绝对不会在中间状态被污染。那在实际开发中，怎么把这个密封袋递过去呢？最常用的方法是使用 E V O 命令。这个命令的结构就像填快递单，分为四个部分。第一部分是脚本内容本身，也就是你要执行的具体逻辑。第二部分是数字，告诉系统你这次用到了几个 Redis 的键。第三部分就是具体的键名，最后一部分是附加参数。

举个真实的场景，比如电商秒杀扣减库存，你可以写一段 Lua 脚本，先检查库存键的值够不够，如果够就减去对应的数量并返回成功，如果不够直接返回失败。把这段逻辑通过 E V O 命令发过去，Redis 就会在服务端瞬间完成判断和扣减，彻底杜绝了超卖的问题。不过如果你的脚本逻辑很长，每次执行都把整段代码通过网络发一遍，会非常浪费带宽。这时候就可以用它的进阶玩法 E A O S H A 命令。你可以先把脚本发给 Redis 让它存起来，Redis 会计算出一串唯一的哈希值，也就是这段脚本的取件码。之后你再想执行同样的逻辑，只需要用 E A O S H A 加上这串取件码，Redis 就会直接从缓存里把脚本拿出来跑。这样网络传输的内容从几百行代码变成了一小串字符，性能会大幅提升。

但 Lua 脚本并不是万能的，它有一个非常致命的边界，绝对不能写得太复杂，更不能有死循环。前面说过 Redis 是单线程的，窗口只有一个。如果你的 Lua 脚本里包含了大量的循环计算，或者执行时间太长，这个窗口就会被你一个人长时间霸占。在这期间整个 Redis 服务器会完全卡住，其他所有客户端发来的简单查询命令全都在外面排队干等。所以 Lua 脚本只适合做那些逻辑清晰、步骤紧凑的原子操作，千万不要把它当成写复杂业务逻辑的地方。Redis 的 Lua 脚本本质上是服务端的一管胶水，它把零散的命令粘合在一起，用最小的网络代价换来了最严格的数据一致性。理解了它的单线程执行原理和阻塞边界，你就能在秒杀、分布式锁这些高并发场景里，用它写出既安全又高效的代码。
