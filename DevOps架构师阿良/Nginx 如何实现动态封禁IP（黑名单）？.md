Nginx 限制 IP 黑名单，之前都是在配置文件使用 deny 段，现在我们单位的平台呢新增一个 Nginx 黑名单功能，用 deny 段就不方便了，我们决定采用 Lua 加 Redis。当 Nginx 收到请求，先检查 Redis 是否该客户端 IP 被封禁，如果封禁则拒绝访问，来看看具体如何来实现。我这里使用的是 OpenResty，它是基于 Nginx 封装，集成了 Lua 的非常强大的功能。嗯，当然你也可以基于原生的 Nginx 啊去增加 Lua 这个模块进去实现。

在 OpenResty 目录下面创建了一个 Lua 目录，在这个 Lua 目录里写了一个 Lua 脚本，打开这个 Lua 脚本来看一下，这这个脚本不是很复杂，第一行是导入 Redis 客户端库，这一行是创建 Redis 客户端实例，指定 Redis IP 和端口用于去连接它，并将连接成功和错误分别赋予 ok 和 error 这两个变量。如果 ok 不为真，就说明连接失败，记录日志到 Nginx 的错误日志里面来，否则就说明它连接成功。

当连接成功之后，先通过 Nginx 的内置变量 remote address 来获取客户端 IP，并赋予 client ip 这个变量，接着调用 Redis 从中啊去 get 一个 key，bind 冒号后面跟客户端 IP，这个呢就是我们手动要去向 Redis 里面去设置的一个 key，或者通过程序进去设置。如果 error 这个变量为真的话，就说明连接 Redis 失败了，有错误返回，然后就记录一条日志到 Nginx 错误日志里面。呃，如果 is bind 呢为真，就说明从 Redis 中获取到了这个 key，然后将 IP 被封禁的提示记录到 Nginx 的日志里面，并返回 HTTP 访问拒绝。好，这么一个简单的脚本就实现了从 Redis 中检查客户端 IP 是否被封禁，如果被封禁就拒绝访问。

打开 Nginx 的配置文件来看一下，虚拟主机这里增加一个 access by lua file 来去指定 Lua 脚本，就说明这个 Lua 脚本呢会在这个虚拟主机中进行去生效，所有访问该虚拟主机的 HTTP 请求都会被这个 Lua 脚本呢给拦截并处理。这是指定它的一个绝对路径，在 Nginx 的配置文件来指定好之后，最后一步呢就是进行对它做一个测试，看看是不是达到我们脚本的预期。现在浏览器访问是 OpenResty，这里是它的访问的首页，这访问是没问题的，现在是可以正常的访问我们这个 Nginx 的服务器是没问题的。现在操作 Redis，我将我本地电脑的 IP 在 Redis 里面设置它的 key，也就表明将它给封禁，再来访问一下看看。

redis-cli set bind 冒号幺九二点幺六八点一点四，然后值设置为 true，这个是一个固定的格式，这个格式啊你可以自己去定义，就完全取决于你 Lua 脚本里边它获取 key 的那个固定格式。这么设置完成之后，就说明啊一点四的这个 IP 呢被封禁，我们在浏览器访问一下，就会发现出现四零四的拒绝，这说明我们的 Lua 脚本已经生效了，刷新刷新都是拒绝的，那如果你要想把这个 IP 呢再进行去。解封，delete，然后再加热k，将它删除掉就可以了。然后浏览器再访问，啊，可以看到就可以再正常的进行去访问。看到了，我们主要是使用redis来存储被封禁的ip，因为redis呢可以被很多层已经去调用，所以在前端dev的平台直接向redis里面呢去写k，呃，或者去删除k，来实现动态封禁ip的这样一个目的。

nginx呢可以结合lua实现很多实用的功能，例如动态负载均衡、灰度发布等等。如果你们公司在重度的使用nginx，建议啊都去学一下这个lua，来去增强nginx的功能。
