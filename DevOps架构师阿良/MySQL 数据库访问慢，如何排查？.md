MySQL数据库访问慢如何排查？第一步先检查服务器性能有没有存在瓶颈，如果系统资源使用率比较高，例如 CPU、硬盘，那访问肯定会慢。如果你发现是 MySQL 进程占用 CPU 比较高，说明 MySQL 读写频率高。如果你们的网站访问量不大，那可能是 MySQL 参数、SQL 语句查询慢等方面的问题。像 MySQL 参数方面影响，你可以尝试去调整缓存池大小、查询缓存大小、最大连接数来看看。如果还没有解决，再重点排查一下 SQL 语句这一块。SQL 方面问题主要去查看执行慢的 SQL，也被称为慢查询。可以在 MySQL 命令行这里执行 show processlist 查看当前的活动链接，这里就会给你呈现出谁正在执行 SQL，这个 SQL 执行了多长时间。

如果在时间这一列超出三秒、五秒，说明这个 SQL 执行比较慢。这样 SQL 就要去重点去关注，进行对它优化和排查。怎么排查呢？待会我们来继续看一下。这里查看的是活动的，那也就意味着嗯你去查看的时候，可能那个慢 SQL 已经执行结束了，你就很容易就错过。为了实时的进行去记录这些慢查询的语句，MySQL 也提供了一个慢查询记录功能，可以将执行超过一定阈值的 SQL 写到日志里面，避免错过执行慢的 SQL，啊方便你后续进行去分析。怎么来去查看有没有启用这个慢查询功能呢？可以通过这个指令 show variable like 查看关于 query 相关变量的配置。在这里面的输出里边就有慢查询相关的几个参数，像这一个就是用于设置慢查询记录的阈值，单位是秒，默认是十秒。这个参数就是用于决定是否启用慢查询记录。

在下面这个将慢查询 SQL 记录到哪个日志中。好，可以看到默认情况下慢查询是没有被启用的。我们可以通过这个指令来去启用慢查询记录。启用后我们再打开一个终端，在这个终端里面还是连接到 MySQL 数据库，在这里执行一个 SQL 语句，这个 SQL 语句呢是查询 user 这个表，id 等于一，并且 sleep 休眠六十秒，来去模拟一条执行慢的 SQL。执行。我们这里呢可以通过 show processlist 来查看一下，这里呢你就能看到现在正在休眠的 SQL，在时间这一列啊你可以多次执行来查看它当前执行时间。这个 SQL 呢就会被记录到慢查询日志中，因为它会超出默认的十秒。如果你也想把它的阈值调低一点，你可以通过设置这个参数，比如设置三秒、五秒，那么超出三秒或者五秒的 SQL 都会被记录到这个日志里面来。

现在查看慢查询日志，就可以看到这个 SQL 呢就已经被记录上了。那么只要超出阈值的都会记录到这个文件中，方便你后期进行去分析。如果这个文件里面的内容比较多的话，也就是慢查询 SQL 比较多，你还可以通过一个叫 mysqldump slow 这个工具来对慢查询日志啊做分析，它是 MySQL 官方。提供的专门用于分析慢查询日志的工具，可以对这里面的日志提取出比如访问最高的 SQL，查询最慢的 SQL 都可以通过这个工具啊进行分析出来。当你分析出哪些 SQL 造成网站访问慢，那你可以对这些 SQL 进一步再做分析，可以通过 EXPLAIN 这个指令对 SQL 语句去跟踪它的执行任务，嗯包括用了哪些索引，查询顺序是怎么样的，可以分析出它的问题。

根据 SQL 具体的这种问题，嗯如果没有走索引就建索引，嗯如果是多表查询尽量的做做优化或者减少。如果服务器硬件没问题，MySQL 参数呢也要调整，SQL 语句呢也有优化，还是没有解决，那你要考虑一下你们的数据量是不是大。如果每次查询的数据量呢都比较大，它查询的时间肯定要慢，对于用户而言，他拿到的数据慢，网站访问也就慢了。那这种情况呢你就要考虑到分库分表，读写分离，来去扩展数据库的整体性能。后面呢我们再具体讲一下这一块，感谢你的观看。
