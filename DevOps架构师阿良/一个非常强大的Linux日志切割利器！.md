小心 Nginx 的日志把你的硬盘给撑爆了，血淋淋的教训。这里给大家推荐一个非常好用的日志切割工具 logrotate。Logrotate 在主流的 Linux 发行版上就已经安装了，例如像 Ubuntu、CentOS 直接就可以去用，非常方便。我这里使用的是 CentOS，logrotate 的配置文件目录是在 /etc/logrotate.d 这个目录下。你可以在这个目录下以服务命名编写日志切割配置文件。这里啊以 Nginx 为例，带着大家看看如何去编写这个配置文件。打开 Nginx 的这个配置文件，第一行指定切割日志的文件路径，这里可以写通配符。像这里呢，匹配的就是 /var/log/nginx 下面所有以 .log 为后缀的日志文件都会进行去切割。

这里使用一个括号来包围着，在里面呢有多个参数，我们看看这些参数有什么作用。第一个参数是指转换后的新日志文件的权限。第二个日志每天轮换一次，以天为单位。第三个参数用来指定保留日志文件的数量，这里十就代表会保留十个归档文件。第四个参数，如果你的日志文件缺少，它就会忽略这个配置。第五个参数，如果你的日志文件为空，它就不进行轮转。第六参数将旧的文件进去压缩来节省磁盘空间占用，默认是 gzip。第七个参数就日志轮转之后，下一个轮转周期才会压缩日志。第八个参数是指当你处理的是包含多个日志文件时，只执行下面一次这里面的脚本。下面这个参数就非常关键了，它在这里面呢是写具体的 shell 脚本。当 logrotate 切割完日志文件之后，你执行什么样的命令来去确保新的日志文件能够被现在这个服务继续使用。

这里是让 Nginx 发送一个 USR1 信号，啊以便 Nginx 呢能够重新打开日志文件句柄，来确保它使用新的日志文件。如果你不发送信号的话，有可能新的日志文件这个服务就不会再向里面去写日志。简而言之，这个配置是每天轮转一次 Nginx 的日志文件，并将切割后的日志文件进行压缩，压缩文件保留是十个。这样一来，logrotate 每天就会自动轮换 Nginx 的日志，无需再人工干预去做这样的事情。当你编辑好这配置文件保存，那该配置文件就已经生效了，因为 logrotate 呢它会扫描这下面的配置文件来去执行。那如果你们服务器呢运行有多个应用，日志增长快，强烈的建议大家使用 logrotate 来管理服务器日志，非常的方便。
