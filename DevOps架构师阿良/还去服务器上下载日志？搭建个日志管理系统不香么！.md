E L K赶紧用起来吧，收集 Linux 系统上的应用日志是真的很方便。E L K 是一组技术栈的首字母，由三个核心组件组成。Elasticsearch 简称 E，用于存储、搜索和分析日志数据。Logstash 简称 L，用于收集各种来源的日志数据，并将其进行预处理和可视化，然后发送到 Elasticsearch。Kibana 简称 K，用于查询、分析和可视化存储在 Elasticsearch 中的日志数据。在早期啊，Logstash 它承担着日志采集和数据处理管道的角色。后来官方呢，它将这个日志采集的角色独立成了一个单独的组件，名称叫 Filebeat，更加的轻量级，占用资源小。

这是一台 Docker 主机，为 E L K 先创建一个 Docker 网络，然后再创建 Elasticsearch 的容器，先把它这个数据库给启动起来。Elasticsearch 已经运行起来了，它对外暴露是九二零零端口，可以通过访问九二零零端口它的 API 来查看一下 Elasticsearch 的健康状态，通过 c u l。访问一下九二零零，然后 cat health。好，可以看到现在的状态呢都是正常的。紧接着再使用 Docker 创建一个 Kibana 的容器。在创建容器的选项里面，通过指定一个 Elasticsearch host 变量来指向 Elasticsearch 容器内部的访问地址，并指定它是中文语言，对外暴露是五六零一。

容器已经运行，打开浏览器输入 Docker 主机的 IP 和五六零一端口，将将看到 Kibana 的欢迎页面。在这里呢选择自己浏览，这就到了它的主页，在主页这里呢有给予一些功能相关的介绍，大概的看一下，在左侧这里有它的支持的一系列功能。在菜单最下面的 Stack Management 在这里，点击索引管理，在这里啊可以看到 Elasticsearch 中的数据库及相关数据，那可以通过视图将 Elasticsearch 的数据呢进行可视化的展示和管理。先到这里，下一个视频再带着大家看看如何使用 E L K 将我们网站的日志给收集起来，并且可视化的管理、查询、搜索等等相关的功能。我们已经将 E L K 给搭建起来了，现在将一台 Linux 服务器上的 Nginx 的访问日志给收集起来，实现集中可视化管理。
