面试官问你说一下 Redis 持久化机制是什么？你这么回答给满分。Redis 提供了两种持久化机制，RDB 和 AOF，默认是 RDB。来一起看看它们工作机制和优缺点。先来看一下 RDB，RDB 持久化呢，它是 Redis 在某个时间点上进行数据快照来实现。这个数据快照它是一个压缩的二进制文件，通常命名啊就以 dump 点 db。这个数据快照操作触发分为自动触发和手动触发。自动触发它是根据 Redis 配置文件中涉及的触发条件。来我们看看它的默认的触发条件是怎么样的。这是 Redis 的配置文件，找到 save。好，这里就是关于它自动触发的触发条件。第一个是在九百秒内如果有至少一次写操作，则会触发快照。第二个是在三百秒内如果有至少十次写操作，则会触发快照。这个呢就是一万次写操作就会触发快照。

有没有想过这里为啥是三个配置呢？其实这是 Redis 它为了确保在不同的负载情况下能够实时的将数据保存到磁盘，来平衡数据的安全性和性能之间的一个关系。这是自动触发，手动触发是通过执行 save 或者 bgsave 命令来完成的。bgsave 命令它是无阻塞的，是异步执行，相比于 save 命令这种阻塞的更高效。那当你触发这个条件满足的时候，比如说就 Redis 的配置文件里它触发了，或者是你手动执行了，那 Redis 它主进程就会生成一个子进程来负责这个快照的工作。子进程它就会遍历 Redis 中存储的这些数据，将数据呢写入到临时文件。快照完成之后，临时文件呢就会替换原有的就是 RDB 文件，来完成本次的数据快照。这是 RDB 的工作流程，再来看一下 AOF 的工作流程。

AOF 持久化它是通过记录 Redis 接收到了每一个写操作命令然后来实现的。你例如你通过 set 指令你设置的一条数据，那这个命令呢它就会以纯文本的形式追加到 AOF 文件中。那 Redis 在启动时就会通过重新来执行这些命令来恢复这个数据。将命令追加到文件也是有策略的，有三种。呃，第一种是 always，就是每次你写操作呢都会同步到磁盘。第二种呢是 everysec，是每秒都会同步一次，这是默认的配置。还有一个呢是 no，就是由操作系统来决定这个同步的一个时间。看一下 Redis 的 AOF 持久化相关的配置，搜索一下 append。然后在这里呢可以看到它默认是关闭了 AOF 持久化这个机制，它写入的文件呢默认就是这个文件。向下拉，在这里呢可以看到它同步的策略为 everysec，就是每秒就会同步一次。

最后做个小结，RDB 它采用的是快照方式，非实时的持久化，有一定数据丢失的风险。而 AOF 呢它是一种追加式的记录方式，实时性高，能够最大限度的减少了数据丢失的风险。在实际应用中，你可以根据具体的需求选择使用一种，或者说你两种都用啊都是可以的。那如果你两种一块用的话，就会带来更多资源开销，当然它的这种安全系数呢也是更高。那话说你们公司用了哪一种持久化方式呢？
