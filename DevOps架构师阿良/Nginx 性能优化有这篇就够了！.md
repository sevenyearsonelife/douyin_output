搭建完 Nginx 服务器之后，强烈建议大家一定要做这些优化，能大幅度提高性能。总共有七处，一个一个给大家解析。这是 Nginx 配置文件，我们要优化的第一处就是调整工作进程数，这个对 Nginx 的性能有重要的影响，通常是设置为 auto 或者指定本机 CPU 数量，以能够更好的发挥服务器的性能。如果这里呢你设置的是具体的数字，那么 Nginx 呢它只会使用指定数量的 CPU 核心，是无法将所有的 CPU 同一时间都能用得到，所以就不能发挥服务器的最大的性能。第二处增加工作进程的连接数，可以为每个工作进程放大它能处理的连接数，也就是同一时间啊能够处理的最大连接数，默认是幺零二四，这个有点小，你可以后面再加个零来提高它的并发能力。第三处开启高效的传输模式，也就是这三个参数，我们分别来看一下它们的作用啊。

第一个参数 sendfile，当你启用这个参数之后呢，Nginx 就直接会将文件从磁盘发送到 socket 的缓冲区，而不是是先将数据从内核缓冲区再拷贝到用户缓冲区，再从用户缓冲区再拷贝到 socket 的缓冲区。那这样一来的话，它就减少了这种拷贝的次数，从而提高传输效率，特别是在处理大量这种静态文件，例如像图片啊、CSS、JS 文件这种时候，效果呢更为显著。第二个参数 tcp_nopush，当你启用这个参数，如果 Nginx 有更多的数据发送时，它将会推迟发送这个数据包，直到累计足够的数据再会发送。那这样的好处呢是可以减少 TCP 包的一个数量，从而来降低网络传输的开销，提高吞吐量。

第三个参数 tcp_nodelay，当你启用了这个参数之后，Nginx 它就会禁用一个叫 Nagle 的算法，而这个 Nagle 算法呢它是用于减少这网络拥塞的一种算法，它主要是通过将小的数据包进行去缓冲，然后等待更多数据包或者到达一定时间再一起发送，来减少网络中的这个小数据包的一个数量。那当你需要立即发送小数据包时，特别是一些像实时消息啊、交互式应用，那你可以禁用这个 Nagle 算法来降低这个延迟，提高响应速度，也就是将这个参数给启用。第四处复用链接，也就是 keepalive timeout 这个参数，那大家都知道 HTTP 呢它是一个无状态协议，在默认情况下呢客户端向服务端发送一个请求后，服务端呢响应完毕就会断开这个链接。

那如果客户端它要发送多个请求呢，那每个请求呢它其实都是要建立一个独自的链接来传输数据，这样就会导致服务器与客户端呢会产生大量的链接和断开的这种操作，从而来增增加服务器的性能开销。我们通过设置这个 keepalive timeout 参数，可以告知让 Nginx 在处理完一个请求之后，先保持一下这个链接，啊以便来再次的接收客户端发送的后续的请求，从而就减少了这种频繁的建立链接和断开链接所带来的性能消耗。第五处启用 gzip 压缩，当你启用了 gzip 压缩后，Nginx 它会先将指定的资源，例如像 HTML、JS、CSS，它先在本地压缩一下，再响应给客户端。这样的好处呢就是会减少这个传输数据量，因为它压缩了嘛，传输的文件就变小了，所以它能减少这个带宽和传输中的一个速度。

但是啊它也会增加 CPU 资源的开销，因为它会有一个压缩的一个过程。第六处。设置浏览器缓存，也就使用这个 add paris 参数。这个参数是用于去告知浏览器缓存静态资源的过期时间。嗯，假设设置是三十天，那么浏览器访问这个网页之后，它将的一些图片啊、CSS、JS 会缓存到本地。下一次如果再有相同请求的资源，它就直接从这个本地的缓存中获取，就不会再向服务器发送请求了。那这样的好处就是能够大幅度的降低服务器的带宽，提高访问速度。但是你需要注意的就是，如果你服务器的静态资源更新了，比如说有个图片更新了，那有可能浏览器还是查看的是你之前的图片，因为它是还是用的本地的缓存嘛，所以你需要知道它会带来的影响。也就是说你的网站有很多静态资源，而且这些静态资源呢会频繁的更新，是不太适合使用 add paris 的。

如果不经常更新，可能几个月更新一次，使用这个呢将很好的能提高这个访问速度。第七步，启用代理缓存。假设你使用 nginx 作为这种反向代理的时候，你可以配置缓存来将后端服务器的响应缓存到本地，以便后面如果来同样的请求时，直接从这个本地的缓存中获取，就不用再向后端服务器发送请求了，从而就减少了服务器和数据库的一个负载，来提高用户访问速度。代理缓存呢通常有两种类型的配置，一种呢是 proxy cache，另外一种呢是 fastcgi cache。比较常见的就是这个 proxy cache，它适用于任何的 HTTP 这个服务。像 fastcgi cache 呢，它主要是代理的是那种 fastcgi 的应用，例如啊像 PHP 啊，我们这里呢是以这个 proxy cache 来为主来看一下如何来启用这个代理缓存。
