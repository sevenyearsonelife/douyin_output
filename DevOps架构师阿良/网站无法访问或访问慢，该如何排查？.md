我用这个方法解决过十多个网站无法访问或访问慢的问题，现在分享给大家。网站无法访问可能有多种因素引起的，例如网络故障、服务器故障。接下来我将从用户端到服务端的链路告诉大家该如何排查。请看上图，首先你要搞清楚问题的现象是个别用户无法访问，还是部分用户无法访问网站，还是所有的用户都无法访问网站。每种情况的处理思路是不同的，分别来看一下。第一种情况，个别用户无法访问，大部分的原因都是由于用户本地网络出现了问题，例如他的网络故障，他的 DNS 服务器配置不正确，他的系统有问题，都可能导致他无法访问我们的网站，这需要进入他的电脑进去查看，你可以让他用手机访问一下试试，来去告知你的电脑出现了问题。第二种情况，部分用户无法访问，要看是不是都来自于同一地理位置，如果是说明这个地区到机房的网络出现了问题。

找三五个用户啊在本地 tracert 命令执行一下，跟踪数据包从源到目标的路径，看看是不是都是没问题的，还是在哪里就中断了，并将这个信息提供给机房的运营商。啊，如果不是来自于同一地理位置，那很有可能是我们后端某台服务器故障了，啊，负载均衡转发这台服务器响应慢或者失败，那这时可以在负载均衡器使用 shell 脚本模拟请求来访问后端的服务器来确定，判断它转发的所有的后端服务器是不是都是正常响应的，有没有超时或者无法响应的，或者你逐步对每一台后端的 web 服务器进去查看。第三种情况，所有用户无法访问，那原因基本上是在服务端出现了问题，也就是我们维护的这些服务器肯定是有问题的，那这种原因就比较多了。

首先重点查看负载均衡器和数据库是不是正常的，因为这两者如果出现了问题，它将直接造成网站无法提供服务，然后再查看 web 服务器或其他第三方服务涉及到一些接口啊，其他的是不是正常提供服务。如果上述都没问题，这时你需要回想一下在发生故障之前有没有修改过防火墙规则、配置变更、应用升级等等这些操作，大部分的故障都是由某种操作引起的，所以你要回忆故障之前有没有操作什么，其他同事有没有操作什么。好，以上就是网站无法访问大致的排查思路，通过这个思路我相信你能够快速定位到问题，那更重要的是你要具备完整的监控系统，当用户端到服务端整个链路全部监控起来，具体怎么监控，监控哪些指标，请看我之前的视频。好，感谢你的观看，下次再见。
