Nginx 七大应用场景，看看你用过几个。场景一，Web 服务器，这是一个最常见的使用方法，就是将 Nginx 作为一台 Web 服务器来提供网站服务。配置也非常简单，只需要在 location 块中通过 root 指令来指定网站根目录即可。呃，如果配置 HTTPS，只需要监听那里启用四四三端口，并配置 SSL 这两个参数，指定证书和私钥就可以了。应用场景二，反向代理。使用反向代理呢也是常见的一种使用方法，就是 Nginx 呢作为网站的访问入口，用户先访问 Nginx，Nginx 再将请求转发到后端，然后再响应给用户。一般使用这样的一个目的就是为了去隐藏后端真实服务器，来统一的对外暴露访问，提高后端服务器的安全性。

那配置反向代理也很简单，只需要在 location 块中通过 proxy_pass 指令来指定后端访问地址就可以了。应用场景三，负载均衡。负载均衡就是把 Nginx 当做一个负载均衡器，用户访问 Nginx，Nginx 再将请求转发到后端的多台服务器上，嗯，来提高 Web 服务器它的高可用和并发能力。啊，那 Nginx 呢是通过 upstream 指令来定义后端多台服务器 IP 地址和端口的，然后在 location 中通过 proxy_pass 的指令来指定 upstream 的名称，这样就可以将请求转发到定义的 upstream 这个组中的服务器。呃，它还提供了丰富的流量分发算法，默认是采用的轮询转发，也就是说后边有多台 Web 服务器，它会轮询的转发。

除此之外呢还可以去配置它的 IP 哈希，啊还有最小链接，还有权重值，都可以进行去灵活的调整。应用场景四，重定向。重定向也是一个较为常见的需求，啊举几个例子，例如将老域名跳转到新域名，啊假设你的网站的域名发生变化了，你希望将老访问老域名的请求都重定向到新域名，并且保持 URI 不变，那你就可以使用这个 rewrite 指令来去重定向。那再例如将某个 URL 路径做一个调整，可能说这个 URL 路径呢发生变化了，那你可以将访问老的 URL 的路径的请求重定向到新的 URL 路径，也可以通过这 rewrite 命令来去实现。应用场景五，防盗链。防盗链呢它是一个用于防止其他网站来去盗用你网站资源的安全机制，例如图片啊、视频等等，很多的大人网站呢都有做。

啊因为如果你不这样做的话，有一些网站呢它可能是直接引用你网站上的图片或者视频，呃当他访问他的网站的时候，实际上这一块加载的资源是来自于你的网站上的，所以就会导致你服务器的资源呢开源增加。那 Nginx 呢可以基于 HTTP Referer 字段来去实现。啊但是需要注意的是啊这个 Referer 这个字段呢它可以被伪造，所以不是绝对安全。应用场景六，手机端重定向 PC 端。一个网站往往呢都会有多个端访问，例如手机端、PC 端，为了来提高用户的体验，会将来自于手机端的请求来重定向到呃这个手机端的站点，那这里呢你可以去配置加一个条件判断，来去根据手机端里面的关键词，使用 rewrite 指令让它重定向到 M 站，就是手机端的网站。应用场景七，基于请求路径转发不同的服务。如果一个网站包含多个模块，每个模块呢有。

不同的服务来提供，那就可以根据请求的路径来转发相应的服务。Nginx可以实现这样的一个需求。啊，例如将请求路径根来转发到后端的服务器一点一百，将请求路径北京来转发到后端服务器一点幺零幺，将请求路径上海转发到后端服务器一点一零二，就可以轻松的这么进行去实现。以上就是Nginx的七个常用的应用场景以及配置，希望你都能把它掌握了，应用到工作中。
