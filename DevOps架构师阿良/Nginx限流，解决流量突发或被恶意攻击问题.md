如果你的网站遇到流量突发或者被恶意攻击，你可以使用 Nginx 的限流来解决这个问题。接下来呢教给大家如何来配置 Nginx 的限流。Nginx 的限流分为两种，第一种限制客户端请求速率，第二种限制客户端连接数，它们作用都是不一样的，我们分别来看一下。先看一下第一种，限制客户端请求速率。Nginx 呢它提供了有一个 limit request 的模块，来用于去限制客户端每秒请求的数量。使用这个模块分为两步，定义限流和应用限流。

首先呢我们要在 http 这个部分定义 limit request zone，这个指令呢有三个参数，第一个参数定义 key，就是你要基于哪一个标识来区分客户端，因为它是要对某个客户端做限流嘛，所以要能够区分这个客户端，这里通常啊就是使用客户端 IP 作为 key，那因此呢我们可以使用它的内置变量，叫 $remote_addr 这个变量，不过我更推荐使用这个 binary remote addr，这个是表示是以二进制来表示客户端 IP，它相比于 remote addr 以字符串形式表示会占用内存更少，能更高的提高这个性能。第二个参数定义区域名，zone 等于起个名字，这个名字呢你可以任意字符串来去取，比如我们叫 my limit，然后在冒号指定该区域可使用的共享内存大小，假设十兆。

第三个参数定义速率，使用 rate 等于假设五 r s，这表示啊每秒允许五个请求。定义完成之后，我们将其应用到虚拟主机中，在 server 块定一个 limit request 的指令，这个指令呢也是有三个参数，在 proxy pass 这里定义。第一个参数指定限流区域，就是上面我们定义的 my limit 的这个名字。第二个参数定义允许突发的请求数量，也就是说如果你在短时间之内有多个请求，最多是可以有十个请求被允许突发进入到这个队列，例如我设置为五个，啊那那么你第六个到第十五个请求就会被放到这个突发队列中，超过这数量的请求呢将会被直接丢弃或者是返回五零三错误。

第三个参数可选是 no delay，这个表示啊是不是要启用不延迟处理突发请求，在默认情况下如果有突发请求，这些请求啊就会被延迟处理，按照设定的速率来逐个的释放。但如果呢你启用了 no delay，这些请求呢就会立即处理，就不会产生延迟。简而言之，这个配置的作用呢是限制客户端请求的速率，防止某个客户端在短时间之内发生大量的请求来导致服务器压力过大。

第二种限制客户端连接数，Nginx 呢它还提供了一个 limit connect 的模块，来用于去限制客户端的并发连接数，它的使用方法呢与 request 的这个类似啊，首先也是在 http 这部分定一个 limit connect 的 zone，然后这个指令呢是有两个参数，第一个也是要是以哪个来表示某个客户端，还是使用客户端 IP 作为 key，第二个参数呢来去定义它的名字，例如啊叫 addr，然后冒号也是十兆。共享内存，好，然后就可以在虚拟主机中指定该限流区域。还是在这里设置一个 limit 的 connect addr，使用这个名称，后面再跟一个数字来去设置单个 IP 可以建立并发的连接数。例如我这里设置十，也就是说每一个客户端同时建立十个并发链接。

简而言之，这个配置的作用呢就是限制客户端在同一时间内与 nginx 保持最大连接数，来防止某个客户端占用过多资源。这两种配置你都可以同时的使用，能够有效的防止异常流量的客户端。如果你后面遇到类似的问题啊，强烈建议大家启用它。配置完成之后，你可以通过压测工具对它进行压测，以验证是否符合预期。
