Docker 是怎么工作的？从四部分给大家讲解一下。第一部分，我们要先了解一下 Docker 它是怎么实现的。Docker 实际上是利用 Linux 的内核特性 cgroup 实现了容器资源的一个限制，namespace 实现容器的隔离，ufs 联合文件系统实现镜像的分层的管理，使镜像管理呢更加的高效。Docker 通过这些技术真正的实现了一个容器的一个概念，每个容器都具备独立的视图，包括容器里的用户、进程、文件、网络等等，它们都是独立的，容器之间相互不干扰，你看不到我，我也看不到你，进入了一个容器里面就像在一个虚拟机环境里一样。第二部分 Docker 主机，也就是 Docker 引擎。

Docker 主机呢主要有 Docker 客户端和服务端组成，客户端也就是它的命令行，是供用户通过命令行去管理容器和镜像，例如创建容器、删除容器、重启容器、构建镜像、删除镜像等等这些操作。呃，并且 Docker 的守护程序呢也提供了有 API，你可以通过网络远程调它的 API 去完成客户端完成那些事情。第三部分 Docker 镜像，Docker 镜像呢也是它的一大创新，可以说成也萧何败也萧何。镜像就相当于是一个应用程序的打包文件，它里面就包括了应用程序本身、文件系统、应用所需要的运行环境等等打包在一块，然后可以通过这个镜像去创建容器。镜像呢它可以来自公共镜像仓库，例如像 Docker Hub，也可以来自私有的镜像仓库，例如使用 Harbor 进行去搭建的。

这个镜像通常我们是自己进去构建，通过 Dockerfile。Dockerfile 呢是一个文本文件，里面呢是有各种各样的指令组成，来构建一个你所需要的镜像。除了说自己构建，像一些开源软件一些商业产品，它们的官方都制作了自己的镜像，我们直接就可以拿来去用，所以有一些应用服务呢我们就直接用官方的镜像了，就不再进行去制作了。像我们自己开发的应用程序通常都要自自己制作镜像的。第四部分 Docker 容器，容器相当于是镜像的一个实例化的运行。当一个容器创建时，Docker 会创建一个进程在宿主机上，并且提供一个完全的隔离环境。总体来说，Docker 它是使用 Linux 的内核特性实现了这种容器的一个概念，通过镜像将应用程序及依赖的环境打包，利用 Docker 引擎去创建容器和管理容器。

呃，Docker 是基础设施的一大革新，使得应用部署也更加的简单高效。如果你们公司还没用 Docker，抓紧时间用起来吧，能够帮助你提高很大的工作效率。
