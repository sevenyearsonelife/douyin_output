这个 Dockerfile 至少有五点可以优化。第一点，在引用基础镜像这里，尽可能的要指定特定的标签。你现在指定一个 nginx，这是它代表使用最新的镜像，现在使用的确是没啥问题。等过几个月，过一两年之后，你再使用这个 Dockerfile 去构建，就可能会存在该软件版本会拉取最新的，导致下面的一些操作可能就不适用了。所以在引用基础镜像这里，一定要指定你当前用的这个版本。另外，这个基础镜像也尽可能要使用官方发布的镜像，这样安全性啊更有保证。如果你要是随便找一个别人制作镜像，有可能里面啊给你注入一些木马呀、病毒啊等等这些，都会造成不可挽回的损失。第二点，像下面这些 RUN 指令应该合并到一行中。在构建镜像时，Docker 呢会将每个 RUN 指令都会作为一层，过多的层会导致镜像变得臃肿，增加镜像大小和复杂性。

所以建议通过按住 F2 将这些命令啊都放在一行里面。这样去拼写，如果这个命令比较长，你还可以加一个换行符。这样显得更有条理一些。第三点，清理软件包缓存。当你使用 apt 或者是 yum 去安装软件包时，它会将 yum 中元数据和安装的包下载到本地，而这些缓存我们在后面是用不到了。所以我们可以将这个缓存进行去清理，从而减少镜像的大小，以避免呢它打到镜像中。你可以再这样，rm -rf apt 删除了缓存目录，如果你是 yum 的话，这个对应的目录是 yum 目录。第四点，在拷贝网站程序到 nginx 的网站根目录下时，当你使用点去拷贝时，它就会将当前目录下所有文件都会拷贝到网站根目录下。如果这个代码目录是你直接通过 git clone 到本地，然后再构建，它就会多一个点 git 这个目录，保存了当前的版本信息。

如果那个点它也同时会把这个目录拷贝进去，啊包括其他的文件，例如像 Dockerfile，像这个说明文档，都会拷贝到网站根目录下，在部署网站时压根是用不到的。并且要拷贝了像点 git 这种也会增加网站的安全风险。呃这时啊你可以在当前目录下创建一个 .dockerignore 文件，在这里面可以将你不希望拷贝的文件或者目录写进去，例如点 git，还有 Dockerfile，说明文档都放在这里面来。这样当你去通过 docker build 构建镜像时，它就会忽略这些信息的一个拷贝。第五点，使用多阶段构建。对于编译型语言，通常情况下我们会先在宿主机上将它源代码进行代码编译，构建出来的包再通过 Dockerfile 再拷贝到对应的网站程序根目录下，来完成它的一个部署。

其实这一步我们也可以把它放到 Dockerfile 里面一块完成，那这就会用到 Dockerfile 的多阶段构建。请看图，在这个 Dockerfile 中有两个阶段，第一个阶段用于执行代码编译，并通过 as 关键字来给这个阶段起个名字。第二阶段呢是用。用于构建项目镜像，使用COPY指令是添加一个FROM参数，用于来拷贝第一个阶段构建出来部署文件到当前阶段中。那这样一来，它只构建出了一个项目镜像，并不包含代码编译的那个环境，也就是第一阶段。不能再随便的编译Dockerfile了，一定要考虑到这些问题，将能促进你构建出更加安全可靠的镜像。
