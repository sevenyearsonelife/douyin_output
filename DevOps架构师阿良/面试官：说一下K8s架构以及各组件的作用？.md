面试官问你，请说一下 K8s 架构以及各组件的作用，你这么回答给满分。请看图，K8s 架构由管理节点和工作节点以及一个键值存储 etcd 组成。那管理节点简称为 master，它是 K8s 集群的控制中心，负责监控整个集群的状态、资源调度、响应事件等等。呃，主要的组件包括有 api server，是提供 K8s 的 API 服务，负责处理外部和内部组件的请求，也就是所有的组件呢都是向它发送请求，并且它会将这些操作都会存储在 etcd 中。那这里的 etcd 也只有 api server 来使用它，其他组件呢都不与 etcd 进行去交互。这个 etcd 呢也可以独立的部署在 K8s 集群之外，也并没要求一定要部署在 master 上。那 etcd 呢它是一个分布式键值存储，就专门用于存储 K8s 集群的数据。

下面这个组件是 control manager，它是负责管理多个控制器的程序，这个程序里面就是包含了很多的控制器，来负责集群的各种各样的任务，比如说它监控节点状态，当节点它发生故障好及时的响应。再比如像管理 pod 的副本数，像 service 后端管理的 pod 也都是这个控制器里面去管理的。所以这里面呢有内置的很多的控制器，那这些控制器呢就是来去维护集群中的不同的方面，来确保整个集群的状态符合预期。呃，下面还有一个 scheduler，是主要是将 pod 调度到合适的节点上，啊，它有自己的调度算法，就专门就干这样一件事情。这是 master 节点主要的几个组件，啊，工作节点简称 node，它是 K8s 集群的工作节点，它是提供运行容器所需的资源和环境。

这里面主要包括组件有像 kubelet，它是运行在每个节点上，来负责管理 pod 和容器的生命周期，例如启动了容器啊，为容器挂载数据卷呀，获取容器 pod 的状态啊，并且向 api server 进行去汇报。第二个组件呢是 kube-proxy，啊，也是运行在每个节点上，它是负责集群内部的网络代理以及负载均衡功能，本质上它就是 service 资源对象的一个具体的实现。咱们在 K8s 里面呢都是通过访问 service 来访问 K8s 里面的 pod，所以 service 背后呢就是由这个组件来去实现的，实现的负载均衡和转发。第三个组件呢是第三方的，也就是容器运行时，它是实际运行和管理容器的服务。

本质上 K8s 它不具备创建容器的能力，而是使用第三方的容器运行时来去完成这一块任务，啊，有 kubelet 进去调用它。K8s 呢也支持有多种运行时，例如像 docker、containerd、CRI-O 等等这些，啊，包括其他支持 K8s CRI 的容器运行时都是可以的。如果有面试官这么问你，你就这么回答就对了。
