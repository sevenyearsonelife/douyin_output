这两台计算机可以直接通信吗？三秒钟思考一下，先说结论，不可以直接通信，因为它们属于不同的网络。如果想要跨网络进行通信，就需要用到路由设备。我们今天就来分享网络中核心设备路由器。首先明确路由器的定义，它是连接不同网络的设备，负责在不同网络间转发数据包。请注意，是不同网络之间，这与交换机在同一网络内转发的角色有本质区别。假设一台主机 A 要访问另一台主机 B，主机 A 的 IP 是幺九二点幺六八点幺点幺零，主机 B 的 IP 是幺九二点幺六八点二零，根据 IP 地址得知它们分布在不同网段，这时候通信就需要通过路由器。我们将路由转发分为四个阶段：原主机封装、路由器入站处理、查路由表决策、封装与转发。第一阶段，原主机的封装与决策。很多人误以为路由转发从路由器开始，实则路由起点在原主机 A。

主机 A 应用层产生的数据经 TCP/IP 封装生成 IP 报文，源 IP 为 A 的 IP，目的 IP 为 B 的 IP。此时主机 A 的网络协议栈会进行第一次路由决策，用自身子网掩码和 IP 算出所在网段，与目的 IP 幺九二点幺六八点二点二零对比后，发现二者不在同一网段，便知道需将数据包发给默认网关路由器。假设路由器与 A 连接的接口 IP 为幺九二点幺六八点幺点幺。重点来了，主机 A 知道网关 IP，但数据链路层传输需 MAC 地址，这就需要 ARP 协议。主机 A 先查 ARP 缓存表，若有幺九二点幺六八点幺点幺对应的 MAC 地址则直接使用，若无，会广播发送 ARP 请求，网关收到后单播回复自身 MAC 地址。

拿到网关 MAC 后，主机 A 完成二层帧封装，二层帧头中原 MAC 是主机 A，目的 MAC 是网关，三层 IP 头中原 IP 是主机 A，目的 IP 是主机 B。关键提醒，目的 IP 是最终终点，目的 MAC 仅为下一跳地址。第二阶段，路由器的入站处理。数据包通过网线传到路由器入接口，路由器先检查二层帧头的 FCS 即帧校验序列，有误则直接丢弃。确认目的 MAC 是自身接口 MAC 后，便剥去二层帧头，提取 IP 报文，这个过程叫解封装。路由器拿到 IP 报文后，做三项基本检查，第一，检查 IP 头部校验和，确保 IP 头完好。第二，检查 TTL 值，TTL 指的是生存时间，每经一台路由器 TTL 必须减一，若减一后为零，为防环路风暴，丢弃数据包并向原主机发送 ICMP 超时报文。

如果确认 IP 报文格式无误后，进入下一步。第三阶段，查路由表决策。若 TTL 大于零，进入核心步骤，查路由表。路由器需根据目的 IP 一零点零点零点一零决定从哪个接口把包送出去，以及送给谁。路由表是路由器内存中的决策表，每条路由条目包含几个核心信息：目的网络，指明一个 IP 地址范围，例如一九二点一六八点一点零二十四。二，下一跳，指出为了到达目的网络，数据包应该传递给的下一个路由器的 IP 地址。三，出接口，指明数据包应该从路由器自身的哪个物理接口发送出去。在路由表中，路由器执行最长匹配原则，什么意思呢？假设路由表里有两条路由，一条是幺零点零点零点零斜杠二十四，下一跳出接口是接口二，另一条是幺零点零点零点零斜杠二八，下一跳出接口是接口三。

我们的目的 IP 是一零点一点一点一零，这两个路由条目都能匹配，该选哪个？答案是选掩码最长的那个，也就是二十八，因为掩码越长，网络范围越小，路由越精确。通过查路由表，路由器会得出两个关键信息，出接口和下一跳 IP。如果目的 IP 就在路由器的。直连网段，下一跳就是目的 IP 本身。如果还需要中转，下一跳就是下一个路由器的接口 IP。第四阶段，封装与转发。查到出接口后，转发之前，路由器会对 IP 数据包头部进行两项必要修改。一，TTL 减一。TTL 生存时间字段用于防止数据包在网络中无限循环，每经过一台路由器，TTL 值减一。若 TTL 减为零，路由器将丢弃该数据包，并通常向源地址发送一个超时消息。二，重新计算头部校验和。由于 TTL 字段已被改变，IP 头部的校验和必须随之更新。

随后进行重新封装，数据包需重新封装二层帧头，这是初学者易忽视，面试常考的知识点。IP 包每经一台路由器，源 MAC 和目的 MAC 都会改变。路由器的出接口 MAC 会变成新的源 MAC，而目的 MAC 是谁呢？是最终主机 B 的 MAC 吗？不一定。如果路由器直接连接主机 B，那目的 MAC 就是主机 B。如果路由器后面还有其他路由器，那目的 MAC 就是下一个路由器的入接口 MAC。完成封装后，路由器将新数据帧放入出接口发送队列，通过物理链路传出，数据包离开该路由器前往下一个节点。至此路由转发流程完成。有人会问，路由表如何产生？它有三个来源，决定了路由器的适用场景。一，直连路由，路由器接口配置并启用 IP 后自动生成，对应接口所在网段，无需手动配置。

如 LAN 口配置一九二点一六八点一点一二十四，路由表会自动添加对应条目。二，静态路由，是由管理员手动添加，适合小型、拓扑固定的网络。三，动态路由，路由器通过 OSPF、BGP 等动态路由协议，与其他路由器交换信息自动生成。OSPF 适合企业内网，BGP 适合互联网骨干网，可自动适应拓扑变化，适合大型复杂网络。最后总结路由转发逻辑，数据包进入路由器后，第一步校验与剥离，查 FCS 包二层帧头，查 IP 校验和，TTL 减一。第二步决策，按最长匹配原则，查路由表确定出接口和下一跳。第三步重写，找下一跳 MAC，修改源 MAC 和目的 MAC。第四步发送，重新封装并发送。这套动作在互联网主干路由器上时刻发生，正是这套严密高效的标准化逻辑，支撑起庞大的网络世界。好了，这就是本期的全部内容，我们下期再见。
