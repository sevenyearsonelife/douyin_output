这两台计算机可以直接通信吗？三秒钟思考一下，先说结论，不可以直接通信，因为它们属于不同的网络。如果想要跨网络进行通信，用交换机肯定不行，因为交换机只能实现同一个网络通信。跨网络通信属于三层通信，需要用到路由设备。我们今天就来分享网络中核心设备路由器。首先明确路由器的定义，它是连接不同网络的设备，负责在不同网络间转发数据包。请注意，是不同网络之间，这与交换机在同一网络内转发的角色有本质区别。假设一台主机 A 要访问另一台主机 B，主机 A 的 IP 是幺九二点幺六八点幺零点幺，主机 B 的 IP 是幺九二点幺六八点二零点二，根据 IP 地址得知它们分布在不同网段，这时候通信就需要通过路由器。我们将路由转发分为四个阶段，源主机封装，路由器入站处理，查路由表决策，重新封装与转发。

第一阶段，源主机的封装与决策，很多人误以为路由转发从路由器开始，实则路由起点在源主机 A，主机 A 应用层产生的数据经 TCP/IP 封装生成 IP 报文，源 IP 为主机 A 的 IP，目的 IP 为主机 B 的 IP，此时主机 A 的网络协议栈会进行第一次路由决策，用自身子网掩码和 IP 算出所在网段，与目的 IP 幺九二点幺六八点二零点二对比后，如果是在同一个网段，则通过二层局域网直接转发出去，很显然，二者不在同一网段，此时主机 A 会将数据包发给自己的默认网关，通常是路由器，假设路由器与主机 A 连接的接口 IP 为幺九二点幺六八点幺零点二五四。

第二阶段，路由器的入站处理，数据包到达路由器的入接口后，路由器首先会检查数据帧的目标 MAC 地址，确认是不是发往自己的，确认目标 MAC 匹配后，路由器会拆掉二层帧头，暴露出里面的 IP 报文，接着校验 IP 头的校验和是否正确，检查 IP 报文有没有损坏，校验通过后，路由器会读取 IP 报文中的目标 IP 地址，这是后续路由决策的核心依据，整个入站处理的本质就是完成二层到三层的解封装，为路由查找做准备。第三阶段，查路由表决策，路由器需根据目的 IP 幺九二点幺六八点二零点二，决定从哪个接口把包送出去，以及送给谁。

路由表是路由器内存中的决策表，每条路由条目包含几个核心信息，一，目的网络，指明一个 IP 地址范围，例如幺九二点幺六八点二零点零斜杠二十四，二，下一跳，指出为了到达目的网络，数据包应该传递给的下一台设备的 IP 地址，三，出接口，指明数据包应该从路由器自身的哪个物理接口发送出去。在路由表中，路由器执行最长匹配原则，什么意思呢？假设路由表里有两条路由，一条是一零点一点一点零斜杠二十四，下一跳出接口是 G 二口，另一条是一零点一点一点零斜杠二十八，下一跳出接口是 G 三口，我们的目的 IP 是一零点一点一点一零，这两个路由条目都能匹配，该选哪个？答案是选掩码最长的那个，也就是斜杠二十八的，因为掩码越长，网络范围越小，路由越精确。

通过查路由表，路由器会得出两个关键信息，出接口和下一跳 IP，如果目的 IP 就在路由器的直连网段，下一跳就是目的 IP 本身，如果还需要中转，下一跳就是下一个路由器的接口 IP。第四阶段，重新封装与转发，确定出接口和下一跳后，路由器并不会直接把 IP 报文发出去，而是要重新封装二层数据帧，这是初学者容易错，面试经常考的知识点，IP 包每经一台路由器，源 MAC 和目的 MAC 都会改变，路由器的出接口 MAC 会变成新的源 MAC，而目的 MAC。是谁呢？是最终主机 B 的 MAC 吗？不一定。如果路由器直接连接主机 B，那目的 MAC 就是主机 B。如果路由器后面还有其他路由器，那目的 MAC 就是下一个路由器的入接口 MAC。

完成封装后，路由器将新数据帧放入出接口发送队列，通过物理链路传出，数据包离开该路由器前往下一个节点，至此路由转发流程完成。好了，现在你知道路由器是怎么工作的了吧？这就是本期的全部内容，我们下期再见。
