哈喽大家好啊，可能百分之九十九的人都搞不清楚 IP 地址跟 MAC 地址它有什么关系。那么 IP 地址我们平时接触的比较多，我们配了它才可以上网。那 MAC 地址是干什么的？它跟 IP 地址又有什么关系？为什么有了 IP 还需要 MAC 地址才可以？那么今天我们花几分钟时间来搞懂它。我们所有的网络通信最终都需要依靠网卡来接收发送数据，不管是电脑的有线网卡还是手机的无线网卡，而 MAC 地址就是这张网卡在网络世界里唯一的身份编号。只要具备网络的功能的设备都会有一个专属的 MAC 地址。MAC 地址的全称是媒体访问控制地址，它又叫物理地址，是有线或者无线网卡在出厂的时候呢由厂商固定在芯片里面的一个全球唯一的这么一个标识，相当于网卡的一个出厂的一个身份证号。

那虽然说这个硬件层面它是烧录在这个网卡里面的是没有办法更改的，但是呢在软件层面我们可以在操作系统里面对它进行一个修改。我们来看一下 MAC 地址有三个核心特征，首先是全球唯一性，每一块 MAC 地址呢它都不会重复，它是由 I E E 统一分配的一个厂商识别码到制造商，然后呢制造商呢再为每一块出厂的网卡呢去分配一个唯一的一个设备序列号。然后第二个呢是硬件的一个固化性，也就是说这个地址啊它在出厂的时候呢就烧录到了硬件的这个网卡当中去，所以说呢原生的这个 MAC 地址呢它是没有办法更改的，不会因为就是说你变更了这个网络或者说重装了操作系统而发生这个改变。然后最后一个呢就是局域网内有效，就是说这个 MAC 地址它的一个作用啊它仅限于二层的这个局域网内，它是没有办法去离开当前局域网呢进行一个访问的。

好，那我们再来看一下 MAC 地址的一个格式，那么标准的这个 MAC 地址呢长度是四十八位，但是呢它通常是使用十六进制的格式来进行表示的。我们看一下，你看这里两个十六进制的字符呢为一组，那组跟组之间呢一般会用这个冒号来进行分隔，比如说我们图上这个就是一个标准的 MAC 地址格式。那这个 MAC 地址呢它这六组字符啊还是要分成两部分，每一部分呢有单独的这个含义，前三组我们叫做组织的唯一标识符，那是 I E E 分给网卡厂商的一个专属代码，就相当于厂商的一个这样子一个唯一的一个标识。而后三组呢是厂商自定义的一个网卡的一个唯一的一个序列号，就相当于网卡的一个个人的一个这个身份标识。

所以说呢这样子呢厂商就可以保证每一块网卡的这个序列号啊都不重复，两者组合起来之后呢它就可以实现全球范围内啊这个 MAC 地址的一个绝对的一个唯一性。你看举个例子，我们图上这个 MAC 地址前三个字节一 A 二 B 三 C，这个呢就是网卡的制造商的一个厂商代码，而后三个字节四 D F 一 F F，那这个呢就是厂商生产这张网卡的时候给它烧录的一个唯一的一个序列号。通过这两者的组合呢它就确保了在全球范围内呢没有另外一块网卡的 MAC 地址跟它是完全相同的，当然了软件修改的这个地址除外。接下来我们要搞懂一个核心的问题，就是 MAC 地址它究竟工作在网络的哪一层？答案是 O S I 七层模型的第二层数据链路层，只要这个数据转发没有跨网段，还在同一个局域网内转发，那么它转发的这个核心呢靠的就是 MAC 地址。

在交换机里面有一张 MAC 地址表，里面保存了 MAC 地址与交换机端口的对应关系。交换机在转发数据帧时只认目的 MAC 地址，然后按照对应的端口进行转发数据，这个时候呢通常不会用到 IP 地址。那这个时候很多人就会问，既然 MAC 地址全球唯一能标识每一台设备，为什么上网还需要 IP 地址？其实呢 MAC 地址它只有局域网内的一个寻址能力，并没有跨网络的一个路由能力。MAC 地址这个结构啊它是扁平的，没有层级的，它只能告诉你这是属于哪一块网卡，并不能告诉你这块网卡。卡在世界的哪一个网络什么位置？而我们的互联网呢，它是由无数个网络组成的，这些网络呢又依靠路由器相互连接。路由器在跨网络转发数据的时候呢，它其实是不关心目标设备的 MAC 地址的，它只看 IP 地址和路由表，它就能把数据从一个网络送到另一个网络。

所以说这个 IP 地址和 MAC 地址是网络通信里分工很明确的。IP 地址呢它工作在 OSI 的第三层网络层，负责全局定位，告诉你设备在哪个网络，哪一个逻辑位置，用来实现跨网段、跨公网的一个路由转发。而 MAC 地址呢它是工作在 OSI 第二层数据链路层，负责最后一公里的交付。也就是说在同一个局域网内，它是可以实现精准定位到具体的网卡上面，然后把数据呢转发到最终的目标设备上。那搞懂了分工，我们再来看一下一个关键的问题，就是 IP 地址跟 MAC 地址是怎么配合完成一次完整的通信的。我们举一个简单的场景，这个时候你要给同一个局域网的同事电脑传文件，你知道对方的 IP 地址，但你的电脑并不知道对方的 MAC 地址，这个时候呢就需要用到 ARP 协议，也就是我们常说的地址解析协议。

那么 ARP 的工作流程非常简单，你的主机会在当前的这个局域网内发送一条广播请求，然后这个请求的内容呢就是去询问这个 IP 地址它的 MAC 地址是什么。这个时候呢局域网内其他的所有设备呢都会收到这条广播，但是呢只有目标 IP 是与之匹配的这个目标主机，它会回复这一个广播，它会将自己的这个 MAC 地址告诉发送方，然后发送方收到之后呢，它就会将这个 IP 与 MAC 地址的这个映射关系啊缓存到本机上，然后后续的这个通信呢，它就会直接的去应用这个 MAC 地址的一个这样子一个映射关系啊去封装数据帧，然后完成点对点的一个传输。那简单的来说，在局域网发送数据帧之前呢，IP 地址呢一定会通过 ARP 协议找到目标对应的 MAC 地址，才能够完成数据的一个这样子一个转发。

最后我们再看看 MAC 地址的一个核心应用场景啊，就是这个交换机的一个转发场景。那么交换机啊它之所以可以实现局域网内数据的一个精准的转发，核心呢就依靠的这个内部的一个 MAC 地址表，那这张表呢记录了哪一个 MAC 地址连接在交换机的哪个端口上。关于 MAC 地址表的完整学习和转发机制呢，这个我们后续啊单独出一期视频再详细的去拆解。好了，最后我们总结一下 MAC 地址的作用。首先呢 MAC 地址呢是网络通信的一个核心，数据的转发呢是需要 IP 加 MAC 的一个协同工作。那第二个呢就是 MAC 地址的这个格式啊，通常呢是用十六进制的方式来进行表示，具备全球的一个唯一性。然后呢它是工作在 OSI 七层模型的第二层数据链路层，仅在局域网内生效。

那第四个呢就是 IP 地址呢是负责网段的一个逻辑寻址和路由，那么 MAC 地址呢是负责局域网内的一个最终的一个交付。最后呢就是交换机，它是依靠 MAC 地址表来实现局域网内数据的一个精准转发的。好了，只要搞懂了 MAC 地址，那你就彻底掌握了局域网二层转发的一个底层核心逻辑。那么本期的这个内容就到这里，我们下一期再见。
