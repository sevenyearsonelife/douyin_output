上一期咱们遗留了一个问题，就是内网多主机如何通过 NAT 上网。此时内网有三台主机，IP 地址分别为 192.168.1.1 与 1.2 和 1.3，路由器的公网 IP 地址为 10.1.1.1，需要访问的互联网服务器 IP 地址为 8.8.8.8，三台主机在同一时间去访问服务器的 HTTP 服务，我们来看看这个过程是怎么样的。第一步，主机会生成访问的数据包，数据包内包含源 IP 地址，也就是自己的 IP 地址，以及目的 IP 地址为服务器的 IP 地址。由于我们访问的是 HTTP 服务，所以目的端口号是 80 端口。另外主机一般会使用一个随机端口作为源端口，这里我们使用的源端口号为 12345。

同时主机 B 跟主机 C 也会生成访问数据包，目的都是 8.8.8.8，端口 80，源 IP 也都是自己的 IP 地址，同时也会随机生成一个源端口号。第二步，数据包发送到路由器，路由器会对它们执行 NAT 的操作。首先将数据包的源 IP 地址修改为自己的公网 IP，10.1.1.1，然后会修改源端口号为随机端口号，例如 50011，然后对主机 B 与主机 C 的数据包都执行 NAT 的操作，修改源 IP 地址与源端口号。此时我们可以看见三个数据包的内容几乎一样，唯一区别就是源端口号不同。第三步，路由器将数据包发送至公网，传递给目标服务器。

此时我们可以看到路由器生成了一张 NAT 的映射关系表，它准确记录了内网 IP 地址、内网端口与外网 IP 地址、外网端口的对应映射关系，这个表将成为数据包返回时精准找到目标的关键。第四步，服务器收到了数据包，并且进行回复，服务器会将数据包的原目的信息进行重新封装，源 IP 为服务器 IP 地址 8.8.8.8，源端口为 80，而目的 IP 都是路由器的公网 IP 地址 10.1.1.1，目的端口是对应数据包来时的端口号。第五步，路由器收到了服务器的回包，此时会拆开数据包提取关键信息，并且打开 NAT 映射表进行比对。路由器使用不同端口号来区分不同的内网主机，并按映射表的对应关系去修改数据包，将目的 IP 地址与端口号进行修改，最终发送到内网对应的主机上了。

至此内网多主机经过 NAT 上网的一次通信全过程就结束了。这种 NAT 类型叫做 NAPT，也叫网络地址端口转换，也是目前家庭和企业最常用的 NAT 类型。它的核心是多台私网设备共享一个公网 IP，通过不同的端口号来区分不同设备，实现多设备同时上网。理论上一个公网 IP 可以同时支持六万多个连接，极大节省了公网 IP 资源，缺点是无法被外网主动访问。好了，这就是今天视频的全部内容，下一期我们来看看为什么现在家用宽带上网没有公网 IP 也能上互联网，我们下期见。
