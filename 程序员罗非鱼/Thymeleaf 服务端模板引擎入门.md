什么是 Thymeleaf？简单说，它是一个面向 Java 的服务端模板引擎，主要工作是把数据和模板合在一起，生成最终的 HTML、XML 或文本内容。它常出现在 Spring Boot 的 Web 项目里，但你也可以脱离 Spring 单独使用。下面会讲清它的核心特点、运行方式、常见语法思路、适用场景和限制。先看它是什么。模板引擎可以理解成一套填空规则，页面里保留固定结构，需要变化的地方写表达式。请求到达服务器后，程序准备数据，Thymeleaf 读取模板，替换表达式，输出完整页面，再发给浏览器。所以它做的是服务端渲染，不是浏览器里的前端框架。页面上的循环、条件、链接和国际化文案都可以在服务端决定。Thymeleaf 最受关注的特点是自然模板。

一个 Thymeleaf 模板通常仍是合法 HTML，你直接用浏览器打开文件也能看到接近最终的静态页面。加入 th 属性后，它才在服务端参与渲染。这对前后端协作和原型展示很有用。设计师可以先做静态页面，开发人员再逐步加上动态表达式，而不必把页面改成完全不可读的标签混排。它的标准表达式大体分几类：变量表达式读取模型数据，选择表达式围绕某个对象取字段，消息表达式读取国际化文案，链接表达式生成带上下文路径的 URL，片段表达式复用页头、页脚等公共区域。常见属性也很直观，th:text 输出文本，th:each 遍历集合，th:if 控制是否渲染，th:href 生成链接。它们写在原有 HTML 属性位置，静态打开时不会破坏页面结构。为什么重要？

因为它把数据准备和页面展示分开，同时保留 HTML 的可读性，对传统 MVC 应用、后台管理页面、内容型网站和邮件模板这种模式很合适。服务器直接返回完整 HTML，首屏内容不依赖大量前端脚本，对 SEO 和可访问性通常更友好。它还能和 Spring MVC 的视图解析机制配合，控制器返回视图名，模型携带数据，Thymeleaf 负责渲染。Spring Boot 项目引入对应 starter 后，通常把模板放在 resources/templates 下就能按约定工作。使用时要注意几个条件。第一，动态内容默认应通过 th:text 这类属性输出，它会做 HTML 转义，只有确认内容可信时才使用不转义的输出方式，否则会有注入风险。第二，模板缓存，生产环境通常开启，开发时按需关闭，改模板才能及时看到效果。

第三，它适合服务端生成页面，不适合把大量交互逻辑塞进模板，复杂前端交互仍应交给 JavaScript 或前端框架。第四，模板片段和布局能减少重复，但过度拆分也会增加维护成本。真实场景可以这样理解：一个商品列表页，控制器查出商品集合，模板用 th:each 生成卡片，用 th:text 填价格和名称，用 th:if 显示售罄，用片段复用导航栏。浏览器收到的是已经拼好的 HTML。若页面需要频繁局部刷新，可以只让部分区域由前端异步更新，而不是让 Thymeleaf 承担所有交互。总结一下，Thymeleaf 是 Java 生态里的服务端模板引擎，核心价值是把模板保持得像普通 HTML，并在服务端把模型数据安全可维护地填进去。它最适合服务端渲染的页面和模板复用场景。

理解它的表达式、转义规则、缓存和 Spring 集成方式才能用对它。它不是前端框架，也不解决所有页面交互问题，边界清楚，优势才成立。
