什么是反射？简单说，反射是程序在运行时查看自己，甚至修改自己结构的一种能力。平时写代码，一个类有哪些方法，哪些字段，编译时基本就确定下来了。而有了反射，程序可以在运行之后再去问自己，这个对象属于哪个类，它有哪些方法，这些方法要什么参数，然后动态地把它们调用起来。接下来的内容会讲清三件事：反射到底在操作什么，它解决了哪些静态代码解决不了的问题，以及为什么它很强大却通常不建议滥用。先从最基础的说起。在 Java、C Sharp 这类语言里，代码要先经过编译，编译器在编译阶段就要知道你调用的方法存不存在，参数对不对。这种提前确定的好处是安全、快，错误在编译期就会被拦住。但它有个前提，写代码的时候你就得知道要操作的是哪个类。反射打破的正是这个前提，它把类本身也当成一种可以在运行时查看的数据。

编译之后，类名、方法名、字段名、参数类型、注解这些信息会以某种形式保留在程序里，通常叫元数据。反射就是一套读取和使用这些元数据的接口。通过它，程序可以拿到一个代表类的对象，在 Java 里叫 Class，在 C Sharp 里叫 Type，然后列出它的构造方法、成员变量、公开方法，还能绕过普通的调用语法，直接按名字去执行某个方法。举个具体场景，假设你写了一个框架，要读取配置文件里的一行，handler 等于 com 点 example 点 my handler，然后创建这个类的实例并调用它。写框架的时候，你根本不知道用户会填哪个类，编译器也无从检查，这时候只能靠反射，按字符串找到类，实例化，再按方法名调用。类似的还有序列化库，它要把任意对象的字段读出来转成 JSON；依赖注入容器要扫描注解然后自动装配；

单元测试框架要找出所有标了测试注解的方法逐个执行。这些都是反射的典型战场。不过反射的代价也很实在。第一是性能，普通方法调用在编译期就确定了目标，而反射要在运行时做名称查找、权限检查、参数打包，开销明显更大。虽然现代运行时做了不少优化，在很多常见场景下已经没那么慢，但在高频执行的热点代码里仍然要谨慎。第二是安全边界，反射能访问私有成员，等于绕过了语言设计的封装，让本来不该被外部改动的东西可以被改动。第三是错误被推迟，方法名拼错、参数类型不匹配，编译器不会提醒你，要等到运行时才抛异常。第四是对代码混淆和裁剪不友好，因为反射依赖字符串形式的名称，工具很难判断哪些代码真的被用到。所以结论在于用在哪里，而不在于反射本身好不好。它更适合框架、工具、插件系统这类必须处理未知类型的场景。

普通业务代码里能用接口、泛型、依赖注入解决的，通常没必要上反射。真要用，也应该把反射集中在少数边界位置，做好结果缓存和异常处理，别让它散落到核心逻辑里。一句话收尾，反射让程序从照着写好的剧本演，变成可以现场翻剧本、临时改台词，灵活性上了一个台阶，代价是把编译期那张安全网撤掉了一部分。理解这一点，比记住几个接口更重要。
