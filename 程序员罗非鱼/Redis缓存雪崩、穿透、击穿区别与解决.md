什么是 Redis 里的缓存雪崩、缓存穿透和缓存击穿？这三个词听起来很像，但它们描述的是三种完全不同的事故场景。理解它们的区别能帮你在设计系统时提前避开最典型的坑。接下来我会先讲清楚三者各自是什么，再说明它们为什么会发生，会造成什么后果，最后给出对应的解决思路。先说缓存雪崩，它的核心特征是大量缓存同时失效。正常情况下请求先查 Redis，查到就直接返回，查不到才去查数据库。但如果一大批键在同一时刻过期，或者 Redis 服务整体宕机，那么原本被缓存挡住的流量会瞬间全部压到数据库上。数据库扛不住就可能被拖垮，进而导致整个系统不可用。这里的关键词是同时和大量。解决办法有两个方向：一是给过期时间加随机值，让键分散失效，避免同一秒集体到期；二是做多级缓存或缓存集群，让单点故障不至于全盘失效。

对关键数据还可以设置永不过期，由后台任务主动更新。再看缓存穿透，它指的是请求查询一个根本不存在的数据。比如有人用不存在的用户 ID 反复请求，Redis 里没有，数据库里也没有，于是每次请求都绕过缓存直接打到数据库。如果是恶意攻击，用大量随机 ID 持续请求，数据库就会承受巨大压力。注意穿透的重点是数据本身不存在，所以缓存永远不会命中。常见对策是缓存空值，即使查不到也把一个空结果写进 Redis，并设置较短过期时间。更严谨的做法是用布隆过滤器，在查询前先判断这个键是否可能存在，不存在就直接拦截。最后是缓存击穿，它和雪崩的区别在于规模。击穿指的是某一个热点键突然失效，而恰好有大量请求同时来访问它。比如首页最热门的商品缓存过期的那一瞬间，成千上万的请求同时发现缓存没了，于是一起去查数据库，并可能同时尝试重建缓存。

结果是数据库在短时间内被同一个查询打爆。它的关键词是单个热点键加高并发。解决办法是加互斥锁，只让一个请求去查数据库并重建缓存，其他请求等待或返回旧值。也可以对热点数据设置逻辑过期，让它在物理过期后仍能提供旧数据，由后台异步刷新。把三者放在一起对比会更清楚。雪崩是大量键同时失效，影响面最广；穿透是查不存在的数据，缓存永远挡不住；击穿是单个热点键失效，瞬间并发集中打击。它们的共同点是最终压力都落到数据库上，但触发条件和应对手段各不相同。实际系统里这三种情况往往需要组合防护，随机过期时间、空值缓存、布隆过滤器、互斥锁和多级缓存一起用，才能让缓存层真正起到保护数据库的作用。
