什么是 Java 二十一的虚拟线程？它是 Java 二十一正式引入的一种轻量级线程，由 J V M 调度，而不是和操作系统线程一对一绑定。它让开发者继续用阻塞式写法，却能支撑更高并发。接下来会讲清它解决什么问题，如何工作，适合什么场景，以及使用时必须注意的约束。传统 Java 线程通常叫平台线程，每个平台线程对应一个操作系统线程，创建和切换成本高，数量也受系统限制。高并发服务常给每个请求分配线程，但请求大部分时间在等数据库、网络或磁盘，线程被阻塞，资源闲置。线程池能减少创建销毁开销，但池大小有限，请求仍可能排队。虚拟线程要解决的就是这种线程不够用、阻塞代价高的问题。

虚拟线程也是 Thread，A P I 基本兼容，可以用 Thread of virtual 括号点 start 创建，也可以用 Executors new Virtual Thread per Task Executor 为每个任务创建虚拟线程。它不由操作系统直接调度，而由 J V M 调度到一组载体线程上。载体线程是平台线程，数量通常和 C P U 核数相关。虚拟线程运行时挂载到载体线程，遇到阻塞 I O 等操作时，J V M 把它卸载载体线程去运行别的虚拟线程，等阻塞结束再重新挂载继续。它的栈存在堆里，按需增长收缩，所以能创建很多，数量级远高于平台线程，但它不是无限，受内存等资源约束。它重要在哪？编程模型没变。过去为了提升吞吐，人们常用异步回调、反应式框架，代码复杂，调试也难。

虚拟线程让一个请求一个线程的简单模型重新可行，对 I O 密集型服务，比如 Web 服务、微服务、网关、数据库访问、远程调用，收益明显。吞吐可能提升，但单次任务不会因此更快，延迟也不一定降低。C P U 密集型任务不适合虚拟线程，还会增加调度开销，应继续使用平台线程或并行计算。使用时有几个关键点。第一，不要池化虚拟线程，它很便宜，池化会限制并发并带来额外复杂度。推荐每个任务创建一个，或使用每任务一个虚拟线程的执行器。控制并发不要靠线程池大小，而要用信号量、限流、连接池等保护下游资源。虚拟线程数量多不代表数据库、文件句柄和下游服务能承受。第二，小心 Thread Local，每个虚拟线程可能有自己的副本，数量大时内存开销上升。

Java 二十一还预览了作用域值 Scoped Values，用于更安全的传递不可变上下文，但预览功能需要显式开启，生产使用要评估。第三，注意固定现象。Java 二十一里，虚拟线程在 synchronized 代码块中阻塞或执行原生方法时，可能被固定在载体线程上，无法卸载，这会占住载体线程，严重时影响吞吐。建议在虚拟线程中把容易阻塞的同步块换成 Reentrant Lock，并留意原生调用。另外，Java 二十一还预览了结构化并发 Structured Task Scope，用来管理一组子任务的生命周期和取消，它不是使用虚拟线程的前提，虚拟线程本身是正式特性，不需要开启预览。总结一下，虚拟线程改变的是 J V M 线程和操作系统线程的绑定方式，让阻塞式代码在高并发 I O 场景下更容易扩展。

它不替代所有线程，也不提升 C P。计算能力，判断是否适合可以看任务是否大量等待 I/O，是否能用简单阻塞模型，是否避免了池化和固定问题。条件满足，Java 二十一虚拟线程就值得采用。条件不满足，先找真正的瓶颈和资源上限。
