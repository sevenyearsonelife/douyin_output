什么是 Markdown？简单说，它是一种用纯文本写文档的轻量标记语言。你不需要鼠标点按钮，只靠键盘敲几个符号就能表达标题、列表、加粗、链接这些格式。它最特别的地方是写出来的内容即使不经过任何渲染也能直接读懂。接下来我会讲清几件事：Markdown 到底解决了什么问题？它的基本语法怎么理解？为什么工程师和写作者都爱用它？以及它有哪些容易踩的坑和适用边界。先从它要解决的问题说起。在 Markdown 出现之前，写带格式的文档通常要用 Word 这类工具。问题在于文件是二进制的，换台电脑可能排版乱掉，用 Git 做版本对比几乎不可能。另一种方式是直接写 HTML，功能强但满屏标签，写一段话要敲一堆尖括号，阅读和修改都很累。Markdown 的思路是折中，用最少的符号表达最常用的格式，让源文件保持可读。

那它的语法怎么理解？核心就一句话：用符号给文字加语义。比如行首打一个井号加空格就是一级标题，两个井号就是二级标题。行首打减号加空格就是无序列表，打数字加点和空格就是有序列表。文字两边各加两个星号是加粗，各加一个星号是斜体。用方括号写文字，圆括号写网址就是链接。大于号开头表示引用，三个减号单独一行就是一条分割线。这些符号有个共同特点，它们模仿了人们本来就习惯的书写方式。星号像强调，减号像列点，井号像标题。所以你学起来很快，忘掉之后看一眼源文件也能猜出来。这就是它被称为轻量标记语言的原因，标记的负担很轻。再讲它为什么重要。第一，纯文本意味着通用，任何设备任何系统都能打开，不会因为软件版本不同而打不开。第二，它天然适合版本控制，每一次修改在 Git 里都能看到具体改了哪个字、哪一行，这对团队协作非常关键。

第三，它把内容和格式分开了，你只管专心写内容，格式交给渲染器去处理，同一份源文件可以输出成网页、 PDF、电子书。第四，它生态极广，GitHub、各种笔记软件、博客平台、文档工具几乎都支持 Markdown。不过这里有个关键点必须说清，Markdown 并不是一个严格统一的标准。最早由约翰格鲁伯在二零零四年提出，但长期没有正式规范。不同平台实现不一样，同样一段符号在这家网站显示正常，换一家可能就不认。后来出现了 CommonMark 这样的规范，试图统一核心语法，但各家扩展仍然五花八门。所以结论要加条件：写普通文档没问题，一旦依赖某个平台特有的扩展语法，换平台就可能失效。它适合什么？不适合什么？适合写说明文档、技术笔记、博客、 README、会议记录这类以文字为主、结构清晰的内容。

不适合做精细排版的海报、复杂表格、需要精确控制字体字号和分页的正式出版物。硬要用它做这些只会不断碰壁。总结一下，Markdown 用极简符号表达常见格式，靠纯文本换来通用、可版本控制、内容与格式分离这三大好处。它的能力边界在于标准不统一、排版能力有限。理解这一点，你就能在合适的场景用它，而不是期待它解决所有问题。
