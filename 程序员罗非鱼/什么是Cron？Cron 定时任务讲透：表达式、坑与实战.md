什么是 cron？简单说，它是 Unix 和类 Unix 系统里一个专门用来按时间表自动执行任务的程序。你只要提前告诉它什么时候做什么，它就会在后台默默守着，时间一到就出发。小到每天凌晨清理临时文件，大到定时备份数据库、生成报表，背后往往都是它在干活。这期我们把它讲透，先搞清楚 cron 到底是什么，由哪几部分组成，再弄明白那串看着像乱码的时间表达式怎么读，然后看它在真实场景里怎么用，有哪些坑，最后说说它在今天还值不值得学。先讲它是什么。Cron 是一个常驻后台的守护进程，英文叫 daemon。它启动后就一直待着，每隔一分钟醒一次，检查有没有任务到了该执行的时间，如果有，就把它拉起来跑。这个任务在术语里叫 cron job，也就是定时任务，而描述什么时候跑的那串规则叫 crontab，直译是 cron 表。

所以你可以把整套东西理解成三层：cron 是执行引擎，crontab 是时间表，cron job 是表上的每一条待办。为什么它重要？因为在计算机世界里，有大量工作不需要人盯着，但必须准时、重复地做。人工去点既容易忘，也没法在凌晨三点执行。Cron 解决的正是这个无人值守的准时重复问题。它出现得早，几乎每个 Linux 服务器都自带，不需要额外安装，这就是它几十年不倒的原因。接下来是核心，那串时间表达式到底怎么读？标准 crontab 一行有五个时间字段，加一条要执行的命令，顺序是分、时、日、月、周。注意，是分钟在最前面，不是秒。也就是说，cron 的最小精度是一分钟，它做不到秒级触发，这是很多人第一个误解。每个字段的写法有几种：写具体数字，就是就这个时间；写星号，代表每一个，比如分钟位写星号就是每分钟都跑；

写逗号是列举，比如一、十五、三十，表示第一、十五、三十分钟；写减号是范围，比如九减十七，表示九点到十七点；写斜杠是步长，比如星斜杠五，表示每隔五个单位。把这几条组合起来，你就能读懂绝大多数 crontab。举几个例子，五个星号意思是每分钟执行一次。如果写成零三星星，就是每天凌晨三点整跑一次。再比如十九杠十八乘乘一杠五，意思是周一到周五早上九点到下午六点之间，每隔十分钟跑一次。你看，只要按字段顺序拆开读，它一点都不神秘。但光会读还不够，真正容易出问题的是执行环境。这里有个关键点，cron 执行任务时，环境和你在终端里手动敲命令时不一样，它不会加载你的登录配置，所以你的环境变量，尤其是 PATH 往往是不完整的。结果就是你手动跑没问题的脚本，交给 cron 就报命令找不到，这是新手最常踩的坑。第二个坑是工作目录。

Cron 不会自动切到你脚本所在的目录，它默认在别的地方启动。所以脚本里如果用了相对路径，很可能找不到文件。稳妥的做法是在脚本里写绝对路径，或者显式地先切换目录。第三个坑是输出。Cron 执行任务产生的标准输出和错误，默认不会显示给你看，而是通过邮件发给当前用户。可很多服务器根本没配邮件，于是这些信息就石沉大海，任务失败了你却完全不知道。所以实践中通常会把输出重定向到日志文件，方便事后排查。那真实场景里它怎么用？最典型的是运维自动化。比如每天凌晨备份数据库，定期清理过期日志，定时同步文件，检查服务是否存活。在 Web 应用里，它也常被用来跑定时脚本，比如每天统计一次数据，给用户发提醒邮件，刷新缓存。可以说，只要一个任务满足重复和按时间这两个特征，Cron 就是最省事的方案。不过也要说清楚它的边界。

Cron 只管按时触发，它不负责任务之间的依赖关系。如果任务 A 必须先于任务 B 完成，Cron 本身管不了，你得自己在脚本里控制。它也不做失败重试，任务跑挂了就是跑挂了。另外，如果上一次任务还没结束，下一次时间又到了，它默认会再启动一个，可能造成重复执行，这需要你自己加锁来避免。所以对于复杂的工作流调度，人们往往会用更专业的工具，比如 systemd timer 或者各类工作流调度系统。但那些工具很多在设计上仍然借鉴了 Cron 的表达方式。总结一下，Cron 是系统里按时间自动执行任务的守护进程，Crontab 是它的时间表，五个字段按分、时、日、月、周排列，最小精度是一分钟。它最大的价值是无人值守的准时重复。用好它的关键不在于表达式多复杂，而在于处理好环境变量、绝对路径和日志输出这三个细节。

理解了这些，你就真正掌握了这个几十年不过时的基础工具。
