什么是 CDN？简单说，CDN 就是内容分发网络，它不是一台服务器，而是一张分布在不同地区、不同运营商里的服务器网络。目标很直接，让用户更快、更稳地拿到网页、图片、视频和软件包。下面讲清楚它是什么、为什么重要、怎么工作以及适合哪些场景。理解源站、边缘节点、缓存、回源和调度这几个词，基本就抓住了核心。先看没有 CDN 的情况，所有用户都直接访问源站。源站可能只在一个城市、一个机房。北京用户也许很快，广州、欧洲、南美用户就要跨越大半个网络。距离远，经过的设备多，延迟就高。遇到热门视频或大促，大量请求同时涌向源站，带宽、连接数和磁盘读写都可能被压垮。CDN 要解决的就是内容离用户太远以及源站压力太大这两个问题。那它怎么工作？第一步，内容提供方把源站接入 CDN。源站是内容的原始存放地，也是最终权威来源。

第二步，CDN 在很多地方部署边缘节点。边缘节点可以理解为靠近用户的缓存服务器，它们提前或按需保存源站内容的副本。第三步，用户请求网址时，通常不直接连源站，而是先经过 CDN 的调度系统。调度系统会根据用户位置、网络运营商、节点健康状况和当前负载，把请求分到合适的边缘节点。这个过程常用智能 DNS 或者任播这种让多个节点共用同一地址的技术实现。如果用户要的内容正好缓存在节点上，就叫缓存命中，节点直接返回，速度快，也几乎不占用源站资源。如果没有缓存或缓存过期，就叫未命中或回源。边缘节点会向源站或上层节点请求，拿到后再返回用户，并按规则缓存一段时间。这个时间通常由 TTL，也就是缓存有效期来控制。TTL 越长，缓存复用越多，源站越轻松，但内容更新可能越慢。TTL 越短，更新更快，回源更频繁。

静态资源常用文件名带版本号来更新，这样既能长期缓存，又能立即发布新版本。CDN 最典型的场景是静态内容分发。图片、CSS、JavaScript、字体、安装包、点播视频，这些内容对很多用户是一样的，非常适合缓存。视频平台会把大文件切成小片段，通过 CDN 分发到边缘，用户播放时从附近节点拉取，起播更快，卡顿更少。直播也类似，主播推流到源站，CDN 把流切片并快速分发，边缘节点在服务大量观众。电商大促、新闻热点、游戏更新也是 CDN 发挥价值的地方，因为流量会在短时间暴涨，分布式节点能分担压力。但 CDN 不等于只能缓存，很多 CDN 还提供动态加速。对登录、下单、支付这类个性化请求，内容不能随便缓存，但 CDN 可以通过就近接入、长连接、最优路由和协议优化，让数据包走更稳的路径，减少跨运营商、跨地域的抖动。

边缘计算更进一步，允许在边缘节点运行一部分代码，比如鉴权、 A B 测试、图片裁剪、简单改写，让请求不必每次都回到中心源站。安全也是 CDN 的重要能力，因为用户先访问 CDN，源站 IP 可以被隐藏，减少直接攻击。CDN 还能吸收和清洗 DDoS 流量，提供 Web 应用防火墙、 TLS 证书管理、防爬和访问控制。不过它不是万能盾牌，它主要缓解网络层和常见应用层攻击，不能替代源站自身的安全开发、权限控制和数据保护。最后要理解边界，CDN 最擅长可缓存、热门、用户分布广的内容。如果内容高度个性化，要求强一致、延迟极低，或者源站。和用户本来就在同一区域，CDN 的收益可能有限，甚至增加一层复杂度。CDN 也不能替代源站，它只是把内容复制到离用户更近的地方，并优化传输路径。

真正稳定的系统仍然需要可靠的源站、合理的缓存策略、监控和容灾。总结一句话，CDN 是一张分布式缓存和流量调度网络，核心价值是让内容更靠近用户，让源站更轻松，让访问更快更稳。
