什么是大语言模型的运行机制？简单说，它不是先想好整段答案再一次性说出来，而是把文字拆成一个个小单位，再不断预测下一个单位。理解 token、上下文窗口和采样参数，就能明白为什么同一个模型有时答得稳，有时答得飘。下面把这些概念拆开讲，并说明它们怎样共同决定输出。先看 token。Token 是模型处理文本的基本单位，可以理解成词片。它不等于一个字，也不等于一个单词。英文里，一个常见单词可能是一个 token，也可能被拆成几段。中文里，一个字可能对应一个 token，也可能几个字合成一个。模型先把你输入的文字转成 token 序列，再把这些 token 变成数字向量送进网络。输出时也一样，模型一次只生成一个 token，再把它接回输入，继续预测下一个。这个循环叫自回归生成。

所以 token 数量直接影响费用、速度以及能不能塞进上下文窗口。不同模型的分词方式不同，同样的句子 token 数可能不一样。再看上下文窗口。它是一次请求中模型能看到的最大 token 数量。这个数量通常包括你给的提示、历史对话以及模型正在生成的回答。比如窗口是八千 token，输入加输出就不能超过八千。超了怎么办？常见做法是截断旧内容、压缩摘要，或者换用更长窗口的模型。窗口不是长期记忆，模型本身没有状态，每次请求都要重新把相关历史放进去。它更像一张临时工作台，而不是仓库。工作台越大，能放的材料越多，但成本和延迟通常也越高。而且材料多了，模型不一定平均关注，关键信息放在中间可能被忽略，放在开头或结尾往往更容易被抓住。然后是采样参数。模型每一步都会算出一个概率分布，表示下一个 token 可能是什么。

采样参数决定怎么从这个分布里选。温度是最常调的一个。温度低，概率高的 token 更容易被选中，输出更稳定、更保守。温度高，低概率 token 也有机会，输出更多样，但也更容易跑偏。Top 减 k 是只保留概率最高的 k 个候选。Top p 也叫核采样，它保留累计概率达到 p 的那一组候选，候选数量会随分布变化。还有重复惩罚，用来降低反复说同一句话的概率。最大输出 token 和停止序列则控制回答什么时候结束。需要准确答案时，温度可以调低，top p 调小。写故事、做头脑风暴时，可以适当调高，增加变化。还要注意，生成是逐 token 进行的，前面选了一个词，后面就会在这个基础上继续。如果早期选了不合适的词，后面的内容可能顺着它越走越偏。采样随机性会放大这种差异，所以同一个提示两次运行结果可能不同。

温度调到零也不代表绝对确定，因为不同实现、并行计算和模型版本都可能带来细微差异。所以调参不是越高越聪明，也不是越低越准确，关键是匹配任务。这些机制怎么共同影响输出？可以这样理解：token 是计量单位，上下文窗口决定模型此刻能看到什么，采样参数决定它怎么选下一个 token。提示词提供方向，模型能力提供上限，采样参数只在这个上限内调整风格和随机性。如果输入超窗，再好的采样参数也看不到被截掉的信息。如果事实信息在上下文中，但温度太高，模型也可能用流畅但错误的说法覆盖它。因此，排查输出问题时，先看 token 和窗口，再看采样参数，最后看提示和模型本身。最后记住三句话：第一，token 决定成本、速度和长度限制，不同语言和模型的切分方式不同。第二，上下文窗口是临时工作台，不是永久记忆，超出就要截断、摘要或换模型。

第三，采样参数控制随。即兴，稳定任务用低温，创意任务用高温。把这三件事分开看，你就能更清楚地判断一次输出为什么好，为什么坏，以及下一次该改哪里。
