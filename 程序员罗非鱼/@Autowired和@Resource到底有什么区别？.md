什么是 Autowired 和 Resource 的区别？这是 Java Spring 开发中最常被问到的问题之一。简单说，两者都能把依赖注入到类里，但它们的来源、匹配规则和使用场景并不一样。搞清这一点能帮你避免启动报错、注入错对象，也能让你在写代码时知道该选哪个。先说它们各自的出身。Autowired 是 Spring 框架自己提供的注解，来自 Spring 的依赖注入体系。Resource 不是 Spring 发明的，它来自 Java 标准，也就是 JSR 杠二五零规范，Spring 只是支持并实现了它。这个出身差异直接决定了两者默认的匹配方式不同。Autowired 默认按类型注入。也就是说 Spring 会先看你要注入的字段或参数是什么类型，然后在容器里找这个类型的对象。

如果这个类型只有一个实例，就直接注入。如果找到多个同类型的实例，它不会随便挑一个，而是会报错，提示存在多个候选者。这时候你需要配合其他手段来消歧，比如加上 Qualifier 指定名字，或者用 Primary 标记首选，再或者把其中一个改成按名字匹配。Resource 默认按名字注入。它会先拿字段名或方法名当作默认的名字，去容器里找同名的对象。如果找到了，就注入。如果按名字找不到，它才会退回按类型匹配。这一点和 Autowired 的默认顺序正好相反。所以当你有一个接口有多个实现类，而你又想精确指定用哪一个时，Resource 往往更省事，只要名字对得上就行。第二个区别在于能否指定名字。Autowired 本身不能直接写名字，它必须搭配 Qualifier 才能按名字筛选。

Resource 则自带 name 属性，可以直接写 Resource name 等于叉叉叉，一步到位。这也是很多老项目里更偏爱 Resource 的原因，代码更短，意图更直接。第三个区别是适用范围。Autowired 可以放在构造器、方法、字段和参数上。Resource 按照标准主要支持字段和方法。虽然 Spring 也允许它用在某些其他位置，但官方更推荐构造器注入时用 Autowired。这里要特别提一句，Spring 官方现在更推荐构造器注入，而不是字段注入。因为构造器注入能保证依赖不为空，也更容易做单元测试，还能暴露循环依赖问题。所以在构造器上 Autowired 是更自然的选择。第四个区别是可选性处理。Autowired 有一个 required 属性，默认是 true，表示找不到匹配对象就启动失败。

你可以把它设成 false，让这个依赖变成可选的。Resource 没有这个 required 属性，它更倾向于要么找到要么报错。如果你需要可选注入，Autowired 配合 required 等于 false 会更方便。那实际开发中到底怎么选？可以记住一个简单的判断逻辑。如果你是按类型注入，尤其是构造器注入，优先用 Autowired。如果你是按名字注入，或者接口有多个实现，名字就是你的区分依据，用 Resource 更直接。如果团队有统一规范，就跟着规范走，别混着用，否则维护时容易混乱。还有一点容易忽略，Autowired 是 Spring 专属的，用了它你的代码就和 Spring 框架绑得更紧。Resource 来自 Java 标准，理论上换一个支持该标准的容器，代码还能用。

虽然现实中大多数人不会换容器，但如果你在意可移植性，Resource 会稍微中立一些。总结一下，Autowired 是 Spring 的，默认按类型，靠 Qualifier 消歧，支持 required 可选，适合构造器注入。Resource 是 Java 标准的，默认按名字，自带 name 属性，按名字找不到才退回类型。适合多实现类的精确选择，两者没有绝对的好坏，关键是理解它们的默认行为，然后在合适的场景用合适的那个。
