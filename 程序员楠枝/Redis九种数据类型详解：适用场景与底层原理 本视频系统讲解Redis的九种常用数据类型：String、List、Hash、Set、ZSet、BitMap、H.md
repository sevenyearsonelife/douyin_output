什么是 Redis 的九种常用数据类型？简单说，它们是 Redis 存储和处理数据的九种不同方式，每种类型解决一类特定问题。今天这期内容，我会逐一讲清楚每种类型是什么，适合存什么，底层怎么工作，以及真实场景里该选谁。理解了这九种类型，你就掌握了 Redis 大半的核心能力。先说最基础的 string 字符串类型。它是 Redis 最通用的数据类型，能存文本、数字、二进制数据，甚至序列化后的对象。它的核心操作是 set 和 get，时间复杂度都是 O 一，所以常用来做缓存、计数器、分布式锁。值得注意的是，Redis 里的数字运算，比如 i n c r decr，也是在这个类型上完成的，而且操作是原子的，多线程环境下不会出错。第二种，list 列表类型。

它本质上是一个双向链表，可以在头部或尾部快速插入和删除元素，时间复杂度 O 一，但按下标访问中间元素是 O n。列表适合做消息队列、时间线、最新动态这类场景，比如用 lpush 往左边推新内容，再用 lrange 取最近 N 条。需要注意的是，列表不擅长随机访问，如果你要频繁按下标查数据，它不是好选择。第三种 hash 哈希类型，它类似一个嵌套的 map，一个 key 下面可以挂多个 field value 对。哈希最典型的用途是存储对象，比如用户信息，每个字段单独存取，更新某个字段时不用整体重写。哈希的底层在字段少时用压缩列表，字段多时转为哈希表，所以小对象场景下内存效率很高。第四种 set 集合类型，它的特点是元素唯一无序，支持交集、并集、差集运算。

集合的底层是哈希表或整数集合，添加、删除、判断是否存在都是 O 一。它最适合做标签系统、好友关系、去重统计。比如用 sadd 把用户 I D 加进某个标签集合，再用 sinter 算两个集合的交集，就能快速找出共同关注。第五种，有序集合类型，也叫 zset。它和集合一样元素唯一，但每个元素关联一个分数，按分数排序。底层是跳跃表加哈希表，所以既能按分数范围查询，也能精确查元素。它几乎是为排行榜量身定做的，比如直播间热度榜、游戏积分榜，用 zadd 更新分数，用 zrevrange 取前几名，效率极高。第六种 bitmap 位图类型，它其实建立在字符串之上，但按位操作，每个位只有零或一。位图的核心价值是极省内存，比如统计一亿用户的签到状态，只需要约十二兆。它的典型场景是签到统计、在线状态、布尔型埋点。

用 setbit 设置某一位，用 bitcount 统计有多少位是一，用 bitop 做多个位图的与或运算。第七种 hyperloglog 类型，它用来做基数统计，也就是统计不重复元素的数量，但允许极小的误差，标准误差约百分之零点八一。它的神奇之处在于内存固定，不管统计多少数据，最多占用约十二 K B。它适合做 U V 统计、独立访客数、搜索关键词去重计数。注意，它只能告诉你大概有多少个不同元素，不能告诉你具体是哪些元素。第八种地理位置类型 geo，它用来存储经纬度坐标，并支持计算两点距离、查找某点附近的其他点。底层实现是使用有序集合，把经纬度编码成一个分数。它的典型场景是附近的人、门店定位、配送范围判断。用 geoadd 添加位置，用 georadius 按半径搜索，用 geodist 算距离，都很直观。

第九种流类型 stream，它是 Redis 五点零引入的，专为消息队列设计，支持消费者组、消息持久化、消息确认。它和列表做队列的区别在于，stream 支持多消费者协作消费，消息不会被简单弹出，而是记录消费进度，适合。和可靠的异步任务分发。如果你需要消息不丢，多个消费者分工处理，Stream 是更正式的选择。现在回头看这九种类型，你会发现它们不是互相替代，而是各自覆盖一类数据结构和场景。字符串是万金油，列表管顺序，哈希管对象，集合管去重和关系，有序集合管排序，位图管极致内存，HyperLogLog 管海量去重统计，Geo 管空间位置，Stream 管可靠消息。选型时先问自己三个问题：数据是什么结构？要做什么操作？对内存和精度有什么要求？答案清晰了，类型自然就定了。

最后提醒一句，数据类型只是 Redis 的第一层，真正用好它还要理解过期策略、持久化、内存淘汰机制，但这些是后续话题了。今天这九种类型，建议你先在本地 Redis 里逐个试一遍，亲手敲几个命令，比看十遍文章都有用。
