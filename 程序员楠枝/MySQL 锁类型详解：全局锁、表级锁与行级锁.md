什么是 MySQL 中的锁？简单说，锁就是数据库为了保证多个操作同时发生时数据不混乱，而设置的一套排队和互斥规则。你平时执行增删改查，MySQL 会在背后自动加锁、释放锁，只是大多数时候你感觉不到，但一旦出现锁等待、死锁或者性能突然变慢，锁的类型和加锁范围就成了必须搞清楚的问题。这条视频会讲清 MySQL 里主要的锁类型，包括全局锁、表级锁、行级锁，以及行级锁内部的记录锁、间隙锁和临键锁。听完你会知道它们分别解决什么问题，在什么场景下出现，以及为什么有些锁会让并发性能下降。先从最重的全局锁说起。全局锁一旦加上，整个数据库实例基本只能读，不能写。最典型的用法是全库逻辑备份，执行 flush tables with read lock 之后，所有表的更新语句都会被阻塞。

它的好处是备份期间数据一致性有保证，坏处是业务几乎停摆。所以生产环境里很少直接长时间用全局锁，更多会考虑在从库上做备份，或者用支持一致性快照的备份工具。比全局锁轻一级的是表级锁。表级锁有两种常见形式，一种是表锁，一种是元数据锁。表锁通过 lock tables 命令显式加上，可以分为表共享读锁和表独占写锁。表锁的优点是开销小、加锁快，缺点是并发度低，因为一张表被写锁占住时，其他连接对这张表的读写都会被挡在外面。元数据锁不需要你手动加，它是 MySQL 自动维护的。当你对一张表做增删改查时，会加元数据读锁，当你修改表结构时，会加元数据写锁。元数据锁主要防止查询进行到一半，表结构突然被改掉。

常见的问题是一个长事务没提交，导致后续的 alter table 一直等待，因为修改表结构需要拿到元数据写锁，而长事务一直占着读锁不放。真正复杂的是行级锁。行级锁只针对被访问到的记录行加锁，并发度比表锁高很多，但开销也更大。行级锁只在 InnoDB 存储引擎里真正生效，它内部又可以分成三类：记录锁、间隙锁和临键锁。记录锁最好理解，就是锁住某一条具体的索引记录。比如你执行 select for update 命中了一行，这行就会被加上排他记录锁，其他事务想改这一行就得等待。注意记录锁加在索引上，而不是数据行本身。如果一张表没有索引，InnoDB 会退而使用隐藏的聚簇索引，但加锁范围可能会因此变大。间隙锁锁的不是某一行，而是两条索引记录之间的空隙。它的作用是防止其他事务在这个空隙里插入新记录。

比如表里 id 有 5 和 10 两条记录，间隙锁可能锁住 5 到 10 之间的范围，这样即使当前没有 id 等于 7 的数据，其他事务也不能插入 id 为 7 的记录。间隙锁主要为了解决可重复读隔离级别下的幻读问题。幻读指的是同一个事务里两次查询，第二次多出了新的行，间隙锁就是阻止这种新行出现。临键锁是记录锁和间隙锁的组合，它锁住一条记录，同时锁住这条记录前面的间隙。InnoDB 在可重复读隔离级别下，默认的行级锁实现就是临键锁。它既能防止其他事务修改当前记录，也能防止在当前记录之前插入新记录，从而同时解决脏写和幻读问题。那这些锁在什么条件下触发？需要看具体语句和隔离级别。读已提交隔离级别下，间隙锁通常不会生效，主要使用记录锁。

可重复读隔离级别下，普通查询使用一致性快照不加锁，但锁定读，也就是 select for update 或 select lock in share mode，会按临键锁规则加锁。更新和删除语句也会加排他锁，范围取决于索引命中情况。最后总结一下，MySQL 的锁体系可以看成三层：全局锁影响整个实例，表级锁影响整张表，行级锁只影响相关记录和范围。全局锁用于备份，表锁用于粗粒度控制，元数据锁自动保护表结构，行级锁则通过记录锁、间隙锁和临键锁的组合，在并发和数据一致性之间做精细平衡。平衡。理解这些锁类型，不是为了背概念，而是当系统出现锁等待或死锁时，你能判断出大概是哪一层、哪一类锁出了问题。
