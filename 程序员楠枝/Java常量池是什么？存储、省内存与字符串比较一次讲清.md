什么是 Java 中的常量池？简单说，它是 Java 虚拟机在加载类的时候，专门划出的一块内存区域，用来集中存放各种写死在代码里的常量。这些常量包括字符串、数字、类名、方法名等等。理解常量池，是理解 Java 内存模型和字符串比较这类日常问题的一把关键钥匙。本期我们会讲清三件事：常量池到底存了什么？它为什么能帮程序省内存？以及我们平时写代码时最容易踩到的字符串比较的坑。听完之后，你会明白为什么两个看起来一模一样的字符串，有时候用双等号比较是 true，有时候却是 false。先看它存了什么。Java 的类文件里有一个专门的区域叫常量池表，编译器会把代码里出现的字面量，比如字符串你好，整数一百，还有各种符号引用，比如类名、方法名、字段名，全部收集起来编上号，放进这张表。

当虚拟机加载这个类的时候，就会根据这张表在内存里创建运行时常量池。所以常量池不是一个模糊的概念，而是一张有编号、有结构的数据表。这里要区分两个容易混淆的概念，一个是刚才说的类文件里的静态常量池，另一个是运行时在内存里的运行时常量池。前者是编译产物，写在 class 文件里，后者是虚拟机真正加载后使用的结构。我们平时说的常量池多数时候指的是后者，尤其是其中的字符串池。为什么需要常量池？最直接的好处是节省内存。假设一个程序里有几十处地方都写了字符串 error，如果没有常量池，每一处都可能创建出一个独立的字符串对象。但有了常量池，编译器会尽量让这些相同的字面量指向同一个入口，运行时只要从池里取，不用反复创建。这对字符串这种高频使用的对象来说，节省非常明显。另一个好处是加快符号引用的解析。

类名、方法名这些信息在类加载后，需要从符号引用变成直接引用，也就是从名字变成内存地址。因为常量池把这些名字集中存放，虚拟机查找和替换的效率会更高。那字符串常量池具体怎么工作？关键在 intern 这个机制。当我们用双引号直接写一个字符串，比如 hello，虚拟机会先检查字符串池里有没有内容相同的字符串，如果有，就直接返回池里那个对象的引用，如果没有，就在池里创建一个，然后返回。这个过程是自动发生的，不需要程序员手动干预。但如果是通过 new 关键字创建的字符串，比如 new String 包着一个 hello，情况就不同了。new 一定会在堆里创建一个全新的对象，哪怕内容相同，它也不会自动去字符串池里找。所以一个双引号字符串和一个 new 出来的字符串，即使内容一样，它们的内存地址通常也不一样。

这就引出了那个经典问题，为什么两个内容相同的字符串用双等号比较结果不稳定？双等号比较的是引用地址，不是内容。两个双引号直接写的 hello，因为都从字符串池返回同一个引用，所以双等号是 true。但如果其中一个是 new 出来的，双等号就是 false，因为地址不同。要比较内容必须用 equals 方法。这里有一个常见的误区，就是以为字符串池是独立于堆的一块特殊内存。在早期 Java 版本里，字符串池确实放在方法区，但后来被移到了堆里，它仍然是堆的一部分，只是逻辑上被单独管理。所以字符串池里的对象一样会被垃圾回收，只是回收条件和普通对象略有不同。再看一个和数字有关的点。

Java 对常用小整数也有缓存机制，范围默认是负一百二十八到一百二十七，在这个范围内用自动装箱得到的整数对象，也会从缓存里取，所以双等号比较可能为 true。但这属于整数缓存，和字符串常量池是两套机制，不要混为一谈。常量池的核心仍是字符串和符号引用。最后总结一下，常量池是 Java 类加载后在内存中维护的一张常量表，用来集中存放字面量和符号引用。它最大的价值是节省内存、加快符号解析。理解它的关键在于分清静态常量池和运行时常量池，以及记住字符串双等号比较的是引用而不是内容。只有从池里返回的同一个引用，双等号才会是 true，这个判断条件比死记结论更重要。
