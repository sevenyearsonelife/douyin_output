这期视频我会讲清楚后端开发中最常见的六种分页方式，包括它们各自的实现逻辑、优缺点以及什么场景该选哪一种。理解了这六种方式，你在设计列表、接口、消息流、后台管理系统时就能做出更合理的技术选型。第一种是偏移量分页，也叫基于 offset 的分页。这是最直观也是开发中最常见的一种方式。前端通常传两个参数，一个是页码，一个是每页条数。后端根据这两个参数计算需要跳过多少条数据，然后查询后面的记录。比如每页十条，查询第三页就需要跳过前二十条，再取十条数据。SQL 中最常见的就是 limit 和 offset 的组合。这种方式的优点是简单，前端也容易实现，用户可以直接跳转到任意页，总条数和总页数也比较容易计算，所以非常适合普通的管理后台、用户列表、订单列表等场景。

但它的问题也比较明显，当页码越来越大时，数据库需要扫描并跳过的数据越来越多，查询性能会逐渐下降。如果数据在翻页过程中频繁新增或删除，还可能出现数据重复或者漏掉的问题。因此它更适合数据量不是特别大，并且用户主要浏览前几页的场景。第二种是基于 ID 的游标分页，它不再关心当前是第几页，而是使用上一页最后一条数据的 ID 作为下一次查询的起点。比如第一次查询二十条数据，最后一条记录的 ID 是一百，那么下一次查询时就可以直接查询 ID 大于一百的数据，再取二十条。这种方式最大的优势是性能比较稳定，因为 ID 通常有索引，数据库可以直接定位到指定位置，不需要像 offset 一样扫描并丢弃前面的大量数据，即使翻到很深的位置，查询性能也不会因为页码变大而明显下降。

但它也有一个明显的限制，就是无法像页码分页一样直接跳到第一百页，只能根据上一页的结果继续向后查询。因此它更适合数据量较大的列表、消息列表、日志列表以及无限滚动等场景。第三种是基于时间的游标分页，它和 ID 游标分页的思路类似，只不过游标不再使用 ID，而是使用创建时间、更新时间等时间字段。比如按照创建时间倒序查询数据，第一页返回的数据中最后一条记录时间是上午十点，那么下一次请求时就查询创建时间早于上午十点的数据。这种方式非常适合订单、操作日志、消息动态等具有明显时间顺序的数据。相比单纯使用 ID，它的业务语义更加直观，比如加载十点之前的数据，同时配合时间字段索引，也能够保持比较稳定的查询性能。不过时间字段并不一定唯一，如果大量数据拥有完全相同的时间，就可能出现重复或者漏数据的问题。

因此在生产环境中通常还需要结合唯一 ID 一起使用。第四种是 keyset pagination，也叫键集分页，它可以看作游标分页的一种更加通用的实现方式。它不依赖 offset 去计算需要跳过多少条数据，而是根据排序字段直接确定下一页的查询范围。比如按照金额倒序排列，就可以根据上一页最后一条记录的金额查询金额更小的数据。这种方式特别适合大数据量场景，因为数据库可以利用索引快速定位到下一批数据，而不需要扫描前面的记录。它也比较适合无限滚动的列表，比如商品流、评论列表、动态信息流等。不过它对排序条件有一定要求，排序字段最好具有索引，而且必须能够稳定的确定下一页的位置。如果排序字段存在大量重复值，就需要使用多个字段组合起来保证结果稳定。

第五种是延迟关联分页，也叫 deferred join，它主要是用来优化传统 offset 分页的一种方案。当数据量非常大，但业务又必须支持用户直接跳转到指定页时，可以先利用索引查询出这一页需要的主键 ID，然后再根据这些 ID 查询完整的数据。比如查询第五万页时，并不是直接对整张表进行大 offset 查询，而是先通过索引找到这一页对应的 ID，再通过这些 ID 回表获取完整记录，这样可以减少大量不必要的数据读取，尤其适合表字段很多。单条记录比较大的场景，这种方式保留了 offset 分页可以跳页的特点，同时能够在一定程度上改善深分页的性能，但它的实现复杂度会比普通 limit 和 offset 更高，而且深分页本身仍然需要处理大量偏移数据。因此如果业务不要求跳页，通常还是优先考虑 keyset 或游标分页。

第六种是无 count 分页，也可以理解为基于是否还有下一页的分页方式。传统分页接口通常会先查询总记录数，然后返回 total、total pages 等信息。但对于数据量特别大的表，count 查询本身也可能带来额外的数据库压力。因此在一些信息流、日志、消息列表中，接口不会再计算总条数，而是每次多查询一条数据，用来判断后面是否还有数据。例如前端每次请求二十条，后端实际查询二十一条，如果能够查到第二十一条，就说明还有下一页，只返回前二十条，并告诉前端 has more 等于 true。这种方式不需要计算总页数，也不需要维护准确的 total，因此特别适合数据量非常大的场景，用户也不需要看到第几页、共多少页，而是不断点击加载更多或者向下滚动。这种设计在 feed 流、短视频、消息列表、海量日志等场景中比较常见。
