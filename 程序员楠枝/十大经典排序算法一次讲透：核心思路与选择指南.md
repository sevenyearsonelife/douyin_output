计算机中的十大经典排序算法有哪几个？它们的原理是什么？这篇文章带你快速过一遍这十个算法的核心思路、时间复杂度，以及实际使用时到底该怎么选。先说最基础的三个冒泡排序、选择排序和插入排序。冒泡排序的思路非常简单，就是让大的数像气泡一样一点点往上升。每一轮比较相邻的两个数，如果顺序不对就交换，一轮比较下来，最大的数就会跑到数组最后面，然后继续处理剩下的数据，反复执行，最终整个数组就排好了。它平均时间复杂度是 O n，数据一多就比较慢，但优点是实现简单，而且属于稳定排序。如果数组本身已经基本有序，再加上提前结束的优化，最好情况下可以达到 O n。选择排序稍微不一样，它每一轮会从剩余数字中找到最小的那个，然后把它放到当前最前面。比如第一轮找到整个数组最小值放到第一位，第二轮再从剩余元素里找最小值放到第二位，以此类推。

选择排序同样是 O n，而且不管数组原本是否有序，该做的比较基本都要做，不过它的交换次数比较少，每轮通常只需要交换一次。需要注意的是普通选择排序并不是稳定排序。插入排序则像我们打扑克牌时整理手牌，假设手里的牌已经有序，每拿到一张新牌就从后往前找到合适的位置，然后插进去。它平均时间复杂度也是 O n，但是对于基本有序或者规模比较小的数据，插入排序其实非常快，最好情况下可以达到 O n。所以很多高级排序算法在处理很小的数据区间时也会使用插入排序。接下来是希尔排序，希尔排序可以理解成插入排序的升级版。普通插入排序的问题是，如果一个很小的数字出现在数组最后面，它可能需要一步一步移动到最前面。希尔排序则先按照一定的间隔把数组分组，对每组分别进行插入排序，然后不断缩小间隔，比如从五变成二，最后变成一。

这样做的目的就是先让整个数组变得大体有序，最后再进行一次完整的插入排序，速度自然会快很多。它的时间复杂度和间隔序列有关，实际性能通常明显好于普通 O n 排序。希尔排序也是历史上最早突破 O n 的排序算法之一。再往上是三个非常重要的高性能排序，归并排序、快速排序和堆排序。先说归并排序，它采用的是经典的分治思想，一个大问题不好解决，就把它拆成多个小问题。归并排序会把数组从中间不断切开，直到每一部分只剩一个元素，然后再把两个已经有序的小数组合并起来。比如左边是一四七，右边是二三八，只需要不断比较两边最前面的元素，就能合并成一二三四七八。归并排序的时间复杂度非常稳定，无论数据原本是什么样，基本都是 O n log n，而且它还是稳定排序。缺点就是数组合并时通常需要额外的内存空间。

然后是最著名的快速排序，快速排序同样采用分治思想，它会先选择一个基准值，也就是 pivot，然后把比它小的元素放到左边，比它大的元素放到右边，接下来再分别对左右两部分执行相同的操作。快排平均时间复杂度是 O n log n，而且实际运行速度通常非常快，所以应用非常广泛。不过快排存在一个问题，如果每次选择的基准值都很差，导致左右两边的数据严重不平衡，最坏时间复杂度会退化成 O n。因此实际实现中经常会通过随机选择基准值、三数取中等方式进行优化。接下来是堆排序，堆排序利用的是二叉堆这种数据结构。如果要从小到大排序，可以先把数组构造成一个大顶堆，这时候堆顶就是最大的元素，然后把堆顶和数组最后一个元素交换，最大的数就确定位置了，接着缩小堆的范围，重新调整堆，再找到剩余元素中的最大值，不断重复这个过程。

堆排序的平均和最坏时间复杂度都是 O n log n，而且额外空间开销比较小，它最大的优势就是性能比较稳定，不会像快速排序一样退化到 O n，不过实际运行速度通常不如优化后的快排。最后三个属于非比较排序，计数排。序、桶排序和基数排序，它们不完全依靠两个元素之间比较大小，而是利用数据本身的特点进行排序。计数排序适合数据范围比较小的整数，比如考试成绩只有零到一百分，我们可以直接统计每个分数出现多少次，然后按照零到一百的顺序重新输出。它的时间复杂度是 O(n+k)，其中 k 是数据范围，当数据范围比较小时，它会非常快。但如果只有几百个数字，取值范围却达到几十亿，就不适合使用计数排序了。桶排序则是把数据按照一定范围分到不同的桶里，每个桶内部单独排序，最后再把所有桶合并起来。

如果数据分布比较均匀，每个桶中的数据量都不大，桶排序理想情况下可以接近 O(n)。但如果数据分布非常不均匀，大量数据全部进入同一个桶，效率就会明显下降。最后是基数排序，它的思路是按照数字的每一位进行排序。比如对一批三位数排序，可以先按照个位排，再按照十位排，最后按照百位排。经过多轮稳定排序之后，整个序列自然就有序了。所以基数排序特别适合整数编号或者固定长度字符串这类可以按照位拆分的数据。最后总结一下，十大经典排序算法，从简单的冒泡、选择、插入到 O(n log n)级别的归并、快排和堆排序，再到利用数据特征实现高效率的计数、桶和基数排序，其实反映的是算法设计的一条核心思路，用更聪明的策略和更合适的数据结构，减少不必要的计算。

所以没有哪个排序算法是绝对最好的，真正选择算法时，你只需要重点考虑几个问题：数据量有多大，数据本身有什么特点，是否要求稳定，能不能接受额外的内存开销。理解了这些，你才算真正理解排序算法，而不只是背下了十个算法的名字和时间复杂度。
