Agent跑长任务，最大的瓶颈从来不是模型不够聪明，是上下文塞不下了。这条视频会讲清三件事：上下文为什么会成为瓶颈，主流的压缩策略各自怎么工作，以及在什么条件下该选哪种策略。理解了这些，你就能判断一个 Agent 在长任务里到底是真聪明，还是假装记住了所有东西。先看问题本身，Agent 每执行一步，都要把用户问题、历史动作、工具返回结果重新拼进上下文。任务一长，token 数量会迅速膨胀，大模型上下文窗口再大也是有限的。而且即使没超限，输入越长，模型对中间信息的注意力也越分散，成本还直线上升。所以上下文压缩不是可选项，是长任务 Agent 的基础能力。最直接的一类策略是截断，只保留最近几轮对话，或者只保留最开始的任务描述和最近的结果。

优点是实现简单，开销极低，缺点也很明显，中间步骤里的关键约束一旦被丢掉，模型可能重复已经失败过的动作，或者忘记某个重要限制。第二类是摘要压缩，让模型定期把历史内容总结成结构化摘要，比如已完成哪些步骤，当前状态是什么，有哪些未解决的约束，之后用摘要替代原始历史。这样信息密度高，能保留跨步骤的长期记忆，但摘要是有损的，如果总结时把某个看似不重要的细节省略了，后面又恰好需要它，就找不回来了。所以摘要策略通常要配合关键事实的单独存储。第三类是选择性保留，也叫检索式压缩，不总结也不简单截断，而是根据当前步骤的需求，从完整历史里检索最相关的片段放回上下文。这需要一套嵌入模型或者关键词匹配机制，优势是保留了原始细节，不会因为摘要偏差丢信息，代价是增加了一个检索环节，而且检索不准的话，真正需要的那段历史可能根本没被选中。

第四类是结构化记忆，把历史信息拆成固定字段，比如任务目标、已完成动作、当前环境状态、失败记录、用户偏好等，每一步只更新这些字段，上下文里始终放的是这个紧凑的结构，而不是原始流水账。这种方式最适合状态明确、步骤重复度高的任务，比如网页操作或表单填写。但它的灵活性差，遇到开放任务时，固定字段可能装不下复杂信息。第五类是混合策略，也是实际 Agent 系统里最常见的做法。比如短期用截断保持最近动作的完整细节，中期用摘要压缩较早的历史，长期用结构化记忆保存跨任务的关键事实，不同层级的信息用不同压缩方式，比单一策略更稳。那怎么选？如果任务短、步骤少，截断就够了。如果任务长但结构清晰，结构化记忆更合适。如果任务长且信息分布不均匀，检索式保留能避免丢细节。如果成本敏感又需要长期记忆，摘要加关键事实存储是平衡点。

最后要明确一点，所有压缩都是有损的，所谓最优策略，是在保留关键决策信息和控制 token 成本之间做权衡。真正可靠的 Agent 不是把历史记得最全的那个，而是知道什么该忘，什么必须留的那个。
