Redis 三大缓存故障分表是缓存穿透、缓存击穿、缓存雪崩。先讲缓存穿透，穿透的意思是请求的 key 在缓存里不存在，数据库里也不存在。比如你查一个根本不存在的用户 id，缓存查不到，数据库也查不到，那每次请求都会直接打到数据库。正常情况下，缓存是挡在数据库前面的一道墙，可穿透就是这道墙被绕过去了。如果攻击者故意构造大量不存在的 key，数据库就会被无效请求活活打满，这叫穿透攻击。解决方案也很直白，第一，把空结果也缓存起来，哪怕是 null 也给它一个很短的过期时间，这样同样的无效 key 在短时间内不会反复打库。第二，用布隆过滤器，它像一个前置哨兵，能快速判断某个 key 大概率不存在，不存在就直接拒绝，根本不给数据库添麻烦。注意，布隆过滤器只能告诉你肯定不存在和可能存在，存在误判，所以它是过滤不是判定。

再说缓存击穿，击穿针对的是一个热点 key，它恰好过期了，结果一瞬间有大量并发请求同时来查这个 key，缓存里没有，所有请求就同时涌向数据库。穿透是查不存在的东西，击穿是查存在但刚好过期的东西，区别在于击穿只打一个 key，但那个 key 的流量可能极高。对付击穿，核心思路是让请求不要同时穿透。第一个办法是互斥锁，也就是只放一个请求去数据库加载数据，其他请求等它加载完再从缓存里拿，这叫加锁回源。第二个办法是逻辑过期，也就是不给 key 设置真实的过期时间，而是在 value 里存一个过期时间戳，读取时发现超时，就异步去更新缓存，旧数据先顶着用，用户不会感知到空窗。互斥锁适合一致性要求高的场景，逻辑过期适合能容忍短暂旧数据的场景。

最后说缓存雪崩，雪崩不是单个 key 的问题，而是大量 key 在同一时间段集中过期，或者缓存服务本身宕机，导致所有请求直接砸向数据库。它和击穿的区别在于规模，击穿是一根针扎进去，雪崩是一整片墙倒下。比如你把所有 key 的过期时间都设成同一个时刻，那到点那一刻，数据库瞬间承受全量压力。应对雪崩有几个层面，第一，过期时间加随机值，让 key 的失效时间错开，避免集中过期。第二，热点数据做多级缓存，比如本地缓存加 redis，本地缓存能挡住一部分请求。第三，缓存服务高可用，用 redis 哨兵或者集群，避免单点宕机。第四，做降级和熔断，数据库扛不住时直接返回默认值或提示稍后再试，而不是让请求无限堆积。最后给你一个理解框架，穿透是查了不存在的东西，击穿是一个热点刚好过期，雪崩是大量 key 同时失效或缓存挂了。

穿透靠过滤和空缓存，击穿靠锁和逻辑过期，雪崩靠随机过期、多级缓存和高可用，但记住，没有任何方案是银弹，你要结合自己的数据规模、访问特征和一致性要求去组合使用。缓存不是加了就完事，它的每一层失效都对应你系统里一个真实的脆弱点。
