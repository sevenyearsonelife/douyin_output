什么是 Vite？简单说，Vite 是一个新型的前端构建工具，由 Vue 点 js 的创造者尤雨溪开发。它的名字来自法语，意思是快速。而它也确实做到了快，比我们熟悉的 Webpack 快上好几倍。那它快在哪里？为什么快？和传统工具比有什么不同？今天我们就把它拆开来讲清楚，你听完就能明白 Vite 到底解决了什么问题，以及它为啥现在那么火。首先我们要知道一个背景，过去几年，前端项目主要用 Webpack 或 Rollup 这样的打包工具来构建。它们的工作方式是把所有源代码、依赖、样式、图片全部读进来，然后分析依赖关系，合并成一个或多个打包文件。这个过程叫编译打包。在开发时，每次改代码都要重新打包一遍。项目小了还好，一旦项目变大，光是启动开发服务器就可能要等几十秒甚至几分钟。

改一行代码后热更新也要等好几秒，这就是传统工具的痛点慢。Vite 的想法很简单，别在开发时打包了。它在开发环境下直接把 E S 模块原封不动地丢给浏览器去加载，因为现代浏览器都支持 script type 等于 module，可以直接加载 js 模块。Vite 只需要对源文件做一点轻量转换，比如把 Vue 单文件组件转成 js，把 Type Script 转成 js，把 S C S S 转成 C S S，然后就把转换后的模块路径直接发给浏览器，浏览器自己负责按需加载，Vite 只做转换和缓存。这样一来，启动服务时根本不用等打包，瞬间就能打开项目。这就是 Vite 的第一大特点，基于原生 E S 模块的开发服务器。具体怎么做到的呢？Vite 内部有两个核心机制，一个是依赖预构建，另一个是按需编译。

依赖预构建指的是，对于像 React、Vue 这样的第三方包，Vite 会在启动前用 esbuild 把它们打包成一个或多个 E S 模块。因为第三方包内部往往是 Common js 格式或有很多小文件，浏览器直接加载会有性能问题。esbuild 是用 Go 语言写的，速度比 JavaScript 打包器快十至一百倍，所以依赖预构建只用一次，之后缓存起来。按需编译指的是，你写的业务代码，比如 Vue、T S X 文件，Vite 不再启动时编译全部，而是当浏览器请求某个文件时，Vite 才去转换它并返回。比如你改了 App 点 vue 文件，Vite 只重新编译那个文件，然后通过 Web Socket 通知浏览器热更新。因为不需要重新打包整个项目，所以热更新几乎是瞬时的。我们再对比一下和 Webpack 的区别。

Webpack 在开发模式下，启动时要从入口开始递归解析所有依赖，生成一个完整的模块图，然后打包成 bundle。启动后每次代码变更都要重新构建部分或全部 bundle。即使用了 H M R 热模块替换，也要在构建后的模块间做增量更新。Vite 则完全没有构建 bundle 这一步，浏览器直接按需加载模块，H M R 时只更新受影响的模块，不需要重建任何 bundle。所以项目越大，Vite 的优势越明显。举个例子，一个大型管理后台 Webpack 启动可能需要二十秒，热更新两秒，Vite 启动不到一秒，热更新几十毫秒，体验完全不同。除了开发环境快，Vite 在生产环境也有独特的设计。生产环境需要最终打包成优化后的静态资源，比如合并文件、压缩代码，这时候 Vite 会使用 Rollup 来打包。

为什么不用 esbuild？因为 Rollup 对 Tree Shaking、代码分割、插件生态的支持更成熟，而且打包后的文件体积和优化效果更好。Vite 只是借用 esbuild 的极速来做开发时的预构建和转换，生产打包依然交给 Rollup。这种分工非常聪明，开发追求速度，生产追求质量。而且 Vite 的配置文件 vite 点 config 点 js，默认对 Type Script、C S S 预处理器、静态资源、J S X 等都有开箱即用的支持。你几乎不需要额外配置就能开始写项目。Vite 还内置了强大的插件系统，兼容 Rollup 插件。如果你想自定义构建行为，可以写一个简单的钩子函数，比如在转换文件时插入代码，或者在打包时修改输出。

Vite 的 SSR 服务端渲染支持也很完善，可以搭配 Vue、React、Svelte 等框架使用。此外，Vite 的 create vite 脚手架可以快速生成各种框架的模板，比如 Vue 三、React、Vanilla JS 等等。最后我们说说 Vite 适用的场景。如果你在新建一个现代前端项目，特别是 Vue 三、React 十八、Svelte 这些框架，Vite 绝对是首选，它也是接下来新工具生态的核心。比如 Nuxt 三、Vitest 测试工具、Storybook 等都开始基于 Vite。但如果你维护的是一个巨大的老项目，用了很多 Webpack 特有的 loader 和配置，那么迁移到 Vite 可能有一定成本。不过现在社区已经有了像 vite-plugin-optimizer 这样的兼容方案。

总体来说，Vite 代表了前端构建工具的未来方向，利用浏览器原生能力，放弃不必要的打包，把速度做到极致。总结一下，Vite 不是一个简单的比 Webpack 快的工具。它重新思考了开发与生产的分工，开发时用原生 E S 模块搭配 esbuild 做快速编译，生产时用 Rollup 做可靠打包。它让你从等待构建的焦虑中解放出来，把精力放回写代码本身。如果你还没试过，建议立刻创建一个 Vite 项目感受一下，那种秒开的热更新体验，用过就回不去了。
