今天咱们来聊一个 Java 里最基础但也最容易被忽略的话题，八种基本数据类型。首先你得知道一个前提，Java 是强类型语言，意思是每一个变量在声明时就必须明确它的类型。八种基本类型是语言内置的，不是由类创建的原始类型，它们直接存值本身，而不是像对象那样存引用，这是理解 Java 内存模型的第一块基石。这八种类型从大类上分，有四类，整型、浮点型、字符型、布尔型。整型最常见有四种，按占用字节数从小到大排，byte、short、int、long。一个字节是八位，byte 占一个字节，也就是八位，去掉一位符号位，范围是负一百二十八到一百二十七。short 占两个字节，范围约负三万两千到正三万两千。int 占四个字节，约负二十一亿到正二十一亿。long 占八个字节，范围就非常大了。

这里有个容易踩的坑，编译器默认把整数当 int 处理。如果你写 long a 等于九九九九九九九九九九，这个数字本身超过了 int 的范围，直接编译报错，你得在末尾加个 L，也就是 long a 等于九九九九九九九九九九 L，告诉编译器这是 long 型，不加 L 就错。然后是浮点型，float 和 double，float 占四字节，double 占八字节，但注意它们都是 I E 七百五十四标准的浮点数，用符号位加指数位加尾数位的二进制科学计数法存储。这就带来一个极其关键的理解点，浮点数无法精确表示所有十进制小数。你写 float f 等于零点一 f，内存里存的其实是一个接近零点一但永远不等于零点一的二进制数。为什么零点一在二进制里无法被精确表示？

因为二进制小数只能表示二分之一、四分之一、八分之一这种分母为二的幂的数，而零点一是十分之一，分母有因子五，所以二进制只能近似。这就是为什么你用 float 或 double 做金额计算会出诡异结果。同样，默认的浮点字面量是 double，你要声明 float 必须加 f 后缀，比如 float f 等于一点二 f，不加 f 也报错。接下来是字符型 char，char 占两字节，也就是十六位，范围从零到六五五三五，它存的不是字符图片，而是字符在 Unicode 字符集中的编号。你把 char c 等于 a 写进代码，其实存的是数字六十五，这个对应关系就是 ASCII 表。因为 Java 支持 Unicode，所以 char 也能存中文，比如 char c 等于中。

这背后有个历史渊源，早期 C 语言的 char 只占一字节，存不了中文，Java 设计时为了让文本国际化，就把 char 定成了两字节定长编码。最后是 boolean 布尔型，只表示 true 和 false。但注意 Java 规范没有严格规定它的体积，J V M 内部可能用一个字节或四个字节来表示，它不是数值类型，所以 boolean 不能和 int 互相转换。这一点跟 C 语言完全不同，C 里零就是 false，非零就是 true，但 Java 禁止这种隐式转换，这是为了类型安全。知道了这八种类型，你可能会问一个更强的问题，为什么 Java 主要数据类型就这么几个，不搞个更细的类型？其实这是刻意为之，基本类型越少，J V M 处理起来越容易预测，性能优化空间越大。

int 就四个字节，C P U 一次寄存器宽度就能处理完，高效。而当你需要更复杂的结构时，就用类去组合这些基本类型，而不是让语言本身变得更复杂。但这里有一个无法绕开的经典陷阱，整型溢出。int 的最大值是二幺四七四八三六四七，如果你在这个值上加一，结果不是二幺四七四八三六四八，而是负的二幺四七四八三六四八。为什么？因为二进制加减法在最高位溢出时会翻转符号位，这就像车的里程表，九九九九九走一格变零零零零零，很多软件 bug，比如某游戏服务器的时间戳溢出，或者银行系统算利息溢出，根本原因都。是这种静默溢出，Java 不会像 Python 那样自动扩展整数精度。这是因为它要保证底层运算效率，代价是溢出需要程序员自己控制。另一个常见误区是默认值问题。

你如果在类里声明一个 int 成员变量，不赋值它默认是零，但如果在一个方法内部声明局部变量 int x，你不赋值就直接使用，编译器会直接报错 Variable might not have been initialized。这个区别为什么存在？因为成员变量 J V M 会自动给内存清零，这是 J V M 规范规定好的，所以安全。但局部变量分配在栈帧里，J V M 为了性能不会去清零。如果你不初始化就拿它做运算，里面的值是上一次调用留下的垃圾数据，这在底层是极度危险的，所以 Java 干脆用编译器强制要求你必须先赋值。总结一下，Java 的八种基本数据类型，整型四种是常用主战场，浮点型两种要记住精度陷阱，char 是两字节的 Unicode 字符，boolean 只负责真假判断。

真正判断你有没有掌握这批知识点的标准，是你遇到 N P E 溢出、精度误差时，能不能一眼看出是哪一种类型在惹事。这门学问不需要背，你只需要记住一句话：基本类型直接存值，值的边界和精度就是 Java 给你画好的安全线，越过这条线的操作，要么编译报错，要么运行时让你付出意外代价。理解这一点，你的 Java 基础就算扎扎实实过了第一关。
