计算机中的十大经典排序算法有哪几个？它们的原理是什么？这篇文章会带你快速过一遍这十个算法的核心思路，它们的时间复杂度，以及实际使用时该怎么选。先说最基础的三个，冒泡排序、选择排序和插入排序。冒泡排序的思路是，让大的数像气泡一样一点点往上升，每一轮比较相邻两个数，顺序不对就交换，一轮下来最大的数就跑到最后了，反复做，数组就排好了。它的时间复杂度是 O n，数据一多就非常慢，但胜在简单，而且稳定。选择排序稍微不一样，每轮从剩余数字里挑出最小的，放到前面去。它同样也是 O n，但交换次数少很多。插入排序则像打扑克牌时理牌，每拿到一张新牌，就把它插到手里已经有序列的合适位置。对于基本有序的小规模数据，插入排序其实非常快，甚至比很多高级算法还快。

接下来是希尔排序，它其实是插入排序的升级版，思路是先让数据变得大体有序，再做一次完整的插入排序。具体做法是把数组按一定间隔分组，分别做插入排序，然后缩小间隔再重复，直到间隔变成一。间隔序列选得好，平均时间复杂度能到 O n 的一点三次方左右，比前面几个纯 O n 的算法快不少。它是第一个突破 O n 的排序算法，在历史上很有地位。再往上是三个性能更好的排序，归并排序、快速排序和堆排序。它们的平均时间复杂度都是 O n log n。归并排序的思路是分而治之，把数组从中间切开，分成两半，分别排好，再合并两个有序数组。合并过程很规整，所以归并排序非常稳定，不管数据乱不乱，时间都稳定在 O n log n。它的缺点是每次合并都要额外的内存空间。

快速排序则是应用最广的排序算法，做法是选一个基准值，把比它小的放左边，比它大的放右边，然后对左右两边递归地做同样的事。快排的平均速度非常快，很多编程语言的内置排序都用到它的思路，但它的最坏情况是 O n，比如数据已经有序时，如果基准选不好就会退化。堆排序利用二叉堆的数据结构，先建堆，再不断把堆顶最大元素和末尾交换，缩小堆范围，依次得到有序序列。它不需要额外空间，最坏也是 O n log n，但实际速度通常不如快排，因为堆操作的常数更大。最后三个是非比较排序，计数排序、桶排序和基数排序。它们不靠两两比较大小，而是利用数据本身的特性来排序，所以能做到线性时间的复杂度。计数排序适用于数据范围不大的整数序列，比如考试成绩从零到一百。思路是统计每个数字出现了多少次，然后根据计数直接把数字放回正确位置。

时间复杂度 O n 加 k，k 是数据范围。桶排序把数据均匀分到几个有序的桶里，每个桶内部排序后合并。它适合数据分布比较均匀的场景，理想情况下是 O n。基数排序则是按位来排，比如先排个位，再排十位，依次进行。适合对整数或字符串这类有固定位数的数据进行排序。这三个算法的共同点是，它们都牺牲了通用性，换来的是极高的效率，但前提是数据得满足特定条件。那么问题来了，实际用的时候怎么选？如果数据量很小，比如几十个，插入排序最省事。如果数据量中等，快排是默认首选。如果要求稳定，或者数据存储在链表上，归并排序更合适。如果担心最坏情况，堆排序更稳妥。而如果数据是有限范围内的整数，计数排序往往比比较排序快得多。没有哪个算法是绝对最好的，关键看你的数据长什么样，对稳定性有没有要求，内存够不够用。

总结一下，十大经典排序算法，从简单的冒泡到复杂的基数，从比较排序到非比较排序，其实反映了一条清晰的进化路径。更聪明的策略，更多的结构，去换取更快的时间和更优的性能。理解它们不只是为了应付考试，更是为了让你在写代码时，真正知道手里这批数据适合用什么招数。
