什么是 SQLite？你可以把它理解成一个不需要安装服务器，整个数据库就装在一个普通文件里的小型数据库系统。它不是像 MySQL、PostgreSQL、SQL Server 那样独立运行的数据库服务，而是一个以库的形式直接嵌入到你程序里的数据库引擎。你写的软件在运行时直接调用它，数据就存在你指定的一个文件里，用完关掉程序，数据还在那里。这条视频我们要讲清楚三件事：第一， SQLite 到底是什么，它和那些大型数据库有什么区别？第二，它为什么在今天的软件世界里无处不在？第三，它适合用来做什么，不适合用来做什么，以及背后最关键的技术原因是什么？先看它是什么。SQLite 这个名字里的 SQL 说明它支持结构化查询语言，也就是我们通常说的 SQL。你可以用标准的建表、查询、插入、更新这些语句来操作数据。

而 Lite 的意思是轻量，它轻到什么程度？整个数据库的核心代码编译完之后大概只有几百 KB。它不需要你单独启动一个数据库服务器进程，不需要配置端口、用户权限、网络连接这些东西。你的程序只要链接这个库，然后打开一个数据库文件，就可以开始读写数据。这里有一个非常关键的区别，像 MySQL 或者 PostgreSQL，它们是客户端服务器架构，程序要操作数据，需要先通过网络连接到数据库服务器，服务器再帮你去读写磁盘上的数据。而 SQLite 是嵌入式架构，程序直接读写数据库文件，中间没有服务器这一层。这种架构差异决定了它的很多特性，比如它没有网络延迟，读写速度在很多本地场景下非常快，它也不需要专门的数据库管理员去维护。那为什么它这么重要？一个最直接的原因是它可能是世界上部署数量最多的数据库引擎。

你手上的手机，不管是安卓还是苹果，系统内部很多地方都在用 SQLite 存数据。你用的浏览器，比如 Chrome 和 Firefox，用 SQLite 来存书签、历史记录、Cookie 这些信息。很多桌面软件、电视、汽车系统、嵌入式设备，甚至飞机上的某些系统都在用它。原因很简单，它零配置、体积小、稳定，而且数据格式是跨平台的，你在 Windows 上创建的数据库文件直接复制到 Linux 或者手机上也能正常读取。接下来我们深入一点，看它是怎么工作的。SQLite 的数据库文件内部，数据是按照页来组织的，常见的页大小是四 KB，表、索引、数据记录都放在这些页里。它支持事务，也就是说你执行一组操作，要么全部成功，要么全部失败，不会出现中间状态。这一点非常重要，因为它保证了数据的一致性。

它还实现了 ACID 特性，也就是原子性、一致性、隔离性和持久性。这意味着即使程序在写入过程中突然断电或者崩溃，数据库也不会坏掉，它会通过一种叫预写日志的机制来保护数据。简单说，就是先把要改的内容写到一个日志文件里，确认日志写好了，再去改主数据库文件。如果中途出问题，下次打开数据库时，它会根据日志把数据恢复到一个完整状态。那它适合做什么？最适合的是本地存储和嵌入式场景，比如一个手机 App，每个用户的数据都独立存在自己设备上，用 SQLite 就很合适。一个桌面软件，需要保存用户的配置、项目文件、历史记录，也很合适。一个网站，如果访问量不大，比如个人博客或者小型内部系统，SQLite 也完全能扛住。很多情况下，它的读性能甚至比大型数据库还要好，因为数据就在本地，不需要走网络。但它不适合做什么？

最典型的是高并发写入的场景。SQLite 的写入是串行的，同一时间只允许一个写操作，因为它没有独立的服务器进程来协调多个写入者，而是靠文件锁来保证安全。如果有很多客户端同时通过网络往同一个数据库文件里写数据，性能会下降得很明显，而且网络文件系统上的锁机制本身也不可靠。所以，如果你要做一个大型的、多用户同时在线写入的网站应用。通常应该选择 MySQL 或者 PostgreSQL 这类服务器型数据库。这不是说 SQLite 不好，而是它的设计目标本来就不是这个。还有一点需要理解，SQLite 的数据类型系统和其他数据库不太一样。它不像很多数据库那样严格要求每一列的类型，它采用的是动态类型。也就是说，你可以在一个整数列里存一段文本，SQLite 不会报错，它会根据值本身来判断类型。

这种设计让它在很多灵活场景下很方便，但也意味着开发者需要自己更小心地处理数据，不能完全依赖数据库来帮你做类型检查。最后总结一下，SQLite 是一个嵌入式的、零配置的、以单文件存储的关系型数据库。它解决的核心问题是，当你需要一个可靠的本地数据存储，但又不想部署和维护一个数据库服务器时，它是最省事、最稳定的选择。它的优势是简单、便携、可靠、跨平台、单机读性能好。它的局限是写入并发能力有限，不适合大规模多用户同时写入的场景。理解这个边界，比记住它的任何技术细节都更重要，因为选数据库不是选最强的，而是选最匹配你场景的。而 SQLite 在它擅长的那个领域里，几乎没有对手。
